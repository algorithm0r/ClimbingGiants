Week 7 · Root Finding and Search

Bisection

Claim

If $f$ is continuous and $f(a)$ and $f(b)$ have opposite signs, a root lies between them. Evaluating $f$ at the midpoint and keeping whichever half still shows a sign change halves the interval containing the root, at a cost of one evaluation. The remaining uncertainty is known at every step, and the rate of convergence does not depend on the function.

Two points with opposite signs trap a root between them, so you halve, keep the half that still traps it, and repeat. Given a true bracket on a continuous function it cannot fail, and it is never fast.

Brackets

A bracket is a pair $[a, b]$ with $f(a)f(b) < 0$. The intermediate value theorem then guarantees a root inside, provided $f$ is continuous, which is the assumption that page 22's pole example violates. Each step evaluates the midpoint $m$ and replaces $a$ or $b$ with it, whichever keeps the signs opposite, so the bracket is halved and it still contains a root. Two things follow, and they are what distinguish bisection from every other method in this week:

  • The uncertainty is known, not estimated. After $k$ steps the root is inside an interval of width $(b-a)/2^k$. No other method this week gives a guaranteed interval for the root.
  • The rate does not depend on the function. Well-behaved or vicious, the interval halves every step. This is bisection's guarantee, though it also means bisection is never faster.

Evaluations per Digit

Halving per evaluation means one bit of precision per evaluation. To reduce an initial bracket of width $W$ to a tolerance $\tau$:

$$k \;=\; \left\lceil \log_2 \frac{W}{\tau} \right\rceil$$

The number is small and it is fixed in advance, which is unusual and useful:

Each additional decimal place costs about 3.3 more evaluations, whatever the function, and twelve digits from a bracket of width 1 costs 40. That is a lot compared with Newton's four or five, though far fewer than a method that does not converge.

Finding a Bracket

Bisection cannot start without one, and finding one is usually a separate problem that the method does not solve. Three approaches:

  1. Plot $f$. Cheap, usually reliable, and it also shows roughly how many roots there are. The previous page's argument.
  2. Scan. Evaluate on a grid and look for adjacent points of opposite sign. This is a sweep, and everything week 2 says applies.
  3. Physics. Sometimes the bracket is known. A crossing must lie between release and landing. A contraflexure between the supports.

The scan costs one evaluation per point and finds every root it can see. The demo opens on a case where it sees nothing, with thirteen points across a 4 m beam, a target of 11.20 kN·m, and two ordinary roots at 1.400 m and 1.600 m that the scan does not report. Both roots lie inside the single interval from 1.333 to 1.667 m. $f$ is negative at both of its ends, so there is no sign change to find, and the scan returns what it would return for a beam that never reaches 11.20 kN·m anywhere. This is the even-number-of-roots property from the aside below. One root inside an interval flips the sign and is found, while two flip it twice and leave no sign change.

The spacing falls monotonically down that table and the outcome does not. What decides it is whether a grid point happens to fall between the two roots. The nine-point scan is the coarsest in the table and succeeds, because its grid includes 1.5 m, which sits between them, and the thirteen-point scan is finer and fails because its grid does not. So refining a scan does not monotonically improve its chance of finding a pair. A finer scan may miss what a coarser one caught, and no single scan can tell you which case you are in. The defense is the one week 2 gives, which is to refine and compare, and to read "nothing found" as a statement about the scan and not about the beam.

An odd number of roots

A sign change means an odd number of roots in the interval, which is not the same as one. Bisection on an interval containing three roots converges to one of them and never mentions the other two. The converse is the one that bites, because no sign change means an even number of roots, and that includes two. The whole-flight bracket on page 22 fails for this reason, on a function with two ordinary roots inside it.

In Code

def bisect(f, a, b, tol=1e-10, max_evals=200):
    fa = f(a)
    fb = f(b)
    if fa * fb > 0:
        raise ValueError(f'no sign change on [{a:g}, {b:g}]')

    evals = 2
    while (b - a) > tol and evals < max_evals:
        m = 0.5 * (a + b)
        fm = f(m)
        evals = evals + 1
        if fa * fm <= 0:
            b = m
            fb = fm
        else:
            a = m
            fa = fm

    return 0.5 * (a + b), (b - a) / 2, evals

function bisect(f, a, b, tol = 1e-10, maxEvals = 200) {
  let fa = f(a);
  let fb = f(b);
  if (fa * fb > 0) {
    throw new Error(`no sign change on [${a}, ${b}]`);
  }

  let evals = 2;
  while ((b - a) > tol && evals < maxEvals) {
    const m = 0.5 * (a + b);
    const fm = f(m);
    evals = evals + 1;
    if (fa * fm <= 0) {
      b = m;
      fb = fm;
    } else {
      a = m;
      fa = fm;
    }
  }
  return {x: 0.5 * (a + b), halfWidth: (b - a) / 2, evals: evals};
}

Check
  1. A bracket of width 4 m must be reduced to 0.1 mm. How many evaluations, and how would that change if the function were ten times more expensive?
    Answer

    16 halvings, plus the two endpoint evaluations that establish the bracket, so about 18 evaluations. Each step halves the interval, so you need 4 / 2n ≤ 10−4 m, giving 2n ≥ 40 000 and n ≥ log₂40 000 = 15.3, so 16.

    If the function were ten times more expensive, the count would be the same. Bisection consults only the sign of f, so its step count is set by the ratio of the starting width to the required width and by nothing else. The shape of the function and its cost are both irrelevant. The wall-clock time goes up tenfold and the number of evaluations does not move. That predictability is what you are buying, since you can promise the answer to 0.1 mm in 18 evaluations before knowing anything about f beyond a bracket.

  2. Bisection returns after 30 steps on a bracket of width 1. State the uncertainty in the answer, exactly.
    Answer

    2−30, which is 9.31 × 10−10. Thirty halvings of a unit interval leave a bracket of width 2−30, and the root is somewhere in it. Reporting the midpoint, the answer is ±2−31. This is a guaranteed bound, which is unusual. It comes from the intermediate value theorem, so it holds for any continuous f, with no assumption about smoothness and no asymptotic regime to be in. Newton may be far more accurate than this after three steps, though it cannot guarantee a bound.

  3. Your scan over 50 points finds no sign change. Give two different explanations.
    Answer

    There is no root in the range. The plainest reading, and often correct.

    There is an even number of roots between two adjacent scan points. Two crossings inside one interval return the sign to where it started, so the scan sees nothing. A sign change detects an odd number of roots, so a pair is invisible to it.

    A third explanation is a root of even multiplicity, where f touches zero and turns back without crossing, and no scan of any fineness will fix it. There the sign never changes, and bracketing methods cannot find it in principle. This is the double-root case on page 22. To separate the first two, refine the grid or offset it by half a step. To find the third, look for minima of |f| instead of sign changes.
