Reading the assignment 5 program

This page reads a5_model_selection.py, the program behind the technical report in the assignment 5 example reports, one section at a time. The program decides which of two models of a shot's height to build on. One fits gravity from the data and the other holds it at 9.81 m/s², and the program tests each by fitting it to the start of a flight and measuring how well it predicts the rest. Each section below shows the Python beside a MATLAB version that prints exactly the same output (checked by running both on the example pack, the MATLAB version in GNU Octave), and the line notes say what each line does and which lines carry a decision.

Program shape I suggests reading unfamiliar code by finding what comes in, what goes out and the state each loop builds, and the next section starts there. In the Python file the functions come first and the main part follows, from the top down. A MATLAB script has to keep its functions at the end, so its line ranges jump. A line you cannot read is usually covered on one of the Reading Python pages, which the notes link to, and the MATLAB lines have notes of their own.

The Acceleration at Each Frame

Finding where a flight starts and ends depends on the ball's vertical acceleration, which the file does not hold. This function estimates it at every frame by fitting a parabola through the 9 frames centered on that frame, since a parabola's acceleration is twice its t² coefficient. The four frames at each end have no full window around them and get nan.

def accel(t, z):
    """Vertical acceleration at every frame, from a parabola through the 9 frames
    centered on it. NaN where the window runs off either end."""
    h = WINDOW // 2
    a = np.full(len(t), np.nan)
    for i in range(h, len(t) - h):
        c = np.polyfit(t[i - h:i + h + 1] - t[i], z[i - h:i + h + 1], 2)
        a[i] = 2 * c[0]
    return a

Where the Hand Lets Go

While the hand is on the ball the acceleration is upward. last_push finds the last frame before the top of the flight where it still is, and release takes the first frame after that where the acceleration has settled near −9.81 m/s² and stays there for four frames. Requiring four frames in a row keeps one noisy estimate from deciding the release.

def last_push(t, z):
    """The last frame before the top where the acceleration is upward, meaning
    the hand is still on the ball. None if there is no such frame."""
    a = accel(t, z)
    top = int(np.argmax(z))
    last = None
    for i in range(top):
        if a[i] > 0:
            last = i
    return last


def release(t, z):
    """The first frame after the last upward push at which the acceleration is
    within TOL of -g and stays there for RUN frames. None if it never does."""
    a = accel(t, z)
    p = last_push(t, z)
    if p is not None:
        first = p + 1
    else:
        first = WINDOW // 2
    for i in range(first, len(t) - RUN + 1):
        if np.all(np.abs(a[i:i + RUN] + G) < TOL):
            return i
    return None

Where the Flight Ends

The flight ends at whichever comes first after the top: the acceleration leaving the band for four frames in a row (the ball has hit the rim, the backboard or the net) or the ball dropping below rim height. The function returns the frame before that, the last frame of free flight.

def flight_end(t, z):
    """Last frame of the flight: the frame before the acceleration leaves the
    band for RUN frames in a row (the ball has hit something), or the frame
    before the ball drops through rim height, whichever comes first."""
    a = accel(t, z)
    top = int(np.argmax(z))
    for i in range(top, len(t) - RUN + 1):
        if np.all(np.abs(a[i:i + RUN] + G) >= TOL) or z[i] < RIM:
            return i - 1
    return len(t) - 1
function e = flight_end(t, z, WINDOW, G, TOL, RUN, RIM)
    % Last frame of the flight: the frame before the acceleration leaves the
    % band for RUN frames in a row (the ball has hit something), or the frame
    % before the ball drops through rim height, whichever comes first.
    a = accel(t, z, WINDOW);
    [~, top] = max(z);
    for i = top:numel(t)-RUN+1
        if all(abs(a(i:i+RUN-1) + G) >= TOL) || z(i) < RIM
            e = i - 1;
            return
        end
    end
    e = numel(t);
end

Filled-In Stretches

Measured heights carry about 3 cm of noise, so they are very unlikely to lie on a straight line. When the tracker loses the ball it probably fills the gap with one, and this function looks for that: six or more steps (seven frames) where the second difference of the height is essentially zero. One training arc, 325, has such a stretch and is left out of the comparison.

def straight_runs(z, frames=6):
    """First and last frame of any stretch where the height falls on a straight
    line for 'frames' steps or more. Measured heights carry about 3 cm of noise,
    so a straight line means the tracker filled a gap."""
    flat = np.abs(np.diff(z, 2)) < 0.001
    hits = []
    for i in range(len(flat) - frames + 2):
        if np.all(flat[i:i + frames - 1]):
            hits.append(i)
    if len(hits) == 0:
        return None
    return hits[0], hits[-1] + frames
function gap = straight_runs(z, frames)

The Two Models

fit holds both models. Each is a parabola fitted by least squares, and the only difference is whether the t² coefficient is solved for or set to −g/2 in advance. The second case moves the known term over to the measurements and fits a straight line to what is left, as Linearity in the parameters explains. rms scores a fitted parabola against a set of heights, and find_shot picks a shot out by its id for the figures.

def fit(t, z, fixed):
    if fixed:   # the known term moves to the left-hand side
        A = np.column_stack([np.ones_like(t), t])
        c = np.linalg.lstsq(A, z + 0.5 * G * t ** 2, rcond=None)[0]
        return np.array([c[0], c[1], -G / 2])
    A = np.column_stack([np.ones_like(t), t, t ** 2])
    return np.linalg.lstsq(A, z, rcond=None)[0]


def find_shot(shots, wanted):
    """The shot whose id is wanted."""
    for s in shots:
        if s['id'] == wanted:
            return s


def rms(c, t, z):
    return np.sqrt(np.mean((c[0] + c[1] * t + c[2] * t ** 2 - z) ** 2))
function c = fit(t, z, fixed, G)

    end

end

Both Models, Three Fit Lengths

For each fit length, each model is fitted to the first frames of every flight and scored twice: on the frames it was fitted to (the residual) and on the frames after them, which it never saw (the held-out error). The held-out error is the one that says how well a model predicts, which is what Bob needs.

# both models, three fit lengths, scored on the unseen part of the flight
results = {}
for n_fit in FIT_LENGTHS:
    rows = []
    for arc_id, t, z in arcs:
        if len(t) - n_fit < MIN_HELD_OUT:
            continue
        tf = t[:n_fit]          # the fitted frames
        zf = z[:n_fit]
        th = t[n_fit:]          # the held-out frames
        zh = z[n_fit:]
        free = fit(tf, zf, False)
        fixed = fit(tf, zf, True)
        rows.append([rms(free, tf, zf), rms(fixed, tf, zf),
                     rms(free, th, zh), rms(fixed, th, zh), -2 * free[2]])
    # residuals and errors to cm, g stays in m/s^2
    results[n_fit] = np.array(rows) * [100, 100, 100, 100, 1]

The Summary

Each fit length gets a heading line and three more: the median residual, the median held-out error, and the median and range of the fitted gravity, over all the arcs. Medians are used so that a few arcs with large errors cannot pull the summary around, and the counts beside them (how many arcs one model matches or beats the other on) say whether a difference is consistent.

# the summary, one block of lines per fit length

Decisions in This Program

Every line below holds a decision the student made, and the report states most of them. Gravity at 9.81 is not on the list, since Bob set it. The line numbers are those of the downloadable files, and the hint under each code box gives the lines it shows. It is a good idea to check your own program with the test on Using AI (pick a line and say why it is that way). For these lines the answer is a choice, and a different student could reasonably have chosen otherwise.

2018Each acceleration comes from a parabola through 9 framesfewer frames (noisier estimates) or more (a release blurred over more time)
2119Free flight means within 5 m/s² of −9.81a narrower band, which would likely start flights later (or miss some)
2220The acceleration has to stay in the band for 4 framesfewer frames, which lets single noisy estimates through
78274A flight ends when the ball drops below rim heightthe memo’s rule, the last frame 1 m or more from the hoop (measured across the floor)
8356A filled-in stretch is six steps (seven frames) on a straight linea different length, or keeping arc 325

2422The models are fitted to 6, 10 and 14 framesother lengths, chosen from what the test records give

Running It Yourself

Both versions are downloads: a5_model_selection.py and a5_model_selection.m. Unzip a data pack, put the program in the pack's top folder beside crash and shots, and run it from there (Files and libraries explains why the folder matters). In Colab, upload the program beside your unzipped pack and run it in a cell with %run a5_model_selection.py (the Colab guide shows how). On your own pack it reads your data, so its numbers will differ from the ones above. The MATLAB version should run as it is in MATLAB R2018b or later. GNU Octave, which is free, needs a script's functions defined before they are used, so to run it there, move the functions to the top of the file and put a line 1; above them.
