Week 1 · Measured Records

Anatomy of a measured signal

Video: Processing Channels of Data (0:17:12). Slides

Claim

A measured record is stored together with a header. The header names the quantity measured, the body it was measured on, the axis it was measured along, the unit, the interval between samples, and the time of the first sample. Those six fields are how you know what the values are meant to be and what may be computed from them.

The header tells you what the numbers are meant to be. Read it before you use the values.

The Instrument's Raw Output

An instrument records a value at fixed intervals and stores the values in order. A record of that shape is a time series, and every channel in a crash test is one. What reaches you is a list:

−0.674   −0.982   0.113   −1.447   0.226   −0.531   …   −470.913   …   242.406

On their own these numbers are ambiguous. They could be metres per second squared or newtons, and they could span 50 milliseconds or 50 seconds. You could guess, and with a familiar signal you would often guess right. However, you would not know how close your guess was, and the sample interval is the one you could pin down least well. For this reason the format stores the facts alongside the values, so you can read them.

Six Facts That Fix What a Value Means

The header names six facts. Each one settles something about what the values mean:

FactAnswersWhat It Settles
quantityacceleration? force? displacement? which equations the values may enter
bodythe head, the chest, the vehicle structure? what the result is a statement about
axisfore-and-aft, lateral, vertical? which components may be combined
unitm/s², g, N, mm? the scale of every value, often by a factor of 9.81 or 1000
sample intervalhow far apart in time consecutive values are the scale of every integral and every derivative
time of first samplewhere zero is the origin events are timed against

The sample interval is the field most often assumed. Integrating a record multiplies by it and differentiating divides by it. For this reason an assumed interval wrong by a factor of two makes every integrated quantity wrong by the same factor. The result still has a plausible shape, sign and magnitude.

The Channel Header

The six facts are stored in the file itself. The format these records are stored in, ISO/TS 13499, requires a header for every channel, and the header names each fact explicitly. Here is a real one, the header of the channel in the figure above:

Channel code                       11HEADCG0000ACXP
Dimension                          Acceleration
Location                           Head
Direction                          Longitudinal
Unit                               m/(s*s)
Sampling interval                  8.0E-5
Time of first sample               -0.050000
Number of samples                  4501
Data source                        transducer
Data status                        ok
Cut off frequency                  2000
First global maximum value         242.405679
First global minimum value         -470.913355
Time of minimum value              0.079040

The first seven lines are the six facts plus the count, and the rest matter later. The file does not store a column of times. A record of 4501 samples stores 4501 numbers and not 9002. The samples are evenly spaced, so three of the header fields describe the instants they were taken at exactly:

$$t_i \;=\; t_0 + i\,\Delta t, \qquad i = 0,\,1,\,\ldots,\,n-1$$

Here $t_0$ is the time of the first sample, $-0.050$ s, $\Delta t$ is the sampling interval, $8.0\times10^{-5}$ s, and the number of samples $n$ is 4501. Every quantity in this course that has a time in it, such as a peak at 79 ms, an integral over an interval or a crossing, comes from building that array first. Plotting the values against their position in the file produces a figure with the right shape and a horizontal axis measured in samples. This mistake will typically survive a glance at the plot.

  • Data status. The laboratory's own verdict on the channel. A channel marked anything other than ok failed in some way. It will still contain numbers.
  • Cut off frequency. The signal has already been through a filter. What you have is the filtered signal, and week 4 is about what that filter did.
  • The global maximum and minimum, with their times. These make the file self-checking: recompute them from the values and compare. If they disagree, either the file is damaged or you have read it incorrectly.
The channel code

11HEADCG0000ACXP is a positional code. Read it in pieces. 11 is the driver dummy, HEADCG is the head centre of gravity, 0000 is unused fine position, AC is acceleration, X is the longitudinal axis, and P marks it the primary instrument. A redundant one carries a different letter. So the code repeats most of the six facts in a form a machine can filter on, which is a convenience when you are picking one channel out of several thousand. The named header fields are the ones to believe, though, and where the code and the fields disagree the fields are correct.

In Code

import json
import numpy as np
import matplotlib.pyplot as plt

with open('crash/10642.json') as f:
    test = json.load(f)

ch = next(c for c in test['channels'].values()
          if c['code'] == '11HEADCG0000ACXP')

t = ch['t0'] + ch['dt'] * np.arange(ch['n'])
y = np.array(ch['y'])

plt.plot(t, y)
plt.xlabel('time (s)')
plt.ylabel(f"{ch['dimension']} [{ch['unit']}]")
plt.title(f"{ch['comment']}  ({ch['code']})")
plt.show()
test  = jsondecode(fileread('crash/10642.json'));
names = fieldnames(test.channels);

for k = 1:numel(names)
    ch = test.channels.(names{k});
    if strcmp(ch.code, '11HEADCG0000ACXP'), break; end
end

t = ch.t0 + ch.dt * (0:ch.n-1);

plot(t, ch.y);
xlabel('time (s)');
ylabel(sprintf('%s [%s]', ch.dimension, ch.unit));
title(sprintf('%s  (%s)', ch.comment, ch.code));

The standard

ISO/TS 13499 requires every one of these fields on every channel, which is why a record written by one laboratory can be read by another years later without asking anyone anything. The standard fixes which fields are present. It does not check that their values are correct. See The standards behind the crash data.

Why the Times Start Negative

The header above gives a time of first sample of −0.050 s. Negative times are not an error. The recording starts before the event, while the vehicle is still travelling at a steady speed, so the true acceleration over that stretch is zero. That makes it the part of the record where the true value is known. For this reason it is used to characterise what the instrument adds on its own account. Week 3 uses it for exactly that, and the noise on several later pages is taken from it.

Four Channels From One Test

Select between the channels below. All four come from the same test, and they share three of the six facts. All four are longitudinal, sampled every 8.0×10−5 s, starting at −0.050 s. They differ in quantity, body and unit.

The head and the seat crossmember both report longitudinal acceleration in m/s², and both are attached to the same decelerating vehicle. Their traces differ. The seat crossmember peaks at 10.8 ms and 1541 m/s², and the head at 79.0 ms and 471 m/s², because the belt and the airbag let the head travel for some milliseconds after the structure has stopped. That is, the difference between the two traces is the work the restraint system did. The header gives the same answer in one field. The channel codes differ in three places as well, 11 against 10, HEADCG against SEATLE, and 0000 against RE00.

The other two channels are not accelerations. 11CHST000000DSXP is driver chest deflection, a distance in metres, and 11NECKUP0000FOXP is upper neck force in newtons. All four rise and fall over the same few tens of milliseconds. Plotted without their units the four shapes leave you comparing magnitudes and reasoning about what each one could be. The header gives the quantity and the unit in one line each.

A Wrong Header

Select the chest deflection channel and read its unit field, which says m, and then read its values. The largest is −32798.0.

Read Aspeak deflectionPlausible?
metres, as the header says32.8 km no, larger than the test facility
millimetres32.8 mno
micrometres32.8 mm yes, an ordinary chest deflection against a 63 mm limit

The values are consistent with micrometres and the header says metres, an error of a factor of a million. Three things follow.

  • The file is self-consistent. Its declared global maximum and minimum match the recorded values exactly. The self-check described above passes, because it compares the values against the header's own maximum and minimum.
  • Data status says ok. The laboratory's own verdict does not catch it.
  • No internal consistency check can catch it. The values do give it away, though only to a reader who knows roughly how far a human chest can compress. That is knowledge from outside the file.

So the six fields are claims and may be wrong. The header tells you what the numbers are meant to be. To find out whether it is telling the truth you compare a value against the physical scale of the thing being measured, which needs knowledge the file does not hold.

Check
  1. You are given a list of 4501 numbers and told only that they are from a crash test. Name two quantities you could compute from them and two you could not.
    Answer

    Computable: the largest and smallest value in the list, their mean, their scatter, the number of samples, and the shape of the trace. Anything that is a property of the sequence of numbers as numbers.

    Not computable: the peak acceleration in g, because that needs the unit. The velocity change, because that needs the unit and the sample interval. Every quantity in the second list is easy to compute. That is, the second list is blocked by the missing header fields and not by the arithmetic.

    You could guess at several of the six facts and often be right. A crash pulse has a recognisable shape, and a peak near 470 is plausible in m/s² and not in g. However, you would not know how close a guess was, and the sample interval is the one you could pin down least well. A guess of 1×10−4 s against a true 8×10−5 s is reasonable, and it puts a 25% error in every velocity computed from it.

  2. A colleague integrates a channel assuming 10 kHz when the header says 12.5 kHz. By what factor is their velocity wrong, and in which direction?
    Answer

    Too large by 25%, a factor of 1.25.

    Integration multiplies by the sample interval. They used 1/10 000 = 1.0×10−4 s where the truth is 1/12 500 = 8.0×10−5 s, so every term in the sum is 1.25 times too big and so is the total. A 15 m/s Δv is reported as 18.75. The result has the right shape, the right sign and a plausible magnitude, which is why an error of this kind commonly survives review. It is typically caught by comparing against the test's known impact speed.

  3. A channel's header reports a global minimum of −470.9 at 79.04 ms. You recompute it from the values and get −470.9 at 79.04 ms. What have you verified, and what have you not?
    Answer

    You have verified that the file is internally consistent: the header describes the array that is actually in the file, you have parsed it in the same order and with the same indexing the writer used, and nothing has been truncated or shifted. That is worth having, because it catches a large class of reading errors.

    You have not verified that the number is right. The calibration of the transducer, its mounting, the axis it pointed along and its units all remain unverified, so a file may be internally consistent and still be uniformly wrong. The chest deflection channel on this page is exactly that case. Every internal check on it passes and the unit is wrong by a factor of a million.

  4. The chest channel's unit is wrong by a factor of a million and every internal check passes. Write down the one check that would have caught it, and say what it needs that the file does not contain.
    Answer

    Compare the value against the physical scale of the thing being measured. A peak of 32 798 in units of metres is a chest deflecting 33 kilometres. In micrometres it is 32.8 mm, which is what a chest does in a barrier test. What that check needs, and the file does not have, is knowledge from outside the file: what a chest is, that it is part of a human-sized body, and roughly how far such a thing can move. Internal consistency cannot supply it, because it only compares the file against itself. The check takes one glance and is the cheapest on the page.
