A ball problem, worked by hand

A ball leaves your hand at 2.00 m moving up at 5.00 m/s. When does it reach the ground?

$$y(t) = y_0 + v_0 t - \tfrac12 g t^2$$

The ground is $y = 0$, so this is a quadratic.

$$4.905\,t^2 - 5t - 2 = 0$$

The quadratic formula gives t.

$$t = \frac{v_0 + \sqrt{v_0^2 + 2 g y_0}}{g}$$

Name every value as you work through it.

Each step by hand is one line of code.

on paper
in code
y₀ = 2.00 m
y0 = 2.00
v₀ = 5.00 m/s

g = 9.81
disc = 25.00 + 39.24 = 64.24
disc = v0*v0 + 2*g*y0

root = sqrt(disc)
t = 13.0150 / 9.81 = 1.3267 s
t = (v0 + root) / g

Each line adds a name to the state.

Running them in order is the flow, the state changing.

A program is a script for the flow of state.

The other root is −0.3073 s, before the ball was released.

4501 samples, one at a time

The crossmember channel holds 4501 samples.

The arithmetic is the same addition repeated.

Six lines, and five names.

a = load_channel(10642, '093')
what comes in
dt = 8.0e-5
 
total = 0.0
set before the loop starts
 
for i in range(len(a)):
i counts the passes, and is gone at each boundary
    total = total + a[i]
added to on every pass, never reset
 
dv = total * dt
what goes out, and it does not exist until here

total is set before the loop and carried across every pass.

That name is the accumulator, what the loop is for.

Everything else in the loop is scratch, used and overwritten each pass.

Reading code

Read unfamiliar code by finding the state and following it.

  • what comes in — arguments, and values loaded from files
  • what goes out — what is returned or plotted at the end
  • each loop's accumulator — that is what the loop is for
  • the rest is scratch — skip it until you have a reason to care
