In decimal, one third goes on forever, so on paper you stop writing 3s and round.

Every place you stop, the answer comes up short.

0.3 × 3=0.9 0.33 × 3=0.99 0.333 × 3=0.999

A Python float works in binary, where one tenth goes on forever.

Binary uses only 0 and 1, with places worth a half, a quarter, an eighth, and so on.

0.0001=1/16=0.0625 0.00011=3/32=0.09375 0.000110011=51/512=0.099609375 0.0001100110011=819/8192=0.0999755859375

What a float stores for 0.1, after 55 places with the last one rounded up

0.0001100110011001100110011001100110011001100110011001101 = 0.1000000000000000055511151231257827021181583404541015625

Every place you stop, the answer comes up short of 0.1. The float rounds its last place up, so its 0.1 is a little too large, and 0.1 + 0.2 prints 0.30000000000000004.

A Python float keeps about 16 digits of every number, counted from the first one.

A float is a double-precision number, with 53 binary digits. For a number in the hundreds, that leaves about 13 decimal places.

you type−407.2 One of our four accelerations.

the mean of all four−404.29999999999995 Each of the four was rounded when stored, and each addition rounds again. The answer is off by about 0.00000000000006.

An accelerometer's own digits run out long before the 16th, so this rounding is far smaller than anything a crash measurement can show.

Today we work the problem on the 24 arcs in the example pack (test 9793), the same arcs the example reports use. Your own pack has 60.

Bob never says what the model is for, so we read each phrase with what we know about shooting and gravity.

Each phrase leaves out something Bob takes for granted.

Bob saysWhat it takes to read itSo he means
“the flight model” A ball in the air feels gravity and little else, so its height is a parabola in time. $z = c_0 + c_1 t + c_2 t^2$ through the frames after the hand lets go, with $g = -2c_2$.
“let the data tell me what gravity is” Gravity is the curvature of that parabola. Fit $c_2$ as well, so each shot gets its own gravity.
“hold gravity at 9.81” Gravity at the Earth’s surface runs from 9.78 m/s² at the equator to 9.83 at the poles, and it is the same for every shot in a game. Fix $c_2$ at $-9.81/2$ and fit only the release height and upward speed.
“build the rest of the season on one” A model of a shot is worth having when it says where the ball is going before it gets there. The model will run on shots it was not fitted to, and predict frames it has not seen.
“how you know” Bob was not there when we fitted it. Evidence he can follow, and how many shots it rests on.

Both models describe the same flights, and today we work out which one Bob should build on.

Seven questions, in the order we take them today.

Our choice: start at the last frame where the upward speed grows, since only the hand can make it grow. Both models are linear in their parameters, so one least-squares solve fits each.

Step 3 of 7 · How do we fit each model?

gravity fittedThree unknowns
$$z = c_0 + c_1 t + c_2 t^2 \qquad g = -2c_2$$
A = np.column_stack([np.ones_like(t), t, t**2])
c = np.linalg.lstsq(A, z, rcond=None)[0]
gravity held at 9.81Two unknowns
$$z + \tfrac{1}{2}(9.81)\,t^2 = c_0 + c_1 t$$
A = np.column_stack([np.ones_like(t), t])
c = np.linalg.lstsq(A, z + 0.5*9.81*t**2, rcond=None)[0]

Our choice: fit the height alone, by least squares. Gravity pulls straight down, so it shows up only in the height, and from above the ball crosses the floor in a straight line at a steady speed. Least squares fits a model that is linear in its parameters in one solve, and it counts every frame the same.

SciPy’s scipy.optimize.curve_fit fits either model from a Python function of t, with no matrix to build, and gives the same coefficients.

The RMS squares each residual, averages the squares, and takes the square root.

Step 4 of 7 · How do we measure how close a curve is?

a new wordResidual The frame’s height minus the curve’s height at that time. Arc 662 has 26 frames in flight, so each model has 26 residuals. With gravity fitted they run from −2.79 cm to +2.98 cm.
why squareThe plain average is 0.00 cm The gaps above the curve cancel the gaps below it. Squaring makes every gap count, whichever side it is on, and a gap twice as big counts four times as much.
a new wordRMS, root mean square
$$\begin{aligned}\text{square each:}\quad &(-1.77)^2 = 3.14,\ \ 0.77^2 = 0.59,\ \ \ldots\\ \text{average:}\quad &63.98 \div 26 = 2.46\ \text{cm}^2\\ \text{square root:}\quad &\sqrt{2.46} = 1.57\ \text{cm}\end{aligned}$$
With gravity held at 9.81, the same steps give $\sqrt{67.36 \div 26} = 1.61$ cm. In step 6 the same calculation on frames the model was not fitted to gives its error.

In NumPy, res = z - z_fit gives all 26 residuals, and np.sqrt(np.mean(res**2)) gives the RMS.
