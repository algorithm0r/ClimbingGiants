These are three reports for Assignment 6, The Head Injury Criterion, written in three different styles. All three use the same example pack (crash test 9793, which no phrase assigns), so nothing here answers anybody's assignment. They agree on the number and on the facts. A Memo

Example 1 · Memo

To: Alice

Re: Head injury criterion for test 9793, and what 200 more would cost

Data phrase: example pack (test 9793)

The driver's head injury criterion for test 9793 is HIC15 = 150.4, well under the limit of 700. The limit we used is a window of 15 ms, and both the 15 ms and the 700 come from FMVSS 208, section S6.2 (49 CFR 571.208). To get the number I examined 2,055,150 windows. With no limit on the window length the same search would have examined 24,503,500, which is 11.9 times as many. The whole program took 0.33 s for this test on my laptop, so 200 tests would take about 1.1 minutes of computing with the limit and about 11.8 minutes without it.

HIC is worked out from the head acceleration in g (multiples of standard gravity, 9.80665 m/s²). For any stretch of the record, called a window, take the average acceleration over it, raise that to the power 2.5 and multiply by the window's length in seconds. HIC15 is the largest result over every window no longer than 15 ms. The record has 7001 samples, one every 0.05 ms (20,000 a second), so a 15 ms window is 300 sample steps long. I filtered the three driver head channels (11HEADCG0000ACXP, ACYP and ACZP) at CFC 1000, the standard low-pass filter class that SAE J211-1 gives for head acceleration, and combined them sample by sample into the resultant. A running total of the integral, built once, turns each window's integral into one subtraction. The program then tries every start in the record and every end up to 300 steps after it. The figure shows the window it found.

A few things need your attention before you commit to the month.

  • The window is exactly as long as the limit allows. It runs from 60.85 to 75.85 ms, which is 15.00 ms, and it starts before the peak (45.3 g at 66.50 ms). With no limit the best window on this record is 53.45 to 105.40 ms and gives 334.0. The number depends on the limit that much, so it should always travel with it, as the customer asked.
  • The times are from one run. They will change from run to run and from machine to machine. The window count will not, as long as the other tests are recorded the same way (7001 samples at 20,000 a second). I have not checked that they are.
  • The estimate covers computing only. It does not include checking each test's channels before trusting them, as Assignment 1 had to.
  • The end of the filtered trace drops to zero. In the last fraction of a millisecond (the right edge of the figure) the filtered resultant falls straight down. I believe this is the filter starting from rest at the end of the record, since a head does not stop that suddenly. It is far from the window and does not touch the number.
  • Only the driver can be done from this file. The passenger's head has an X channel only, so there is no resultant to compute for the passenger.

Assumptions. The occupant you mean is the driver, since only the driver has all three head channels. The 700 is the limit for a 50th percentile male dummy, and I have assumed the driver dummy is that size because the file does not say. A window may be exactly 15 ms long, and lengths are counted in whole sample steps. The integral uses the trapezoid rule, and time zero is the impact the file declares.

Program. a6_hic15.py (attached) filters the channels, runs the search with and without the limit, times both and draws the figure.

The list tells Alice what the cost estimate rests on (one run and one record length). That is probably what she needs most for costing a month.

A Technical Report

Example 2 · Technical report

Data phrase: example pack (test 9793)

Summary

The head injury criterion for the driver in NHTSA test 9793 is HIC15 = 150.4, over the window from 60.85 to 75.85 ms. The 15 ms window limit and the pass limit of 700 both come from FMVSS 208, section S6.2. The search examined 2,055,150 windows, against 24,503,500 with no limit (11.9 times as many). It took 0.042 s, or 0.09 s per test including reading and filtering, so 200 tests would take about 19 s of computing.

Data

Test 9793 is a New Car Assessment test of a 2017 Hyundai Elantra driven into a rigid barrier at 56.15 km/h. HIC is computed from the driver's three head acceleration channels, which are measured at the head's center of gravity (CG). Each has 7001 samples at a spacing of 0.05 ms (a sample rate of 20,000 per second), from −50 to 300 ms, in m/(s*s) with a status of ok. Table 1 gives each channel's largest value in g (one g is 9.80665 m/s²) before and after filtering.

Method

A Python program, a6_hic_search.py (listed in the appendix and submitted with this report), does every step below and draws every figure.

  1. Filter each component at CFC 1000. This is the low-pass filter class SAE J211-1 assigns to head acceleration, run forward and then backward as in the Smoothing notes.
  2. Combine the three into the resultant, the square root of the sum of their squares, and divide by 9.80665 to put it in g.
  3. Build the running total (prefix sum) of the trapezoid integral once, so each window's integral is one subtraction.
  4. For each window length from 1 to 300 sample steps (0.05 to 15 ms), compute the HIC value of every window of that length at once with numpy, and keep the largest.

HIC for a window from t1 to t2 is (t2 − t1) times the average acceleration over the window raised to the power 2.5, with time in seconds and acceleration in g. HIC15 is its largest value over every window no longer than 15 ms. Every start in the record was searched, including the 50 ms before impact. Those windows cannot win, but searching them costs little and means no judgment is needed about where the event begins. The same code was run with no limit, to show how much the limit decides.

HIC15 is 150.4, which passes the FMVSS 208 limit of 700. The resultant peaks at 45.33 g at 66.50 ms, and the window opens before it (Figure 2). The best window is exactly as long as the limit allows. Figure 3 shows why. HIC keeps rising as the limit is relaxed, up to 51.95 ms, where the record itself sets the optimum. The value therefore depends strongly on the limit, and a HIC value cannot be read without it.

Search cost. The number of windows depends only on the record length and the limit, so it is the same for every test recorded the same way. With the prefix sum each window costs one subtraction, 2,055,150 in all. Integrating each window directly from its own samples would take 307,050,100 additions, 149 times as many. On this run one test took 0.09 s (0.05 s to read and filter and 0.042 s to search), so 200 tests would take about 19 s. The same search written as two plain Python loops took 0.58 s, so even the plain-loop version would finish 200 tests in a few minutes.

Errors and Anomalies

Filter edge at the end of the record. The course's filter starts each pass from zero. The backward pass therefore starts at 300 ms from rest, while the head is still at about 3.6 g. The filtered resultant reads 3.59 g at 299.50 ms, 2.99 at 299.80, 1.02 at 299.90 and 0.00 at 300.00, against 3.49 to 3.62 g unfiltered. From 299.80 ms on, the filtered values are wrong. They are far from the window and do not affect HIC.

Resultant before impact. The resultant averages 0.127 g before impact, where the head is not moving. A resultant is never negative, so the sensor noise cannot average out. Removing each component's mean leaves HIC15 at 150.4 (Table 3).

Passenger head. The passenger (13HEADCG0000ACXP) has an X channel only, so no HIC can be computed for the passenger from this file.

Second event. All three components rise again after about 230 ms (Figure 1). It is well below the main pulse.

Assumptions

  • HIC is for the driver (position 1), the only occupant with all three head channels.
  • The 700 limit is for a 50th percentile male dummy. The file does not give the dummy's size, and I have assumed that is what sat in the driver's seat.
  • "No longer than 15 ms" includes 15 ms. Window lengths are whole numbers of 0.05 ms steps, so the longest window is 300 steps.
  • The integral uses the trapezoid rule, and the resultant is formed after filtering each component, since the standard gives a class for each channel.
  • Impact is at time zero, as the file declares.
  • Timings are from one run on one laptop and will vary. The window counts will not.

Appendix. Program

"""Assignment 6: HIC for the driver's head, and what the search costs.

Run this from the unzipped pack folder. It:
  1. reads the three driver head channels by code and filters each at CFC 1000,
  2. forms the resultant in g,
  3. finds the best window for every window length with a prefix sum,
     one numpy pass per length, which gives HIC15 and the limit-free value,
  4. counts and times the windows, and counts what direct integration would cost,
  5. runs three checks (a plain double loop, no filter, baseline removed).
Figures saved: head_components.svg, hic_windows.svg, hic_vs_limit.svg
"""
import json
import os
import time

import matplotlib.pyplot as plt
import numpy as np

G = 9.80665            # standard gravity (m/s^2)
CODES = ['11HEADCG0000ACXP', '11HEADCG0000ACYP', '11HEADCG0000ACZP']
LIMITS_MS = [15]       # FMVSS 208


def cfc(y, dt, cls):
    """SAE J211-1 Butterworth (Smoothing notes), run forward then backward."""
    wd = 2 * np.pi * cls * 2.0775
    wa = np.tan(wd * dt / 2)
    d = 1 + np.sqrt(2) * wa + wa**2
    a0 = wa**2 / d
    a1 = 2 * a0
    a2 = a0
    b1 = -2 * (wa**2 - 1) / d
    b2 = (-1 + np.sqrt(2) * wa - wa**2) / d

    def one_pass(x):
        out = np.zeros_like(x)
        for i in range(2, len(x)):
            out[i] = (a0 * x[i] + a1 * x[i - 1] + a2 * x[i - 2]
                      + b1 * out[i - 1] + b2 * out[i - 2])
        return out

    return one_pass(one_pass(y)[::-1])[::-1]


def resultant_g(comps):
    return np.sqrt(sum(c**2 for c in comps)) / G


def best_by_length(a, dt, kmax):
    """For each window length k = 1..kmax samples, the best HIC over every
    start. The prefix sum S makes each window's integral one subtraction."""
    S = np.concatenate([[0.0], np.cumsum((a[1:] + a[:-1]) / 2 * dt)])
    best = np.zeros(kmax + 1)
    start = np.zeros(kmax + 1, dtype=int)
    windows = 0
    for k in range(1, kmax + 1):
        T = k * dt
        mean = (S[k:] - S[:-k]) / T          # every window of length k at once
        h = T * np.clip(mean, 0, None)**2.5
        start[k] = np.argmax(h)
        best[k] = h[start[k]]
        windows += len(h)
    return best, start, windows


def hic(a, dt, kmax):
    """HIC with windows up to kmax samples: (value, start, end, windows)."""
    best, start, windows = best_by_length(a, dt, kmax)
    k = int(np.argmax(best))
    return best[k], start[k], start[k] + k, windows


def hic_loops(a, dt, kmax):
    """The same search as two plain loops, as a check on the numpy version."""
    a = list(a)
    S = [0.0]
    for i in range(1, len(a)):
        S.append(S[-1] + (a[i] + a[i - 1]) / 2 * dt)
    best = 0.0
    for i in range(len(a) - 1):
        for j in range(i + 1, min(i + kmax, len(a) - 1) + 1):
            mean = (S[j] - S[i]) / ((j - i) * dt)
            if mean > 0:
                best = max(best, (j - i) * dt * mean**2.5)
    return best


# ---- read and filter
t_start = time.perf_counter()
name = os.listdir('crash')[0]
with open(os.path.join('crash', name)) as f:
    test = json.load(f)
by_code = {c['code']: c for c in test['channels'].values()}
chans = [by_code[c] for c in CODES]
dt, n = chans[0]['dt'], chans[0]['n']
t = (chans[0]['t0'] + dt * np.arange(n)) * 1000          # ms
raw = [np.array(c['y']) for c in chans]
filt = [cfc(y, dt, 1000) for y in raw]
res = resultant_g(filt)
t_read = time.perf_counter() - t_start
print(f"test {test['testNo']}, {n} samples at dt = {dt * 1000:.2f} ms "
      f"({1 / dt:.0f} per second), {t[0]:.0f} to {t[-1]:.0f} ms")
for c, y, yf in zip(chans, raw, filt):
    print(f"  {c['code']}  {c['unit']}  {c['status']}  "
          f"raw peak {np.abs(y).max() / G:5.1f} g  "
          f"CFC 1000 peak {np.abs(yf).max() / G:5.1f} g")
p = int(np.argmax(res))
print(f"resultant: peak {res[p]:.2f} g at {t[p]:.2f} ms, "
      f"mean before impact {res[t < 0].mean():.3f} g")
# the filter starts each pass from zero, so look at the ends of the record
raw_res = resultant_g(raw)
for i in [-11, -5, -3, -1]:
    print(f"  at {t[i]:.2f} ms: unfiltered {raw_res[i]:.2f} g, "
          f"CFC 1000 {res[i]:.2f} g")
print(f"read and filter: {t_read:.3f} s")

# ---- HIC for each limit, and with no limit
print(f"{'limit':>8} {'HIC':>7} {'from (ms)':>10} {'to (ms)':>8} {'length':>7} "
      f"{'mean g':>7} {'windows':>11} {'time (s)':>9}")
found = {}
for lim in LIMITS_MS + [None]:
    kmax = n - 1 if lim is None else round(lim / 1000 / dt)
    t0 = time.perf_counter()
    h, i, j, w = hic(res, dt, kmax)
    secs = time.perf_counter() - t0
    found[lim] = (h, i, j, w, secs)
    mean = (h / ((j - i) * dt))**(1 / 2.5)
    label = f'{lim} ms' if lim else 'none'
    print(f"{label:>8} {h:7.1f} {t[i]:10.2f} {t[j]:8.2f} "
          f"{(j - i) * dt * 1000:7.2f} {mean:7.1f} {w:11,} {secs:9.3f}")

# ---- what the search costs
kmax = round(15 / 1000 / dt)
# integrating directly: one addition per sample, for every window
direct = sum(k * (n - k) for k in range(1, kmax + 1))
h15, i15, j15, w15, s15 = found[15]
print(f"HIC15 windows: {w15:,} subtractions with the prefix sum, "
      f"{direct:,} additions integrating each window directly "
      f"({direct / w15:.0f} times as many)")
w_all = found[None][3]
print(f"no limit: {w_all:,} windows, {w_all / w15:.1f} times as many")
per_test = t_read + s15
print(f"one test: {per_test:.2f} s (read and filter {t_read:.2f} s, "
      f"search {s15:.3f} s), 200 tests: {200 * per_test:.0f} s")

# ---- checks
t0 = time.perf_counter()
print(f"check, plain double loop: HIC15 = {hic_loops(res, dt, kmax):.1f} "
      f"in {time.perf_counter() - t0:.2f} s")
print(f"check, no filter: HIC15 = {hic(resultant_g(raw), dt, kmax)[0]:.1f}")
before = t < 0
debiased = [y - y[before].mean() for y in filt]
print(f"check, each component's mean before impact removed: "
      f"HIC15 = {hic(resultant_g(debiased), dt, kmax)[0]:.1f}")

# ---- figure 1: the three filtered components
plt.figure(figsize=(8, 4))
for c, yf in zip(chans, filt):
    plt.plot(t, yf / G, linewidth=0.8,
             label=f"{c['code'][-2]}, {c['direction'].lower()}")
plt.xlabel('time from impact (ms)')
plt.ylabel('head acceleration, CFC 1000 (g)')
plt.title(f"Test {test['testNo']}, driver head CG, components at CFC 1000")
plt.legend()
plt.tight_layout()
plt.savefig('head_components.svg')
plt.close()

# ---- figure 2: the resultant with the HIC15 window
plt.figure(figsize=(8, 4))
plt.plot(t, res, linewidth=0.8, color='k', label='resultant, CFC 1000', zorder=3)
plt.axvspan(t[i15], t[j15], color='tab:orange', alpha=0.4,
            label=f'HIC15 = {h15:.1f}, {t[i15]:.2f} to {t[j15]:.2f} ms')
plt.xlim(0, 160)
plt.ylim(0, 62)    # room for the legend above the trace
plt.xlabel('time from impact (ms)')
plt.ylabel('resultant head acceleration (g)')
plt.title(f"Test {test['testNo']}, driver head resultant and the best window")
plt.legend(loc='upper left', fontsize=8)
plt.tight_layout()
plt.savefig('hic_windows.svg')
plt.close()

# ---- figure 3: HIC against the window length limit
best, _, _ = best_by_length(res, dt, round(80 / 1000 / dt))
limit_ms = np.arange(1, len(best)) * dt * 1000
plt.figure(figsize=(8, 4))
plt.plot(limit_ms, np.maximum.accumulate(best[1:]), color='k')
for lim in LIMITS_MS:
    plt.axvline(lim, color='gray', linestyle='--', linewidth=0.8)
    plt.annotate(f'HIC{lim} = {found[lim][0]:.1f}', (lim, found[lim][0]),
                 xytext=(5, -15), textcoords='offset points')
hn, inn, jn = found[None][:3]
plt.plot((jn - inn) * dt * 1000, hn, 'o', color='tab:red',

plt.xlabel('longest window allowed (ms)')
plt.ylabel('HIC (a in g, t in s)')
plt.title(f"Test {test['testNo']}, driver HIC against the window length limit")
plt.legend(loc='lower right')

Filtering takes the peak down to 45.33 g at 66.50 ms and keeps the shape. Now the search. I wrote it like the code in the Windowed Optimum notes, with a running total of the integral so each window's integral is one subtraction, and a break as soon as a window gets longer than 15 ms (300 steps). The choice I made is to start the windows at impact and not at the start of the record. Before impact the head is only reading noise, so a window that starts there cannot be the best one, and Alice asked how many windows I had to look at.

def hic_search(a, dt, first, kmax):
    # running total of the trapezoid integral, built once
    S = [0.0]
    for i in range(1, len(a)):
        S.append(S[-1] + (a[i] + a[i-1]) / 2 * dt)
    best, window, count = 0.0, None, 0
    for i in range(first, len(a) - 1):
        for j in range(i + 1, len(a)):
            if j - i > kmax:          # longer than the limit
                break
            count += 1
            T = (j - i) * dt
            score = T * ((S[j] - S[i]) / T) ** 2.5
            if score > best:
                best, window = score, (i, j)
    return best, window, count
