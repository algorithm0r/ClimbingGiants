Reading the assignment 2 program

This page reads a2_peak_loss.py, the program behind the technical report in the assignment 2 example reports, one section at a time. The program asks what a slower logger would have read. A logger running at a twentieth of the recorded rate takes one sample for every 20 of ours, so the program makes each slower record by keeping every k-th sample. Nothing says which sample the slower logger would start on, so it tries every start and keeps the worst and the best. Each section shows the Python beside a MATLAB version that prints the same results (checked by running both on the example pack, the MATLAB version in GNU Octave), and the line notes say what each line does.

Program shape I suggests reading unfamiliar code by finding what comes in, what goes out and the state each loop builds, and the next section starts there. This program reads the test and works out the rates before it defines its functions, and the main part follows them. A MATLAB script has to keep its functions at the end, so its line ranges jump. A line you cannot read is usually covered on one of the Reading Python pages, which the notes link to, and the MATLAB lines have notes of their own.

The Test and the Rates to Try

The program reads the test and finds the recorded rate from the time between samples. A slower logger can only be imitated by keeping every k-th sample, so the rates it can try are the recorded rate divided by a whole number. It tries every whole number from 1 to 100 that divides the rate exactly, which on the example test gives 14 rates from 20,000 down to 200 Hz.

with open('crash/09793.json') as f:

factors = []
for k in range(1, 101):
    if rate_now % k == 0:              # k divides the rate exactly
        factors.append(k)
rates = []
for k in factors:
    rates.append(rate_now // k)

A Channel's Values

This function gives a channel's values in the units the report uses: g for the accelerations, and millimeters for the chest displacement, whose header says meters while its values fit micrometers (assignment 1 found this).

def values(key):
    """The channel in g, or in mm for the chest displacement.
    Its header says m, but the values are micrometers (see Errors)."""
    ch = channels[key]
    out = []
    if key == 'chest_d':
        for v in ch['y']:
            out.append(v / 1000)
        return out, 'mm'
    for v in ch['y']:
        out.append(v / G)
    return out, 'g'
function [out, unit] = values(channels, key, G)
    % The channel in g, or in mm for the chest displacement.
    % Its header says m, but the values are micrometers (see Errors).
    y = channels.(key).y;
    out = zeros(size(y));
    if strcmp(key, 'chest_d')
        for i = 1:numel(y)
            out(i) = y(i) / 1000;
        end
        unit = 'mm';
        return
    end
    for i = 1:numel(y)
        out(i) = y(i) / G;
    end
    unit = 'g';
end

The Peak

The peak is the largest size in a record, ignoring its sign. A crash decelerates, so most of the largest values are negative, and peak gives their size, which is always positive.

def peak(y):
    """The largest size in y, ignoring sign."""
    biggest = abs(y[0])
    for v in y:
        if abs(v) > biggest:
            biggest = abs(v)
    return biggest
function biggest = peak(y)
    % The largest size in y, ignoring sign.
    biggest = abs(y(1));
    for i = 1:numel(y)
        if abs(y(i)) > biggest
            biggest = abs(y(i));
        end
    end
end

The Peak at Every Start

This function does the program's main work. For a logger that keeps every k-th sample, there are k places it could start, and each gives a different record. The function finds the peak of each one. The smallest of them is the worst start and the largest the best.

def peaks_by_start(y, k):
    """Peak of the record that keeps every k-th sample, for each start 0..k-1."""
    peaks = []
    for start in range(k):
        peaks.append(peak(y[start::k]))
    return peaks
function peaks = peaks_by_start(y, k)
    % Peak of the record that keeps every k-th sample, for each start 0..k-1.
    peaks = zeros(1, k);
    for start = 0:k-1
        peaks(start + 1) = peak(y(start + 1:k:end));
    end
end

The Lowest Rate That Passes

The rates run from fastest to slowest. The loop walks down them and stops at the first rate where some channel keeps less than 95% of its peak, so the rate it reports passes and so does every faster one. On the example test the first rate below 20,000 Hz already fails.

Two Functions Only the MATLAB Version Has

The MATLAB file ends with two functions the Python does not need in this form. plot_kept is the Python's plot_kept, defined partway down the main part, written separately because a MATLAB function cannot see the script's names. title_case stands in for Python's .title().

function plot_kept(start, mark, win, t_ms, y, k)
    % The samples in the window that a logger starting at sample start keeps.
    kept = [];
    for i = win
        if mod((i - 1) - start, k) == 0      % i - 1 is the sample counted from 0
            kept(end+1) = i;
        end
    end
    plot(t_ms(kept), y(kept), [mark '-']);
end


function s = title_case(s)
    % Capital first letter on each word, the rest lower case, like Python's .title().
    s = lower(s);
    starts = [1, find(~isletter(s(1:end-1))) + 1];
    s(starts) = upper(s(starts));
end

Running It Yourself

Both versions are downloads: a2_peak_loss.py and a2_peak_loss.m. Unzip a data pack, put the program in the pack's top folder beside crash and shots, and run it from there (Files and libraries explains why the folder matters). This program names the example test's file, crash/09793.json, so to run it on your own pack, change that name to your test's. Its labels are written for the example test too: they say 20 kHz and test 9793, which on most packs is not the recorded rate or the test. The MATLAB version should run as it is in MATLAB R2018b or later. GNU Octave, which is free, needs a script's functions defined before they are used, so to run it there, move the functions to the top of the file and put a line 1; above them.
