Week 9 · Time Stepping

Euler's method

Claim

When the rate of change of a state is known as a function of the state itself, the trajectory is obtained by stepping: evaluate the rate at the current state, advance by the rate times a small step, and repeat. That is Euler's method. Each step starts where the last one ended, so an error made in one step is carried into every later step.

The rate comes from a rule that uses the current state, so you have to reach a state before you can compute the rate there.

A Tracked Shot With Drag

The shot is arc 79 of the tracked shots (SportVU optical tracking, 25 frames a second), a three-pointer that missed. Time is measured from frame 20 of the record, the release this data set marks (page 19 finds the release 0.08 s earlier). Frames on this page are counted from that release, so frame 5 is frame 25 of the record. A fit to the first 11 free-flight frames gives the ball's position and velocity at frame 5, 0.20 s after release (page 25 builds that fit).

The position changes at the rate set by the velocity. The velocity changes at the rate set by gravity and by air drag:

$$\frac{\mathrm{d}\mathbf{r}}{\mathrm{d}t} \;=\; \mathbf{v}, \qquad \frac{\mathrm{d}\mathbf{v}}{\mathrm{d}t} \;=\; -g\,\hat{\mathbf{z}} \;-\; k\,|\mathbf{v}|\,\mathbf{v}$$

Here $\mathbf{r}$ is the position $(x, y, z)$, $\mathbf{v}$ is the velocity, $|\mathbf{v}|$ is the speed, $g$ is 9.81 m/s², and $\hat{\mathbf{z}}$ points up. Drag acts against the velocity and grows with the square of the speed. The constant $k$ is 0.016 per meter (page 25 gives its source). Without drag the height is a parabola in time, the model fitted on page 19. With drag the acceleration depends on the velocity, which is one of the unknowns being solved for. No formula is known for this path, so we find it by stepping.

A Rate That Depends on the State

In week 3 the acceleration was a recorded array, so every value was available before any integration started and the whole cumulative sum could be formed in one pass. Here the rate is a function of the state $s$, which for the shot is the six numbers $(x, y, z, v_x, v_y, v_z)$:

$$\frac{\mathrm{d}s}{\mathrm{d}t} \;=\; f(t, s)$$

The rate at a later time needs the state at that time, and the state needs the rate that carried it there, and the two are found in turns. Each step uses the rate at the current state to find the next state, and the loop repeats from there. ($f$ takes the time as well, for rates that depend on a recorded signal. The shot's rate does not use it.)

One Euler Step From Frame 5 to Frame 6

$$s_{i+1} \;=\; s_i \;+\; h\, f(t_i, s_i)$$

Here $s_i$ is the state at time $t_i$ and $h$ is the step. Read it as the rectangle rule from week 3, where the change over one step is the rate times the step width, with the rate taken at the start of the step. Euler treats the rate as constant across the step, though the rate changes during it.

On the shot, the speed at frame 5 is 6.76 m/s. The vertical part of drag is $k\,|\mathbf{v}|\,v_z$ = 0.016 × 6.76 × 2.7508 = 0.298 m/s², so the vertical acceleration is −9.81 − 0.298 = −10.108 m/s². One step of 40 ms (one frame) moves the height and the vertical velocity by the rate times the step:

$$\begin{aligned} z &= 4.2018 + 0.04 \times 2.7508 = 4.3118\ \text{m} \\ v_z &= 2.7508 + 0.04 \times (-10.108) = 2.3465\ \text{m/s} \end{aligned}$$

The other four components step the same way. The new state is the start of the next step, and 18 steps reach frame 23, the last frame before the ball nears the hoop.

An 8 mm Overshoot Carried Through 18 Steps

The comparison here is the same program (the euler function at the end of this page) run with 0.1 ms steps. It puts the ball at 4.3038 m at frame 6, so the single 40 ms step lands about 8 mm high. The height is concave (it bends downward), and Euler follows a straight line at the slope it found at the start of the step. A tangent line to a concave curve lies above the curve on both sides of the point it touches. The overshoot is about half the vertical acceleration times the step squared.

$$\tfrac{1}{2} \times 10.108 \times 0.04^2 = 0.0081\ \text{m}$$

The next step starts from the high point, so its own overshoot adds to the first. The table gives the gap to the 0.1 ms run after each step.

If each 40 ms step started from the 0.1 ms run's state, its overshoot would fall from 8.1 to 7.5 mm over the flight, and the 18 of them add to 139.8 mm. The gap at frame 23 is 5.1 mm less, and that difference comes from the vertical velocity. The size of the downward acceleration falls from 10.11 to 9.32 m/s² over the flight (drag adds to gravity on the way up and works against it on the way down). Euler uses the value at the start of each step, so it makes the vertical velocity a little too low each step. Every later step moves with that velocity. By frame 23 the vertical velocity is about 15 mm/s low, and that has pulled the height down by about 5 mm. The height error and the velocity error both stay in the state and carry into every later step.

A drag-free run is a check on the program, because without drag the height has a formula. With $k$ = 0 the vertical acceleration is exactly $-g$, the velocity steps exactly, and every 40 ms step overshoots by ½ × 9.81 × 0.04² = 7.85 mm. Eighteen of them make 141.3 mm, and the program's drag-free run at 40 ms ends 141.3 mm above the parabola.

Step Size Against the Tracking Noise

In week 3 the instrument fixed the interval. Here you choose the step, and the choice has a cost either way:

  • Too large - the answer is wrong, possibly wildly.
  • Too small - the run is slow, and eventually less accurate once rounding dominates.
  • No formula - the right step depends on how fast the solution changes, and that is not known before the run.

On the shot, one step per frame ends 13.5 cm high at frame 23. That is more than four times the 3.07 cm vertical tracking noise in the header of the shots file, so the stepping error alone would likely be visible in the data. Steps of 20 ms end 6.7 cm high. The 0.1 ms run is a fair comparison only if it is itself close enough. Checking that, by halving the step until the answer stops moving, is the convergence study on page 26.

Check
  1. Why does an error in one Euler step affect every later step, when an error in one panel of a week-3 integral does not?
    Answer

    A quadrature panel is computed from the data. The area of panel 40 depends on the samples at panel 40 and on nothing else. The panels are independent terms in a sum, so an error in one panel changes the total by that amount only.

    An Euler step is computed from the result of the previous step. The state at step 40 is the starting point for step 41, so an error made at step 40 displaces the trajectory. Every later step is taken from the wrong place, and the rate is evaluated at a state the system never occupied. On the shot the rate depends on the velocity and not on the height. For this reason the first step's 8 mm height error is carried along unchanged, while the velocity error changes every later position step (by about 5 mm at frame 23).

  2. A run with 20 ms steps ends 67.1 mm above the 0.1 ms run at frame 23, about half of the 40 ms run's 134.7 mm. Explain the half from the overshoot of one step.
    Answer

    One step overshoots by about ½ |az| h². Halving h makes each overshoot a quarter as large (about 2.0 mm in place of 8.1 mm). It also doubles the number of steps, from 18 to 36, so the total is about half. That is why Euler's error at a fixed time is roughly proportional to the step. Page 26 measures this on the shot and compares it with steppers that do better.

  3. Your solution is convex and not concave. Which way does Euler err, and why?
    Answer

    Euler underestimates a convex solution. Euler steps along the tangent at the current point. For a convex solution, meaning one curving upward with a positive second derivative, the tangent lies below the curve everywhere except where it touches, so each step lands low. The errors have one sign, so they add up and do not cancel. For a concave solution like the shot's height, the tangent lies above and Euler overestimates. If the second derivative keeps one sign over the run, you can predict the sign of the error before running the program.

In Code

def euler(f, s0, t0, dt, n):
    s = np.array(s0, dtype=float)
    out = np.empty((n + 1, s.size))
    out[0] = s
    for i in range(n):
        s = s + dt * f(t0 + i*dt, s)
        out[i + 1] = s
    return out
function out = euler(f, s0, t0, dt, n)
    s = s0(:);
    out = zeros(n+1, numel(s));
    out(1,:) = s.';
    for i = 0:n-1
        s = s + dt * f(t0 + i*dt, s);
        out(i+2,:) = s.';
    end
end
function euler(f, s0, t0, dt, n) {
  let s = s0.slice();
  const out = [s.slice()];
  for (let i = 0; i < n; i++) {
    const ds = f(t0 + i * dt, s);
    const next = [];
    for (let j = 0; j < s.length; j++) {
      next.push(s[j] + dt * ds[j]);
    }
    s = next;
    out.push(s.slice());
  }
  return out;
}
