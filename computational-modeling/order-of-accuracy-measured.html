Order of accuracy

Claim

A method's order $p$ is the exponent in error $\propto h^p$. It is measured by halving the step and taking the ratio of successive errors. A ratio of 2 is order 1, of 4 is order 2, of 16 is order 4. The measurement requires no theory, and it checks the implementation as well as measuring a property of the method.

Halve the step, see what the error does. If it does not do what the method promises, something is wrong, and it is usually your code and not the method.

Measuring the Order

If error $\approx Ch^p$ then halving $h$ divides the error by $2^p$:

$$\frac{E(h)}{E(h/2)} \;\approx\; 2^p \qquad\Longrightarrow\qquad p \;\approx\; \log_2 \frac{E(h)}{E(h/2)}$$

Two runs give an estimate, and three or more give an estimate plus evidence that it has settled. The ratios matter more than the errors do, because a sequence of ratios converging on 4.00 is strong evidence and a single ratio of 3.7 is weak evidence.

Heun's Method and RK4

Euler takes the rate at the start of a step and uses it for the whole step. Heun's method and RK4 evaluate the rate at more than one point inside the step and step with a weighted average of those evaluations. Each evaluation is called a slope, meaning the rate function $f$ evaluated at some time and some state (writing the state as $s$, as the code on page 25 does).

Heun's method takes two slopes. The first is Euler's, $k_1 = f(t, s)$. The second is taken at the end of the step, at the state Euler would have reached, $k_2 = f(t + h,\ s + h k_1)$, and the step uses their average:

$$s_{\text{next}} \;=\; s + \tfrac{h}{2}\,(k_1 + k_2)$$

This is the trapezoid rule from week 3 applied to the rate, the average of the two ends times the width, with the far end estimated by an Euler step because it is not yet known.

RK4 (the fourth-order Runge-Kutta method) takes four slopes, one at the start of the step, two at its midpoint and one at its end. Each slope is used to reach the point where the next one is taken:

$$\begin{aligned} k_1 &= f(t,\ s) \\ k_2 &= f(t + \tfrac{h}{2},\ s + \tfrac{h}{2}k_1) \\ k_3 &= f(t + \tfrac{h}{2},\ s + \tfrac{h}{2}k_2) \\ k_4 &= f(t + h,\ s + h k_3) \end{aligned} \qquad\qquad s_{\text{next}} \;=\; s + \tfrac{h}{6}\,(k_1 + 2k_2 + 2k_3 + k_4)$$

With the slopes taken at these points, the weights 1, 2, 2 and 1 make the error fall as $h^4$, which the table in the next section measures.

The table gives one step of $h$ = 0.1 s on the basketball problem from the next section (released 3.4520 m up with a vertical speed of 4.7428 m/s, with quadratic drag). The slopes of the height are the vertical speed at each evaluation point, which gravity and drag reduce as the step goes on.

def heun(f, s0, t0, dt, n):
    s = np.array(s0, dtype=float)
    out = np.empty((n + 1, s.size))
    out[0] = s
    for k in range(n):
        t = t0 + k*dt
        k1 = f(t, s)
        k2 = f(t + dt, s + dt*k1)
        s = s + dt/2 * (k1 + k2)
        out[k + 1] = s
    return out

def rk4(f, s0, t0, dt, n):
    s = np.array(s0, dtype=float)
    out = np.empty((n + 1, s.size))
    out[0] = s
    for k in range(n):
        t = t0 + k*dt
        k1 = f(t, s)
        k2 = f(t + dt/2, s + dt/2*k1)
        k3 = f(t + dt/2, s + dt/2*k2)
        k4 = f(t + dt, s + dt*k3)
        s = s + dt/6 * (k1 + 2*k2 + 2*k3 + k4)
        out[k + 1] = s
    return out
function out = heun(f, s0, t0, dt, n)
    s = s0(:);
    out = zeros(n+1, numel(s));
    out(1,:) = s.';
    for k = 0:n-1
        t = t0 + k*dt;
        k1 = f(t, s);
        k2 = f(t + dt, s + dt*k1);
        s = s + dt/2 * (k1 + k2);
        out(k+2,:) = s.';
    end
end

Read the ratio columns down. Each settles and stays, at 2.00, 4.00, and about 16, and those ratios give measured orders of 1, 2 and 4, with no derivation needed to obtain them.

RK4's last ratio is 15.7 against a promised 16.0, and halving the step once more takes it to 12.6. Read the error columns across instead, at $h = 0.0125$. Euler is off by 5.9 cm, Heun by 27 micrometres, and RK4 by 0.11 nanometres. At equal cost (Heun takes two rate evaluations per step and RK4 four) RK4 is still ahead by many orders of magnitude (the same currency argument as week 7).

Choosing a Test Problem

The first attempt at this table used the projectile without drag, and RK4's error came out at $4\times10^{-16}$ at every step size, with ratios of about 1. That is not a broken implementation. The drag-free solution is a quadratic in $t$, and RK4 integrates polynomials up to cubic exactly, so its only error was floating-point rounding and the measurement showed only that rounding. So a convergence test needs a problem the method cannot solve exactly, which usually means one whose solution is not a low-degree polynomial. Adding drag was enough here.

The reference solution

Measuring an error needs a truth, and there are three sources of one, in descending order of how much they are worth. First an exact analytical solution, then the same integrator at a much finer step, and then a different, higher-order integrator.

The second is used above, and its danger is that the reference shares any bug the runs have. This means a convergence study may return an order of 4 for an implementation that is consistently solving the wrong equation, because the errors converge on the reference and the reference is wrong too. Where an exact solution exists, use it.

Mismatched Orders

A measured order that matches the method is evidence that the implementation is right, and it is one of the few such checks available. An order that does not match points at something specific:

MeasuredExpectedUsual Cause
12the second stage is not being used, or is using the wrong state

drifting toward 0anythingrounding has taken over, and the step is too small
above the expected orderanythingthe reference is not independent, or the problem is solved exactly

The drag-free case above is the extreme of the last row's cause, with the problem solved exactly and only rounding left. An order better than promised feels like good news, and it is usually a sign that the test is not measuring what it claims to.

Check
  1. Your errors at h, h/2 and h/4 are 8.0×10⁻³, 2.1×10⁻³ and 5.2×10⁻⁴. What is the order, and what method might this be?
    Answer

    Order 2. The ratios are 8.0/2.1 = 3.8 and 2.1/0.52 = 4.0, and log₂4 = 2. Any order-2 method fits, whether Heun in this week, the trapezoid rule in week 3, the central difference in week 4, or midpoint quadrature. They are different algorithms that share an exponent, so order is a property you can read off a run without knowing what the run contains. The first ratio coming out at 3.8 against a promised 4.0 is expected, because it is the coarsest step and the furthest from the asymptotic regime. If it had been 3.8 and then 3.5 and then 3.0, the falling ratios would need explaining.

  2. The ratios go 4.0, 4.0, 3.1, 1.4, 0.9 as you keep halving. What is happening at the end?
    Answer

    The method has stopped being the limiting factor and rounding error has taken over. The ratios fall away from 4, then through 1, and a ratio below 1 means the error is growing as the step shrinks. Truncation is still falling as h², but rounding accumulates over the 1/h steps needed to cross the interval, and at a small enough step it is the larger of the two. So there is a best step somewhere in between.

    The best answer available was at the step just before the ratio of 0.9, and after the ratio of 3.1 each halving bought very little. The way to know is to watch the ratio, since the answer itself gives no sign.

  3. You measure order 4 for a method you know is order 2. Name two explanations and say how you would distinguish them.
    Answer

    The test problem is too easy. If the exact solution is a low-degree polynomial, the order-2 error term can vanish identically and a higher term is left to dominate. A drag-free projectile is a quadratic in time, and several methods integrate it exactly, so any order measured there reflects only rounding.

    The reference is not independent. If the "exact" answer is the same method at a small step, part of the error is common to both and cancels in the subtraction, flattering the apparent order.

    To distinguish them, change one thing at a time. Change the problem, by adding drag so the solution is no longer a polynomial. If the order drops to 2, it was the first. Change the reference. Use a closed form, or a different method entirely, at a fine step. If the order drops, it was the second.

    An order that comes out better than the method's is usually a warning. It most likely means the measurement is not measuring what it claims.
