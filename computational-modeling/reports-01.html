Example reports

Example reports · Assignment 1

These are three reports for Assignment 1, Data Inspection, written in three different styles. All three describe the same example pack (crash test 9793, which no phrase assigns), so nothing here answers anybody's assignment. They find the same things in the data and present them in different ways. Please see the Example reports page for what every report needs and who it is written for.

Each report is followed by a short note on what it does well. The purpose of the notes is to show that three different styles can meet the same standard (plots identified at a glance, errors flagged, assumptions noted).

A Memo

Example 1 · Memo

To: Alice and Bob

Re: What is in the data pack

Data phrase: example pack (test 9793)

The pack holds one crash test and four files of basketball shot tracking. The crash test is NHTSA test 9793, a 2017 Hyundai Elantra driven into a rigid barrier at 56.15 km/h (a New Car Assessment test, head on). It has eight channels. Six are on the driver dummy (the head in three directions, the chest acceleration and displacement, and the pelvis), one is on the passenger dummy's head, and one is on the car itself. All eight hold 7001 samples taken every 0.05 ms (20,000 per second), from 50 ms before impact to 300 ms after. The figure shows all eight.

Two things need your attention before the analysis.

  • Chest displacement is in the wrong units. Its header says meters, and it reaches −31,676, which would be 31 km. Read as micrometers it is 31.7 mm, a believable chest compression for this kind of test. I have not changed the file, and the figure shows the channel as labeled.
  • The channel named vehicle_x is not the vehicle. Its header describes an accelerometer on the left rear seat crossmember. It measures one point on the structure, and I have used the header's description in every label.

Everything else looks consistent. Every channel reports a status of ok. Before impact the car is towed at a constant speed, so its true acceleration is zero, and every acceleration channel averages within about 0.2 m/s² of zero over that stretch.

Assumptions. I built each channel's times from the three header fields t0, dt and n, and took the zero the file declares as the moment of impact. The code prefix 11 marks the driver dummy, and I took 13 (the channel titled V1P2) to be the front passenger, which the codes do not spell out. The four shot files are Bob's, so I have listed them here and left them for his report.

Program. pack_overview.py (attached) lists the pack, prints a line for each channel and draws the figure.

What to notice

The answer is in the first paragraph, and the two problems are the second thing you read. A reader who stops after the list still has what they need. The single figure is easy to read because every panel carries its own title and unit, so the memo does not need to explain it.

A Technical Report

Example 2 · Technical report

Data phrase: example pack (test 9793)

Summary

The data pack contains one frontal crash test (NHTSA test 9793) with eight measurement channels, and four files of basketball tracking data that this report does not cover. The crash data is complete and evenly sampled. One channel, the driver's chest displacement, is labeled in meters but its values are consistent with micrometers.

Data

Test 9793 is a New Car Assessment test of a 2017 Hyundai Elantra, run head on into a rigid barrier at 56.15 km/h. Every channel has 7001 samples at a spacing of 5 × 10-5 s (a sample rate of 20 kHz), starting 0.05 s before impact. The record therefore covers −50 to +300 ms. The table lists each channel with its largest value. Accelerations are also given in g (one g is 9.81 m/s²).

Channels

Figure 1 shows every channel against time from impact, each titled with the description and code from its own header. The chest displacement is shown in millimeters, read as micrometers (see Errors and Anomalies).

Method

A Python program, inspect_pack.py (listed in the appendix and submitted with this report), reads the test file, finds each channel's largest value and when it occurs, and draws every figure in this report. Times are built from each channel's t0, dt and n, since the file stores no time column.

Errors and Anomalies

Chest displacement units. The header gives the unit as meters and the status as ok, but the channel reaches −31,676, a 31 km compression of the chest. Its dimension field also reads "Meters", where every other channel names a quantity (Acceleration). Read as micrometers the values give 31.7 mm at 69 ms, which is a plausible chest compression for a 56 km/h test and peaks at the same time as the chest acceleration. Figure 2 shows the channel both ways. The file itself is unchanged.

Crossmember peak. The crossmember channel reaches −196 g at 52.8 ms, about three and a half times the largest dummy value, and swings sharply on either side of it (Figure 1). It is not a single isolated reading, so it has been kept. This report does not establish what causes it.

Assumptions

  • Impact is at time zero. This is the zero the file declares.
  • The code prefix 11 marks the driver dummy. The channel with prefix 13 (titled V1P2) is taken to be the front passenger, which the codes do not spell out.
  • Every unit is as the header states, except the chest displacement.
  • The channel key vehicle_x is a label added to the file. The header describes a sensor on the left rear seat crossmember, so the report uses the header's description.

Appendix. Program

"""Assignment 1: inspect the crash test in a data pack.

Run this from the unzipped pack folder. It prints the test description and the
largest value in each channel, and saves the figures used in the report:
one per channel (channel_<key>.svg) and the chest displacement both ways
(chest_d_units.svg).
"""
import json
import os

import matplotlib.pyplot as plt

G = 9.81      # m/s^2 in one g
PACK = '.'    # the unzipped pack folder


def load_test(pack):
    """The crash folder holds one file, the test."""
    folder = os.path.join(pack, 'crash')
    with open(os.path.join(folder, os.listdir(folder)[0])) as f:
        return json.load(f)


def times_ms(ch):
    """The file stores no times. t0, dt and n give them, here in milliseconds."""
    return [1000 * (ch['t0'] + i * ch['dt']) for i in range(ch['n'])]


test = load_test(PACK)
v, info = test['vehicle'], test['test']
print(f"Test {test['testNo']}: {v['year']} {v['make']} {v['model']}, "
      f"{info['config']} at {info['speed_kph']} km/h")

# the largest value in each channel, and when it happens
print(f"{'description':36} {'unit':8} {'largest':>9} {'in g':>6} {'at (ms)':>8}")
for key, ch in test['channels'].items():
    t, y = times_ms(ch), ch['y']
    i = max(range(len(y)), key=lambda k: abs(y[k]))
    in_g = f"{y[i] / G:6.1f}" if ch['dimension'] == 'Acceleration' else '     -'
    print(f"{ch['comment']:36} {ch['unit']:8} {y[i]:9.1f} {in_g} {t[i]:8.1f}")

# one figure per channel, labeled from its own header
for key, ch in test['channels'].items():
    y, unit, dim = ch['y'], ch['unit'], ch['dimension']
    if key == 'chest_d':   # header says m and 'Meters', values are micrometers
        y, unit, dim = [v / 1000 for v in y], 'mm', 'Displacement'
    plt.figure(figsize=(5, 3))
    plt.plot(times_ms(ch), y, linewidth=0.8)
    plt.axvline(0, color='gray', linestyle='--', linewidth=0.8)
    plt.title(f"{ch['comment']}  [{ch['code']}]", fontsize=9)
    plt.xlabel('time from impact (ms)')
    plt.ylabel(f"{dim} ({unit})")
    plt.tight_layout()
    plt.savefig(f"channel_{key}.svg")
    plt.close()

# the chest displacement as labeled, and read as micrometers
ch = test['channels']['chest_d']
fig, (a, b) = plt.subplots(1, 2, figsize=(10, 3.2))
a.plot(times_ms(ch), ch['y'], color='tab:red', linewidth=0.8)
a.set_title('as the header labels it')
a.set_ylabel('chest displacement (m, per header)')
b.plot(times_ms(ch), [v / 1000 for v in ch['y']], linewidth=0.8)
b.set_title('read as micrometers, shown in mm')
b.set_ylabel('chest displacement (mm)')
for ax in (a, b):
    ax.set_xlabel('time from impact (ms)')
fig.tight_layout()
fig.savefig('chest_d_units.svg')
What to notice

The headings let a reader go straight to the part they need, and the summary answers the question before any of them. The table gives the eight peaks and their times side by side, and Figure 1 shows every channel, so a reader can check one against the other. Figure 2 shows the one channel that needed explaining (the chest displacement) both ways.

Eight channels. The set on the last line has a single entry, so every channel has 7001 samples at the same spacing and start time. A spacing of 0.00005 s means 20,000 samples a second, and starting at −0.05 s with 7001 samples means the record ends at +0.30 s. The dimension column is odd for chest_d, which says "Meters" where every other channel names a quantity. I am taking time zero as the impact. One thing to note is that the key vehicle_x sounds like the whole car, while the description says it is one sensor on the left rear seat crossmember. I will use the description. Dividing by 9.81 to get g, the dummy channels peak between about 7 and 57 g, which looks like a crash. chest_d does not. It says meters and goes to −31,676, which is 31 km. If the numbers are micrometers it is 31.7 mm, a believable chest compression. I am flagging this as a units error in the file and treating the values as micrometers. The crossmember responds first, and the dummy channels follow some milliseconds later. They show the main deceleration between about 50 and 100 ms, and the chest displacement, now in millimeters, bottoms out at 31.7 mm. The crossmember is much spikier than the dummy channels.

Flags. The chest displacement units, and its dimension field (above). Assumptions. Time zero is the impact. Code prefix 11 is the driver dummy, and I took 13 to be the passenger, which the codes do not spell out. Every other unit is as the header gives it.

What to notice

The program and the report are one document, so a reader can check every number against the code that printed it. It reads as a record of the work in the order it was done. For this reason the flags and assumptions are gathered again at the end, so a reader does not have to find them in the middle.
