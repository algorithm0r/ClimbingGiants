Reading the assignment 7 program

This page reads a7_occupant_model.py, the program behind the technical report in the assignment 7 example reports, one section at a time. The program models the occupant as one mass held to the car by a spring and a damper (the belt), drives it with the car's own acceleration from the crash test, and steps it forward in time with RK4. Most of its work goes into showing that the answer has settled. It runs the model at nine steps, each half the one before, and picks the largest step whose next two halvings hardly move the travel. Each section shows the Python beside a MATLAB version that prints the same results (checked by running both on the example pack, the MATLAB version in GNU Octave), and the line notes say what each line does.

The model is the one on State as a vector, a state of two numbers whose rates come from the equation of motion, and the stepping method and the settling test are those of Order of accuracy. Program shape I suggests reading unfamiliar code by finding what comes in, what goes out and the state each loop builds, and the next section starts there. In the Python file the functions come first and the main part follows, from the top down. A MATLAB script has to keep its functions at the end, so its line ranges jump. A line you cannot read is usually covered on one of the Reading Python pages, which the notes link to, and the MATLAB lines have notes of their own.

The Filter

The CFC filter is the one from Smoothing, copied in. It runs forward over the record and then backward over the result, so the two passes' delays cancel. The program filters the drive at CFC 180, the class the course standards give for a vehicle acceleration that will be integrated, and the model integrates it twice.

def cfc(y, dt, cls):
    """SAE J211-1 Butterworth, forward then backward (assignment 4)."""
    wd = 2 * np.pi * cls * 2.0775
    wa = np.tan(wd * dt / 2)
    d = 1 + np.sqrt(2) * wa + wa**2
    a0 = wa**2 / d
    a1 = 2 * a0
    a2 = a0
    b1 = -2 * (wa**2 - 1) / d
    b2 = (-1 + np.sqrt(2) * wa - wa**2) / d

    def one_pass(x):
        out = np.zeros_like(x)
        for i in range(2, len(x)):
            out[i] = a0*x[i] + a1*x[i-1] + a2*x[i-2] + b1*out[i-1] + b2*out[i-2]
        return out

    forward = one_pass(y)
    backward = one_pass(forward[::-1])
    return backward[::-1]
function out = cfc(y, dt, cls)

    b2 = (-1 + sqrt(2) * wa - wa^2) / d;
    c = [a0, a1, a2, b1, b2];
    forward = one_pass(y, c);
    backward = one_pass(flip(forward), c);
    out = flip(backward);
end

        out(i) = c(1)*x(i) + c(2)*x(i-1) + c(3)*x(i-2) + c(4)*out(i-1) + c(5)*out(i-2);
    end
end

Stepping the Model with RK4

This is the model. The state is two numbers, the travel u and its rate w. rate gives how fast each is changing at one time. u changes at w, and w changes at the acceleration the equation of motion gives. RK4 takes each step by finding those rates four times, at the start, twice at the middle and at the end, and averaging them. The car's acceleration is only recorded every 0.05 ms, so between two samples it is read off a straight line between them.

def rk4(t, a_car, h):
    """Step the state (u, w) from rest at t[0] to the end of the record with RK4.
    Returns the step times, u and w."""
    def rate(time, u, w):
        a = np.interp(time, t, a_car)        # straight line between samples
        return w, (-C * w - K * u) / M - a

    n_steps = int(round((t[-1] - t[0]) / h))
    times = t[0] + h * np.arange(n_steps + 1)
    u = np.zeros(n_steps + 1)
    w = np.zeros(n_steps + 1)
    for n in range(n_steps):
        tn = times[n]
        un = u[n]
        wn = w[n]
        k1u, k1w = rate(tn, un, wn)
        k2u, k2w = rate(tn + h/2, un + h/2 * k1u, wn + h/2 * k1w)
        k3u, k3w = rate(tn + h/2, un + h/2 * k2u, wn + h/2 * k2w)
        k4u, k4w = rate(tn + h, un + h * k3u, wn + h * k3w)
        u[n+1] = un + h/6 * (k1u + 2*k2u + 2*k3u + k4u)
        w[n+1] = wn + h/6 * (k1w + 2*k2w + 2*k3w + k4w)
    return times, u, w
function [du, dw] = rate(time, u, w, t, a_car, M, K, C)
    % The rate of the state (u, w) at one time.
    a = interp1(t, a_car, min(time, t(end)));   % straight line between samples, last value past the end
    du = w;
    dw = (-C * w - K * u) / M - a;
end


function [times, u, w] = rk4(t, a_car, h, M, K, C)
    % Step the state (u, w) from rest at t(1) to the end of the record with RK4.
    % Returns the step times, u and w.
    n_steps = round((t(end) - t(1)) / h);
    times = t(1) + h * (0:n_steps)';
    u = zeros(n_steps + 1, 1);
    w = zeros(n_steps + 1, 1);
    for n = 1:n_steps
        tn = times(n);
        un = u(n);
        wn = w(n);

        [k2u, k2w] = rate(tn + h/2, un + h/2 * k1u, wn + h/2 * k1w, t, a_car, M, K, C);
        [k3u, k3w] = rate(tn + h/2, un + h/2 * k2u, wn + h/2 * k2w, t, a_car, M, K, C);
        [k4u, k4w] = rate(tn + h, un + h * k3u, wn + h * k3w, t, a_car, M, K, C);
        u(n+1) = un + h/6 * (k1u + 2*k2u + 2*k3u + k4u);
        w(n+1) = wn + h/6 * (k1w + 2*k2w + 2*k3w + k4w);
    end
end

The Largest Travel

travel runs the model at one step and keeps only the answer the report needs, the largest forward travel and when it happens. This is the largest value on the step grid. The run's own peak can fall a little above it between steps, and at a coarse step the step's error can move it either way (the 1.6 ms row of the table below is above the settled value). The step study shows that the difference is small at the step used.

def travel(t, a_car, h):
    """Largest forward travel (mm) and when it happens (ms), at step h. This is
    the largest value on the step grid, so it can only be at or below the true
    peak; the step study shows how much that matters."""
    times, u, w = rk4(t, a_car, h)
    i = np.argmax(u)
    return 1000 * u[i], 1000 * times[i]
function [x, at] = travel(t, a_car, h, M, K, C)
    % Largest forward travel (mm) and when it happens (ms), at step h. This is
    % the largest value on the step grid, so it can only be at or below the true
    % peak; the step study shows how much that matters.
    [times, u, ~] = rk4(t, a_car, h, M, K, C);
    [top, i] = max(u);
    x = 1000 * top;
    at = 1000 * times(i);
end

The Step Study

The study runs the model at nine steps, from 6.4 ms (128 samples) down to 0.025 ms (half a sample), each half the one before, with both the filtered and the raw drive. Each row of the table gives the travel at one step and how much it changed from the step before. Those changes are what the settling test reads.

Choosing the Step

The step chosen is the largest one for which the next two halvings each move the travel by less than SETTLED. Two are required because one small change can be luck. The program then prints the step in samples and its product with the natural frequency, which the report compares with the limit at which RK4 becomes unstable (Stability and accuracy).

    first_change = abs(s180[k+1] - s180[k])

The Run at That Step

The model runs once more at the chosen step, and this time the whole run is kept, since the checks and the figures need it. The program prints the travel, which is the report's answer, and the most negative travel, where the occupant has swung back past where they started. A real belt cannot push, so the report treats this part as the model's spring.

Three Checks

The first check runs the model with the drive filtered three ways, at the record's own step, to see how much the filter changes the travel. The second integrates the drive to a change of velocity and compares it with the approach speed, which tests the drive's sign and size. The third compares the model occupant's acceleration with the driver's chest accelerometer, since no channel measures the travel itself.

Running It Yourself

Both versions are downloads: a7_occupant_model.py and a7_occupant_model.m. Unzip a data pack, put the program in the pack's top folder beside crash and shots, and run it from there (Files and libraries explains why the folder matters). On your own pack it reads your data, so its numbers will differ from the ones above. The MATLAB version should run as it is in MATLAB R2018b or later. GNU Octave, which is free, needs a script's functions defined before they are used, so to run it there, move the functions to the top of the file and put a line 1; above them. The program needs a chest_x channel for its third check, which 11 of the course's tests do not have. Its approach speed, Figure 2's title and the step study's comment are written for the example test, so change them for yours.
