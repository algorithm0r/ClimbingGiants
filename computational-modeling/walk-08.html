Reading the assignment 7 program

This page reads a7_drag_model.py, the program behind the technical report in the assignment 7 example reports, one section at a time. The program asks whether quadratic drag improves the flight model. It fits a starting position and velocity to the first few frames of each training flight, steps the flight on with RK4 with and without drag, and measures how far each stepped ball ends up from the measured one. Each section below shows the Python beside a MATLAB version that prints exactly the same output (checked by running both on the example pack, the MATLAB version in GNU Octave), and the line notes say what each line does and which lines carry a decision.

Program shape I suggests reading unfamiliar code by finding what comes in, what goes out and the state each loop builds, and the next section starts there. In the Python file the functions come first and the main part follows, from the top down. A MATLAB script has to keep its functions at the end, so its line ranges jump. A line you cannot read is usually covered on one of the Reading Python pages, which the notes link to, and the MATLAB lines have notes of their own. The stepping functions follow the code on State as a vector and Order of accuracy.

Where the Flight Starts and Ends

These three functions are the flight-finding rules of the assignment 5 technical report. The vertical acceleration at each frame comes from a parabola through the 9 frames around it. The flight starts once the acceleration has settled near −9.81 after the last upward push, and it ends when the acceleration leaves that band (the ball has hit something) or the ball drops below rim height. Reading the assignment 5 program goes through them line by line (so the notes here are brief).

def accel(t, z):
    """Vertical acceleration at every frame, from a parabola through the 9 frames
    centered on it. NaN where the window runs off either end."""
    h = WINDOW // 2
    a = np.full(len(t), np.nan)
    for i in range(h, len(t) - h):
        c = np.polyfit(t[i - h:i + h + 1] - t[i], z[i - h:i + h + 1], 2)
        a[i] = 2 * c[0]
    return a


def release(t, z):
    """The first frame after the last upward push at which the acceleration is
    within TOL of -g and stays there for RUN frames."""
    a = accel(t, z)
    top = int(np.argmax(z))
    first = WINDOW // 2
    for i in range(top):
        if a[i] > 0:
            first = i + 1      # the hand is still pushing at frame i
    for i in range(first, len(t) - RUN + 1):
        if np.all(np.abs(a[i:i + RUN] + G) < TOL):
            return i
    return None


def flight_end(t, z):
    """Last frame of the free flight: the frame before the acceleration leaves the
    band for RUN frames in a row (the ball has hit something), or the frame
    before the ball drops through rim height, whichever comes first."""
    a = accel(t, z)
    top = int(np.argmax(z))
    for i in range(top, len(t) - RUN + 1):
        if np.all(np.abs(a[i:i + RUN] + G) >= TOL) or z[i] < RIM:
            return i - 1
    return len(t) - 1
function a = accel(t, z, WINDOW)
    % Vertical acceleration at every frame, from a parabola through the 9 frames
    % centered on it. NaN where the window runs off either end.
    h = floor(WINDOW / 2);

        c = polyfit(t(i-h:i+h) - t(i), z(i-h:i+h), 2);
        a(i) = 2 * c(1);
    end
end

Spotting a Filled-In Gap

Arc 325 has a stretch where the height falls on straight lines, which measured heights with 3 cm of noise never do. This function reports whether an arc has such a stretch, so the main part can drop it (on the example pack only arc 325 has one).

def straight_run(z, frames=6):
    """True if the height falls on a straight line for 'frames' steps or more.
    Measured heights carry about 3 cm of noise, so a straight line means the
    tracker filled a gap."""
    flat = np.abs(np.diff(z, 2)) < 0.001
    for i in range(len(flat) - frames + 2):
        if np.all(flat[i:i + frames - 1]):
            return True
    return False
function found = straight_run(z, frames)
    % True if the height falls on a straight line for 'frames' steps or more.
    % Measured heights carry about 3 cm of noise, so a straight line means the
    % tracker filled a gap.
    flat = abs(diff(z, 2)) < 0.001;
    found = false;
    for i = 1:numel(flat)-frames+2
        if all(flat(i:i+frames-2))
            found = true;
            return
        end
    end
end

The Starting State

Stepping needs a position and a velocity at one moment. This function fits straight lines to the first n positions across the floor and a parabola with gravity held at 9.81 to the first n heights, the fits of assignment 5. Time is measured from the middle of the fitted frames, so each fit's constant is the position at that moment and its slope is the velocity there. A straight line through the frames of a slowing ball likely has a slope nearer the speed at the middle of them than at either end, which is the reason for the middle. The six numbers are handed back in the order the stepper expects, positions first.

def start_state(t, x, y, z, first, n):
    """Position and velocity at the middle of n frames starting at 'first', from
    straight lines in x and y and a parabola in z with gravity held at 9.81.
    Time is measured from the middle of the fitted frames, so each fit's constant
    is the position there and its slope is the velocity there."""
    t_mid = np.mean(t[first:first + n])
    dt = t[first:first + n] - t_mid
    A = np.column_stack([np.ones_like(dt), dt])
    cx = np.linalg.lstsq(A, x[first:first + n], rcond=None)[0]
    cy = np.linalg.lstsq(A, y[first:first + n], rcond=None)[0]
    cz = np.linalg.lstsq(A, z[first:first + n] + 0.5 * G * dt ** 2, rcond=None)[0]
    return t_mid, np.array([cx[0], cy[0], cz[0], cx[1], cy[1], cz[1]])
function [t_mid, s] = start_state(t, x, y, z, first, n, G)
    % Position and velocity at the middle of n frames starting at 'first', from
    % straight lines in x and y and a parabola in z with gravity held at 9.81.
    % Time is measured from the middle of the fitted frames, so each fit's constant
    % is the position there and its slope is the velocity there.
    idx = first:first+n-1;
    t_mid = mean(t(idx));
    dt = t(idx) - t_mid;
    A = [ones(size(dt)), dt];
    cx = A \ x(idx);
    cy = A \ y(idx);
    cz = A \ (z(idx) + 0.5 * G * dt .^ 2);
    s = [cx(1); cy(1); cz(1); cx(2); cy(2); cz(2)];
end

The Rate and One RK4 Step

This is the physics and the method, kept apart as on State as a vector. rate takes a state and returns how fast each of its six numbers is changing. The positions change at the velocity. The velocities change by gravity and by a drag of k times the speed squared, pointing against the motion, and because the speed uses all three components the three directions have to be stepped together. rk4_step is one step of RK4 from Order of accuracy, and it never mentions drag or basketballs (so Heun or Euler could replace it without touching rate).

def rate(s, drag_k):
    """The rate of the state s = [x, y, z, vx, vy, vz]. Drag acts against the
    velocity and grows with the speed squared, so every direction needs the speed."""
    vx = s[3]
    vy = s[4]
    vz = s[5]
    speed = np.sqrt(vx ** 2 + vy ** 2 + vz ** 2)
    return np.array([vx, vy, vz,
                     -drag_k * speed * vx,
                     -drag_k * speed * vy,
                     -G - drag_k * speed * vz])


def rk4_step(s, h, drag_k):
    k1 = rate(s, drag_k)
    k2 = rate(s + h / 2 * k1, drag_k)
    k3 = rate(s + h / 2 * k2, drag_k)
    k4 = rate(s + h * k3, drag_k)
    return s + h / 6 * (k1 + 2 * k2 + 2 * k3 + k4)
function ds = rate(s, drag_k, G)
    % The rate of the state s = [x; y; z; vx; vy; vz]. Drag acts against the
    % velocity and grows with the speed squared, so every direction needs the speed.
    vx = s(4);
    vy = s(5);
    vz = s(6);
    speed = sqrt(vx ^ 2 + vy ^ 2 + vz ^ 2);
    ds = [vx; vy; vz;
          -drag_k * speed * vx;
          -drag_k * speed * vy;
          -G - drag_k * speed * vz];
end


function s = rk4_step(s, h, drag_k, G)
    k1 = rate(s, drag_k, G);
    k2 = rate(s + h / 2 * k1, drag_k, G);
    k3 = rate(s + h / 2 * k2, drag_k, G);
    k4 = rate(s + h * k3, drag_k, G);
    s = s + h / 6 * (k1 + 2 * k2 + 2 * k3 + k4);
end

Stepping to a Frame and Scoring the Flight

The frames are not always exactly 40 ms apart (assignment 5 found a few gaps of 30 and 50 ms), and the starting state sits between two frames, so step_to fills any gap with a whole number of equal steps of about the chosen length. unseen_error uses it to carry the ball from frame to frame through the part of the flight the fit did not see, and it returns the rms distance between the stepped and the measured ball.

def step_to(s, t_from, t_to, drag_k, h_max):
    """Step the state from t_from to t_to in equal steps no longer than about
    h_max, so that the last step lands exactly on t_to."""
    n = max(1, int(np.floor((t_to - t_from) / h_max + 0.5)))
    h = (t_to - t_from) / n
    for i in range(n):
        s = rk4_step(s, h, drag_k)
    return s


def unseen_error(t, x, y, z, first, last, t_mid, s, drag_k):
    """rms distance (m) between the stepped ball and the measured ball over
    frames first .. last."""
    t_now = t_mid
    gaps = []
    for j in range(first, last + 1):
        s = step_to(s, t_now, t[j], drag_k, H)
        t_now = t[j]
        gaps.append(np.sqrt((s[0] - x[j]) ** 2 + (s[1] - y[j]) ** 2 + (s[2] - z[j]) ** 2))
    return np.sqrt(np.mean(np.array(gaps) ** 2))
function s = step_to(s, t_from, t_to, drag_k, h_max, G)
    % Step the state from t_from to t_to in equal steps no longer than about
    % h_max, so that the last step lands exactly on t_to.
    n = max(1, floor((t_to - t_from) / h_max + 0.5));
    h = (t_to - t_from) / n;
    for i = 1:n
        s = rk4_step(s, h, drag_k, G);
    end
end


function err = unseen_error(t, x, y, z, first, last, t_mid, s, drag_k, H, G)
    % rms distance (m) between the stepped ball and the measured ball over
    % frames first .. last.
    t_now = t_mid;
    gaps = [];
    for j = first:last
        s = step_to(s, t_now, t(j), drag_k, H, G);
        t_now = t(j);
        gaps(end+1) = sqrt((s(1) - x(j)) ^ 2 + (s(2) - y(j)) ^ 2 + (s(3) - z(j)) ^ 2);
    end
    err = sqrt(mean(gaps .^ 2));
end

The Rim Crossing, Stepped and Measured

The crossing is where the ball's center comes down through 3.048 m. For the stepped ball, stepped_crossing steps until the ball is below the rim on the way down and then finds the crossing inside that last step by bisection, as on the week 7 pages. For the measured ball, measured_crossing finds the two frames either side of rim height on the way down and draws a straight line between them. find_shot, between the two, picks a shot out by its id for the figure. The measured crossing is likely a little off on an arc where the ball touches the rim near rim height, which is one reason the main part scores only some arcs.

def stepped_crossing(t_now, s, drag_k):
    """Time and floor position where the stepped ball comes down through rim
    height: steps of H until it is below the rim on the way down, then bisection
    on the length of that last step, to a microsecond."""
    while True:
        s_next = rk4_step(s, H, drag_k)
        if s_next[2] < RIM and s_next[5] < 0:
            break
        s = s_next
        t_now = t_now + H
    lo = 0.0           # a step this long ends above the rim
    hi = H             # and this long ends below it
    while hi - lo > 1e-6:
        mid = (lo + hi) / 2
        if rk4_step(s, mid, drag_k)[2] > RIM:
            lo = mid
        else:
            hi = mid
    s = rk4_step(s, lo, drag_k)
    return t_now + lo, s[0], s[1]


def find_shot(shots, wanted):
    """The shot whose id is wanted."""
    for s in shots:
        if s['id'] == wanted:
            return s


def measured_crossing(t, x, y, z):
    """The rim crossing in the record: the last frame above rim height after the
    top, and a straight line from it to the next frame (which is below)."""
    i = int(np.argmax(z))
    while z[i + 1] >= RIM:
        i = i + 1
    f = (z[i] - RIM) / (z[i] - z[i + 1])     # how far from frame i to frame i+1
    return i, t[i] + f * (t[i + 1] - t[i]), x[i] + f * (x[i + 1] - x[i]), y[i] + f * (y[i + 1] - y[i])

end

Checking the Stepper and the Step

Two checks come before any results. With no drag the acceleration is constant, and RK4 should give back the fitted parabola exactly, so the first loop compares the two at the end of every flight. The second loop steps every arc with the most drag at five step sizes, halving each time, and prints the largest change in any arc's final position at each halving. The ratio of one change to the next should settle near 16 for a fourth-order method, and the changes themselves say whether the step matters at all next to the tracker's noise. On the example pack every change is under a micrometer (see What It Prints).

Every Arc, Every Fit Length, Three Models

This is the main loop. For each fit length and each arc it fits the starting state, then scores the three models on the unseen frames. If the arc's free flight reaches the measured crossing, it also finds the stepped crossing for each model and scores the distance between the two across the floor. The rule for "reaches" is that the flight ends no more than 4 frames, half an acceleration window, before the crossing (a longer gap usually means the ball touched the rim or the board first).

# every arc, every fit length, all three models

        # than half an acceleration window between the end of the flight and it

In Colab, upload the program beside your unzipped pack and run it in a cell with %run a7_drag_model.py (the Colab guide shows how). On your own pack it reads your data, so its numbers will differ from the ones above. The MATLAB version should run as it is in MATLAB R2018b or later. GNU Octave, which is free, needs a script's functions defined before they are used, so to run it there, move the functions to the top of the file and put a line 1; above them.
