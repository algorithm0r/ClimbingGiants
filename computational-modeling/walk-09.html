Reading the assignment 8 program

This page reads a8_crossing_intervals.py, the program behind the technical report in the assignment 8 example reports, one section at a time. The program puts a 90% interval on where each short record comes down through rim height. It fits the few frames of flight a short record holds and solves for the crossing, then adds noise at the tracker's stated level to those frames and fits and solves again, 1000 times. The spread of the 1000 answers gives the interval. Last, it cuts the training arcs to the length of a short record, gives them the same intervals, and counts how often the interval holds the crossing the whole arc shows. Each section shows the Python beside a MATLAB version that does the same steps, and the line notes say what each line does and which lines carry a decision.

The two versions draw different random numbers, so their intervals typically differ by a few centimeters and a count may differ by one arc. Everything that does not depend on the draws prints the same (checked by running both on the example pack, the MATLAB version in GNU Octave). The output at the bottom of the page is the Python version's, which is the one the report quotes.

Program shape I suggests reading unfamiliar code by finding what comes in, what goes out and the state each loop builds, and the next section starts there. In the Python file the functions come first and the main part follows, from the top down. A MATLAB script has to keep its functions at the end, so its line ranges jump. A line you cannot read is usually covered on one of the Reading Python pages, which the notes link to, and the MATLAB lines have notes of their own.

Settings

The program brings in its libraries and names the numbers it works with. Gravity and the rim height are given. The window, band and run come from the assignment 5 program. The window sets every acceleration estimate, including the ones that find the last push on every record, and the band and run are used only on the whole training arcs. The number of reruns, the level and the seed are new choices.

Where the Hand Lets Go

A short record starts while the ball is still in the shooter's hand, so the program has to find where the flight starts. accel estimates the vertical acceleration at each frame from a parabola through the 9 frames around it, and last_push finds the last frame before the top where that acceleration is upward, meaning the hand is still pushing. The fit starts on the frame after it, which is likely the first frame of free flight (or close to it, since the estimate is spread over 9 frames).

def accel(t, z):
    """Vertical acceleration at every frame, from a parabola through the 9 frames
    centered on it. NaN where the window runs off either end."""
    h = WINDOW // 2
    a = np.full(len(t), np.nan)
    for i in range(h, len(t) - h):
        c = np.polyfit(t[i - h:i + h + 1] - t[i], z[i - h:i + h + 1], 2)
        a[i] = 2 * c[0]
    return a


def last_push(t, z):
    """The last frame before the top where the acceleration is upward (the hand
    is still on the ball). With no such frame, the first frame that has an
    acceleration estimate."""
    a = accel(t, z)
    top = int(np.argmax(z))
    last = WINDOW // 2
    for i in range(top):
        if a[i] > 0:
            last = i
    return last
function a = accel(t, z, WINDOW)
    % Vertical acceleration at every frame, from a parabola through the 9 frames

Whole Flights, from Assignment 5

These three functions are used only on the whole training arcs. release and flight_end are the assignment 5 rules for where a whole flight starts and ends, and filled_in finds a stretch where the tracker filled a gap with a straight line, as it did in arc 325.

def release(t, z):
    """Assignment 5's release on a whole arc: the first frame after the last push
    where the acceleration is within TOL of -g for RUN frames in a row."""
    a = accel(t, z)
    for i in range(last_push(t, z) + 1, len(t) - RUN + 1):
        if np.all(np.abs(a[i:i + RUN] + G) < TOL):
            return i


def flight_end(t, z):
    """Assignment 5's end of a whole flight: the frame before the acceleration
    leaves the band for RUN frames (the ball hit something), or before the ball
    drops below rim height, whichever comes first."""
    a = accel(t, z)
    for i in range(int(np.argmax(z)), len(t) - RUN + 1):
        if np.all(np.abs(a[i:i + RUN] + G) >= TOL) or z[i] < RIM:
            return i - 1
    return len(t) - 1


def filled_in(z):
    """True if the height runs in a straight line for 6 steps or more, which
    3 cm of tracking noise cannot do (the tracker filled a gap)."""
    flat = np.abs(np.diff(z, 2)) < 0.001
    for i in range(len(flat) - 4):
        if np.all(flat[i:i + 5]):
            return True
    return False

Fitting the Flight and Solving for the Crossing

This is the model, and it is held fixed for every rerun. The height is a parabola with gravity held at 9.81, fitted by moving the known term to the measurements and fitting a straight line to what is left. Across the floor the ball moves in straight lines. The crossing is where the parabola comes back down to rim height, which is a root of a quadratic, and a parabola that comes down through rim height crosses it twice. The function keeps the later root, the one with the ball falling. The same function fits gravity freely when it is told to (the whole-flight answer uses this).

def line(t, v):
    """Least-squares straight line v = c0 + c1 t."""
    A = np.column_stack([np.ones_like(t), t])
    return np.linalg.lstsq(A, v, rcond=None)[0]


def crossing(t, x, y, z, fit_gravity=False):
    """Fit the frames given and solve for the falling crossing of rim height.
    Returns the time from the first frame given, and x and y there."""
    t = t - t[0]
    if fit_gravity:
        A = np.column_stack([np.ones_like(t), t, t ** 2])
        c0, c1, c2 = np.linalg.lstsq(A, z, rcond=None)[0]
    else:   # the known term moves to the left-hand side
        c0, c1 = line(t, z + 0.5 * G * t ** 2)
        c2 = -G / 2
    # c2 t^2 + c1 t + (c0 - RIM) = 0; with c2 < 0 the later root has the minus sign
    tc = (-c1 - np.sqrt(c1 ** 2 - 4 * c2 * (c0 - RIM))) / (2 * c2)
    bx = line(t, x)
    by = line(t, y)
    return tc, bx[0] + bx[1] * tc, by[0] + by[1] * tc
function c = fit_line(t, v)
    % Least-squares straight line v = c(1) + c(2) t.
    A = [ones(size(t)), t];
    c = A \ v;
end


function [tc, xc, yc] = crossing(t, x, y, z, fit_gravity, G, RIM)
    % Fit the frames given and solve for the falling crossing of rim height.
    % Returns the time from the first frame given, and x and y there.
    t = t - t(1);
    if fit_gravity
        A = [ones(size(t)), t, t.^2];
        c = A \ z;
    else   % the known term moves to the left-hand side
        c = fit_line(t, z + 0.5 * G * t.^2);
        c(3) = -G / 2;
    end
    % c3 t^2 + c2 t + (c1 - RIM) = 0; with c3 < 0 the later root has the minus sign
    tc = (-c(2) - sqrt(c(2)^2 - 4 * c(3) * (c(1) - RIM))) / (2 * c(3));
    bx = fit_line(t, x);
    by = fit_line(t, y);
    xc = bx(1) + bx(2) * tc;
    yc = by(1) + by(2) * tc;
end

The Crossing in the Frames, and Long or Short

observed finds the crossing in a whole arc's own frames: the frame just above rim height on the way down and the one after it bracket it, and a straight line between them gives where. split turns a crossing point into the two numbers the report gives. Long/short is measured along the line from the first fitted frame to the hoop, so a positive value is past the hoop center, and left/right is measured across that line, as the shooter sees it. A signed pair can be either side of zero, which a distance from the hoop center cannot (Coverage shows what that floor at zero may do to an interval).

def observed(x, y, z):
    """The frame just before the ball comes down through rim height, and where it
    crossed, by straight-line interpolation between that frame and the next."""
    for k in range(int(np.argmax(z)), len(z) - 1):
        if z[k] >= RIM and z[k + 1] < RIM:
            f = (z[k] - RIM) / (z[k] - z[k + 1])
            return k, x[k] + f * (x[k + 1] - x[k]), y[k] + f * (y[k + 1] - y[k])


def split(x, y, s, x0, y0):
    """A crossing point as (long, right): meters past the hoop center along the
    line from (x0, y0), the first fitted frame, to the hoop, and meters to the
    right of that line as the shooter sees it."""
    ux = s['hoop_x'] - x0
    uy = s['hoop_y'] - y0
    n = np.hypot(ux, uy)
    ux = ux / n
    uy = uy / n
    dx = x - s['hoop_x']
    dy = y - s['hoop_y']
    return dx * ux + dy * uy, uy * dx - ux * dy
function [k, xc, yc] = observed(x, y, z, RIM)
    % The frame just before the ball comes down through rim height, and where it
    % crossed, by straight-line interpolation between that frame and the next.
    [~, top] = max(z);
    for k = top:numel(z)-1
        if z(k) >= RIM && z(k+1) < RIM
            f = (z(k) - RIM) / (z(k) - z(k+1));
            xc = x(k) + f * (x(k+1) - x(k));
            yc = y(k) + f * (y(k+1) - y(k));
            return
        end
    end
end


function [lng, rgt] = split_point(x, y, s, x0, y0)
    % A crossing point as long and right: meters past the hoop center along the
    % line from (x0, y0), the first fitted frame, to the hoop, and meters to the
    % right of that line as the shooter sees it.
    ux = s.hoop_x - x0;
    uy = s.hoop_y - y0;
    n = hypot(ux, uy);
    ux = ux / n;
    uy = uy / n;
    dx = x - s.hoop_x;
    dy = y - s.hoop_y;
    lng = dx * ux + dy * uy;
    rgt = uy * dx - ux * dy;
end

Resampling and the 90% Interval

This is the resampling. The value is the crossing from the frames as measured. Then, 1000 times, the function adds fresh noise to every fitted frame (3.07 cm in height and 2.84 cm along and across the court, the header's figures) and runs the same fit and solve again. Sorting the 1000 answers and leaving out 50 at each end gives the interval. Only the noise is varied, and gravity, the model, the first fitted frame and the direction to the hoop are held fixed. Drawing the noise as normal and independent is a common first choice, and it may make the interval too narrow here, since the header says the noise is mildly correlated.

def interval(t, x, y, z, first, s, rng):
    """The crossing from the frames, and its 90% interval from DRAWS reruns with
    the tracker's noise added to the fitted frames. Returns the value, the low
    and high ends (each as long, right) and every rerun's answer."""
    t = t[first:]
    x = x[first:]
    y = y[first:]
    z = z[first:]
    x0 = x[0]
    y0 = y[0]
    tc, xc, yc = crossing(t, x, y, z)
    value = split(xc, yc, s, x0, y0)
    runs = np.zeros((DRAWS, 2))
    for k in range(DRAWS):
        zk = z + SIG_Z * rng.standard_normal(len(z))
        xk = x + SIG_XY * rng.standard_normal(len(x))
        yk = y + SIG_XY * rng.standard_normal(len(y))
        tc, xc, yc = crossing(t, xk, yk, zk)
        runs[k] = split(xc, yc, s, x0, y0)
    ends = np.sort(runs, axis=0)
    return np.array(value), ends[LEAVE], ends[DRAWS - 1 - LEAVE], runs
function [value, lo, hi, runs] = interval(t, x, y, z, first, s, DRAWS, LEAVE, SIG_Z, SIG_XY, G, RIM)
    % The crossing from the frames, and its 90% interval from DRAWS reruns with
    % the tracker's noise added to the fitted frames. Returns the value, the low
    % and high ends (each as long, right) and every rerun's answer.
    t = t(first:end);
    x = x(first:end);
    y = y(first:end);
    z = z(first:end);
    [tc, xc, yc] = crossing(t, x, y, z, false, G, RIM);
    [v1, v2] = split_point(xc, yc, s, x(1), y(1));
    value = [v1, v2];
    runs = zeros(DRAWS, 2);
    for k = 1:DRAWS
        zk = z + SIG_Z * randn(numel(z), 1);
        xk = x + SIG_XY * randn(numel(x), 1);
        yk = y + SIG_XY * randn(numel(y), 1);
        [tc, xc, yc] = crossing(t, xk, yk, zk, false, G, RIM);
        [r1, r2] = split_point(xc, yc, s, x(1), y(1));
        runs(k, :) = [r1, r2];
    end
    ends = sort(runs);
    lo = ends(LEAVE + 1, :);
    hi = ends(DRAWS - LEAVE, :);
end

Starting the Fit One Frame Later

Resampling varies only the noise. The first fitted frame was chosen, and the reruns never move it. This section starts each fit one frame later and measures how far the value moves, so the report can compare that with the width of the interval. A move much smaller than the width usually means the choice matters little to the answer.

The Training Arcs

This loop is the coverage check. Each training arc is cut 7 frames after its last push, so it holds what a short record would, and given an interval in exactly the same way. Its answer comes from the whole arc: the whole free flight fitted with gravity free and carried down to rim height. Most arcs (15 of the 23) touch the rim or the board before the ball's center gets down to rim height, so on those the frames never show a free-flight crossing. Where the flight does run down to rim height, the crossing in the frames is checked as well.

Decisions in This Program

Every line below holds a decision the student made, and the report states most of them. Gravity at 9.81 and the rim height are not on the list, since they are given. The line numbers are those of the downloadable files, and the hint under each code box gives the lines it shows. It is a good idea to check your own program with the test on Using AI (pick a line and say why it is that way). For these lines the answer is a choice, and a different student could reasonably have chosen otherwise.

Python lineMATLAB lineThe decisionWhat else could have been chosen
2727Each record is refitted 1000 timesfewer reruns, which leave the ends of the interval less settled, or more, which cost time
2828The interval is the middle 900 of 1000 sorted answers (percentiles)the value ± 1.645 standard deviations, which gives 90% only when the spread is near-normal
18662The fit starts on the frame after the last pusha frame or two later, which leaves fewer frames to fit
152367The noise is normal at the header’s level, independent from frame to framedrawing from the residuals of fitted flights, or allowing for the correlation the header mentions
135349The crossing is split into long/short and left/right along the line to the hoopthe distance from the hoop center, or the court’s own x and y
17547Training arcs are cut at the median of 7 frames after the last pushcutting each arc to match one short record, or at several lengths
225112The answer is the whole free flight fitted with gravity freeonly the crossing seen in the frames, which exists on fewer arcs

Running It Yourself

Both versions are downloads: a8_crossing_intervals.py and a8_crossing_intervals.m. Unzip a data pack, put the program in the pack's top folder beside crash and shots, and run it from there (Files and libraries explains why the folder matters). In Colab, upload the program beside your unzipped pack and run it in a cell with %run a8_crossing_intervals.py (the Colab guide shows how). On your own pack it reads your data, so its numbers will differ from the ones above. The MATLAB version should run as it is in MATLAB R2018b or later. GNU Octave, which is free, needs a script's functions defined before they are used, so to run it there, move the functions to the top of the file and put a line 1; above them.
