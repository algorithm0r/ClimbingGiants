Reading the assignment 4 program

This page reads a4_filter_report.py, the program behind the technical report in the assignment 4 example reports, one section at a time. The program filters the crossmember channel with the SAE J211-1 filter, run forward and then backward, and reports its peak at CFC 60. Before that it checks the filter, and after it gives the peak at every class J211 defines and shows what a single forward pass would have done. Each section shows the Python beside a MATLAB version that prints the same results (checked by running both on the example pack, the MATLAB version in GNU Octave), and the line notes say what each line does.

The filter is the one from Smoothing and phase lag, written as three small functions. Program shape I suggests reading unfamiliar code by finding what comes in, what goes out and the state each loop builds, and the next section starts there. In the Python file the functions come first and the main part follows, from the top down. A MATLAB script has to keep its functions at the end, so its line ranges jump. A line you cannot read is usually covered on one of the Reading Python pages, which the notes link to, and the MATLAB lines have notes of their own.

The Filter's Coefficients

Each output of the filter is a weighted sum of the current input, the two inputs before it and the two outputs before it. The five weights depend only on the class and the time between samples, and this function works them out as the standard gives them.

def cfc_coefficients(cls, dt):
    """SAE J211-1 coefficients, as given in the course notes (Smoothing)."""
    wd = 2 * np.pi * cls * 2.0775
    wa = np.tan(wd * dt / 2)
    d = 1 + np.sqrt(2) * wa + wa ** 2
    a0 = wa ** 2 / d
    b1 = -2 * (wa ** 2 - 1) / d
    b2 = (-1 + np.sqrt(2) * wa - wa ** 2) / d
    return a0, 2 * a0, a0, b1, b2
function c = cfc_coefficients(cls, dt)
    % SAE J211-1 coefficients, as given in the course notes (Smoothing).
    wd = 2 * pi * cls * 2.0775;
    wa = tan(wd * dt / 2);
    d = 1 + sqrt(2) * wa + wa^2;
    a0 = wa^2 / d;
    b1 = -2 * (wa^2 - 1) / d;
    b2 = (-1 + sqrt(2) * wa - wa^2) / d;
    c = [a0, 2 * a0, a0, b1, b2];
end

One Pass

One pass runs the filter over the record in order. Each output needs the two outputs before it, so the first two have to be set before the loop. Setting them to zero means the filter starts from rest. One of the checks starts it from the first sample instead.

def one_pass(x, c, start=0.0):
    """One pass in the direction of increasing index. start is what the two
    outputs before the first sample are taken to be."""
    a0, a1, a2, b1, b2 = c
    out = np.zeros(len(x))
    out[0] = start
    out[1] = start
    for i in range(2, len(x)):
        out[i] = (a0 * x[i] + a1 * x[i - 1] + a2 * x[i - 2]
                  + b1 * out[i - 1] + b2 * out[i - 2])
    return out
function out = one_pass(x, c, start)
    % One pass in the direction of increasing index. start is what the two
    % outputs before the first sample are taken to be.
    out = zeros(size(x));
    out(1) = start;
    out(2) = start;
    for i = 3:numel(x)
        out(i) = c(1) * x(i) + c(2) * x(i-1) + c(3) * x(i-2) ...
                 + c(4) * out(i-1) + c(5) * out(i-2);
    end
end

Forward and Backward

A single pass delays the record. Running a second pass backward over the result delays it the same amount the other way, so the two cancel. The function reverses the forward result, runs the same one-pass filter over it, and reverses the answer back.

def cfc(y, dt, cls, start_at_data=False):
    """Forward, then backward over the forward result. With start_at_data the
    filter starts from the first sample instead of from zero."""
    c = cfc_coefficients(cls, dt)
    start = 0.0
    if start_at_data:
        start = y[0]
    fwd = one_pass(y, c, start)[::-1]       # forward, then reversed
    start = 0.0
    if start_at_data:
        start = fwd[0]
    back = one_pass(fwd, c, start)          # forward again over the reversed record
    return back[::-1]
function out = cfc(y, dt, cls, start_at_data)
    % Forward, then backward over the forward result. With start_at_data the
    % filter starts from the first sample instead of from zero.
    c = cfc_coefficients(cls, dt);
    start = 0;
    if start_at_data
        start = y(1);
    end
    fwd = flip(one_pass(y, c, start));      % forward, then reversed
    start = 0;
    if start_at_data
        start = fwd(1);
    end
    back = one_pass(fwd, c, start);         % forward again over the reversed record
    out = flip(back);
end

The Peak

def peak(t, y):

Checks

The first check is on the filter itself. Fed a constant, a filter of this kind should hand back the same constant, so its gain on a constant should be 1. The coefficients also exist only when the sample rate is more than 4.155 times the class. The other checks change one choice around the filter and see how far the peak moves: starting from the first sample, removing the mean before impact, and taking g as 9.81 instead of standard gravity.

Every Class

The table gives the peak at every class, with the change in velocity over the whole record as a comparison. A filter takes the top off a spike and spreads it to the sides, so the peak falls while the area under the record, the change in velocity, hardly moves.

print("\nevery class")
print(f"  {'filter':12} {'peak m/s^2':>11} {'peak g':>8} {'at ms':>7} {'delta-v m/s':>12}")
filtered = {'as recorded': raw}
for cls in CLASSES:
    filtered[f'CFC {cls}'] = cfc(raw, dt, cls)
for label, y in filtered.items():
    p, tp = peak(t, y)
    dv = np.sum((y[1:] + y[:-1]) / 2) * dt        # trapezoid rule, whole record
    print(f"  {label:12} {p:11.1f} {p / G:8.1f} {tp:7.2f} {dv:12.3f}")

Running It Yourself

Both versions are downloads: a4_filter_report.py and a4_filter_report.m. Unzip a data pack, put the program in the pack's top folder beside crash and shots, and run it from there (Files and libraries explains why the folder matters). In Colab, upload the program beside your unzipped pack and run it in a cell with %run a4_filter_report.py (the Colab guide shows how). On your own pack it reads your data, so its numbers will differ from the ones above. On 64 of the course's 200 tests the car-body channel is a sill (its description says SILL or ELTA-V), so the search for CROSSMEMBER finds nothing and the program stops. Finding the channel by its key, vehicle_x, works on every test. The 45 to 60 ms window and the figures' ranges are set for the example test. The MATLAB version should run as it is in MATLAB R2018b or later. GNU Octave, which is free, needs a script's functions defined before they are used, so to run it there, move the functions to the top of the file and put a line 1; above them.
