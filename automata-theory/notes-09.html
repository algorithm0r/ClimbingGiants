The Acceptance Problem for TMs

The most important undecidable language is:

$$A_{TM} = \{\langle M, w \rangle \mid M \text{ is a TM and } M \text{ accepts } w\} $$

Theorem: $A_{TM}$ is Turing-recognizable but not decidable.

The Turing-recognizability is easy: simulate $M$ on $w$; if $M$ accepts, accept. The hard part is undecidability.

Undecidability of $A_{TM}$ via Diagonalization

Theorem: $A_{TM}$ is undecidable.

Proof: Assume for contradiction that $A_{TM}$ is decidable. Then there exists a TM $H$ that decides $A_{TM}$:

$$H(\langle M, w \rangle) = \begin{cases} \text{accept} & \text{if } M \text{ accepts } w \\ \text{reject} & \text{if } M \text{ does not accept } w \end{cases} $$

Construct a new TM $D$ using $H$ as a subroutine:

$D$ = "On input $\langle M \rangle$ where $M$ is a TM:

  1. Run $H$ on $\langle M, \langle M \rangle \rangle$.
  2. If $H$ accepts, reject.
  3. If $H$ rejects, accept."

$D$ does the opposite of what $H$ says $M$ does on its own description.

Now ask: what does $D$ do on input $\langle D \rangle$?

$$D(\langle D \rangle) = \begin{cases} \text{accept} & \text{if } H \text{ rejects } \langle D, \langle D \rangle \rangle \text{, i.e., } D \text{ does not accept } \langle D \rangle \\ \text{reject} & \text{if } H \text{ accepts } \langle D, \langle D \rangle \rangle \text{, i.e., } D \text{ accepts } \langle D \rangle \end{cases} $$

This is a contradiction in both cases:

  • If $D$ accepts $\langle D \rangle$, then $D$ rejects $\langle D \rangle$
  • If $D$ does not accept $\langle D \rangle$, then $D$ accepts $\langle D \rangle$

Therefore our assumption that $H$ exists is false. $A_{TM}$ is undecidable. $\square$

The diagonal structure: $D$ is "designed to contradict itself" — it accepts iff it doesn't accept its own description. This is the same paradox as "this statement is false."

The Universal Turing Machine

The proof that $A_{TM}$ is Turing-recognizable relies on the existence of a Universal Turing Machine (UTM):

Theorem: There exists a TM $U$ such that for any TM $M$ and string $w$:

$$U(\langle M, w \rangle) \text{ accepts iff } M \text{ accepts } w $$

The UTM $U$ simulates any TM given its description as input.

Construction idea (multitape TM):

  • Tape 1: encoding of $M$'s tape contents
  • Tape 2: encoding of $M$'s transition function
  • Tape 3: $M$'s current state

$U$ simulates each step of $M$ by:

  1. Looking up the current state (Tape 3) and current symbol (Tape 1) in $M$'s transitions (Tape 2)
  2. Updating the tape symbol, moving the head, and updating the state

Historical significance: The UTM is the theoretical foundation for programmable computers. A computer is a physical implementation of a UTM: it reads a program (encoding of a TM) and simulates it on data (the input string).

Reductions

The primary tool for proving undecidability is reduction: if we can reduce a known undecidable problem to a new problem, the new problem is also undecidable.

Mapping Reductions

Definition: Language $A$ is mapping reducible to language $B$, written $A \leq_m B$, if there exists a computable function $f: \Sigma^* \to \Sigma^*$ such that:

$$w \in A \iff f(w) \in B $$

The function $f$ is called a reduction.

Theorem: If $A \leq_m B$ and $B$ is decidable, then $A$ is decidable.

Contrapositive: If $A \leq_m B$ and $A$ is undecidable, then $B$ is undecidable.

Strategy for proving $B$ is undecidable:

  1. Take a known undecidable language $A$ (usually $A_{TM}$)
  2. Construct a computable reduction $f$ such that $w \in A \iff f(w) \in B$
  3. Conclude: if $B$ were decidable, we could use $f$ to decide $A$ — contradiction

Reduction Template

Proof that $B$ is undecidable (by reduction from $A_{TM}$):

Assume for contradiction that $B$ is decidable by TM $R$.

We construct a TM $S$ that decides $A_{TM}$:

$S$ = "On input $\langle M, w \rangle$:

  1. Construct [some object $X$ based on $M$ and $w$]
  2. Run $R$ on $\langle X \rangle$
  3. Output what $R$ outputs."

Correctness: Show that $\langle M, w \rangle \in A_{TM}$ iff $\langle X \rangle \in B$.

If $R$ decides $B$, then $S$ decides $A_{TM}$. But $A_{TM}$ is undecidable — contradiction. Therefore $R$ does not exist and $B$ is undecidable. $\square$

More Undecidable Problems

$HALT_{TM}$ — The Halting Problem

$$HALT_{TM} = \{\langle M, w \rangle \mid M \text{ is a TM that halts on input } w\} $$

Theorem: $HALT_{TM}$ is undecidable.

Proof (reduction from $A_{TM}$): Suppose $R$ decides $HALT_{TM}$. Build $S$ to decide $A_{TM}$:

$S$ = "On input $\langle M, w \rangle$:

  1. Run $R$ on $\langle M, w \rangle$. If $R$ rejects, reject ($M$ loops on $w$, so $M$ doesn't accept).
  2. Simulate $M$ on $w$ until it halts (guaranteed by step 1).
  3. If $M$ accepted, accept. If $M$ rejected, reject."

If $HALT_{TM}$ were decidable, $A_{TM}$ would be decidable — contradiction. $\square$

$E_{TM}$ — Emptiness Problem for TMs

$$E_{TM} = \{\langle M \rangle \mid M \text{ is a TM and } L(M) = \emptyset\} $$

Theorem: $E_{TM}$ is undecidable.

Proof (reduction from $A_{TM}$): Suppose $R$ decides $E_{TM}$. Build $S$ to decide $A_{TM}$:

$S$ = "On input $\langle M, w \rangle$:

  1. Construct TM $M'$:
    • $M'$ = "On input $x$: ignore $x$; run $M$ on $w$; if $M$ accepts, accept."
  2. Run $R$ on $\langle M' \rangle$.
  3. If $R$ rejects (i.e., $L(M') \neq \emptyset$), accept. If $R$ accepts (i.e., $L(M') = \emptyset$), reject."

Correctness:

  • If $M$ accepts $w$: $M'$ accepts every input, so $L(M') = \Sigma^* \neq \emptyset$, so $R$ rejects, so $S$ accepts. ✓
  • If $M$ does not accept $w$: $M'$ accepts nothing, so $L(M') = \emptyset$, so $R$ accepts, so $S$ rejects. ✓

If $E_{TM}$ were decidable, $A_{TM}$ would be decidable — contradiction. $\square$

Key technique: The reduction constructs a new TM $M'$ on the fly based on the input. This is a common pattern — the reduction outputs an encoding of a machine, not just a string.

$EQ_{TM}$ — Equivalence Problem for TMs

$$EQ_{TM} = \{\langle M_1, M_2 \rangle \mid M_1 \text{ and } M_2 \text{ are TMs and } L(M_1) = L(M_2)\} $$

Theorem: $EQ_{TM}$ is undecidable.

Proof: Reduce from $E_{TM}$: let $M_2$ be a TM that immediately rejects all input (so $L(M_2) = \emptyset$). Then $\langle M_1, M_2 \rangle \in EQ_{TM}$ iff $L(M_1) = \emptyset$ iff $\langle M_1 \rangle \in E_{TM}$.

Rice's Theorem

Theorem (Rice's Theorem): For any non-trivial property of Turing-recognizable languages, the problem of deciding whether a given TM's language has that property is undecidable.

More precisely: a property is a set $P$ of Turing-recognizable languages. $P$ is non-trivial if $P \neq \emptyset$ and $P$ does not contain all Turing-recognizable languages. The language:

$$L_P = \{\langle M \rangle \mid L(M) \in P\} $$

is undecidable for any non-trivial $P$.

Examples of properties that are non-trivial (and thus undecidable):

  • "The language is empty" → $E_{TM}$
  • "The language contains the string $w$" → $A_{TM}$
  • "The language is finite"
  • "The language equals $\Sigma^*$"
  • "The language is regular"
  • "The language is a CFL"

Warning: Rice's theorem applies to properties of the language $L(M)$, not to properties of the machine $M$ itself. Properties like "M has more than 5 states" are decidable.

Not Turing-Recognizable Languages

$A_{TM}$ is undecidable but still Turing-recognizable. Are there languages that are not even Turing-recognizable?

Theorem: If both $A$ and $\overline{A}$ are Turing-recognizable, then $A$ is decidable.

Proof: Run the recognizers for $A$ and $\overline{A}$ in parallel (interleave steps). Since every string is in either $A$ or $\overline{A}$, one of the recognizers will eventually accept.

Corollary: $\overline{A_{TM}}$ is not Turing-recognizable.

Proof: $A_{TM}$ is Turing-recognizable. If $\overline{A_{TM}}$ were also Turing-recognizable, then $A_{TM}$ would be decidable (by the theorem above). But $A_{TM}$ is undecidable — contradiction. $\square$

Mapping Reductions and Recognizability

Theorem: If $A \leq_m B$ and $B$ is Turing-recognizable, then $A$ is Turing-recognizable.

Contrapositive: If $A$ is not Turing-recognizable and $A \leq_m B$, then $B$ is not Turing-recognizable.

To show $\overline{A_{TM}} \leq_m E_{TM}$:

Recall the reduction in the $E_{TM}$ proof: we showed $A_{TM} \leq_m \overline{E_{TM}}$. This means:

$$\overline{A_{TM}} \leq_m E_{TM} $$

Since $\overline{A_{TM}}$ is not Turing-recognizable, $E_{TM}$ is also not Turing-recognizable!

So $E_{TM}$ is not Turing-recognizable (even though $E_{TM}$ is the complement of something recognizable... actually that's $\overline{E_{TM}}$, which is Turing-recognizable by the reduction).

The big picture:

Turing's 1936 paper established the theoretical limits of computation — there are mathematical questions (like "does this program halt?") that no algorithm can answer, no matter how powerful the computer. This was a profound discovery: not all well-posed mathematical questions are mechanically solvable.

Connection to practice:

  • Static analysis tools for programs are always incomplete (by Rice's theorem)
  • Virus detection cannot be perfect in general
  • Program verification is undecidable in general
  • These limitations are not engineering failures — they are mathematical impossibilities

Proof strategies summary:

Goal Strategy
Show $L$ is decidable Describe an algorithm (TM pseudocode) that always halts
Show $L$ is Turing-recognizable Describe a TM that accepts $L$ (may loop)
Show $L$ is undecidable Reduce $A_{TM}$ to $L$ (assume $L$ is decidable, use it to decide $A_{TM}$)
Show $L$ is not Turing-recognizable Show $\overline{A_{TM}} \leq_m L$, or show $L \leq_m \overline{A_{TM}}$ and apply corollary
