Week 4 — Overview · Notes · Assignment

Extra Assignment — Decompressed Literature

Version 1.3 (May 7, 2023)

Time Estimate: 10–12 hours

Learning Outcomes

The purpose of this assignment is to:

  • Complete the Huffman algorithm by decoding what we have encoded.
  • Reading a binary file.
  • Parsing a string to reconstruct a list.
  • Decoding a binary message.

Overview

In the primary assignment this week you compressed War and Peace with Huffman's compression algorithm. The only way to recover the compressed text is to decompress it using Huffman's decompression algorithm. In this assignment we will complete this decompression task.

In this assignment you will implement Huffman's decoding algorithm by:

  • reading the file with the encoded text and the file with the codes
  • parsing the string in the codes file to rebuild the list of codes
  • decode the list of bytes:
    • search the list of codes for codes matching the code word
    • if found, add the matching character to the string
  • write the decompressed file

To complete this you will implement one public class and one private class:

  • HuffmanDecoder
    • CodeNode

Formal Specifications

HuffmanDecoder

#compressedFileName : String
#codesFileName : String
#outputFileName : String
#codesString : String
#encodedText: byte[]
#codes : MyOrderedList<CodeNode>
#book : String

+HuffmanDecoder()
#readFiles()
#buildCodes()
#getBit(pos : int) : String
#rebuildText()
#writeFile()

Field summary

  • compressedFileName — filename for the compressed input file
    • For testing default to "./WarAndPeace-compressed.bin".
  • codesFileName — filename for the codes input file
    • For testing should be set to "./WarAndPeace-codes.txt".
  • outputFileName — filename for the decompressed output file
    • For testing should be set to ".WarAndPeace-decompressed.txt".
  • codesString — The string of codes read in from the codes file.
  • encodedText — The encoded binary string read in from the compressed file.
  • codes — A list that stores the codes assigned to each character by the Huffman algorithm.
  • book — The uncompressed text of the book.

Method summary

  • HuffmanDecoder — The constructor should call the helper methods in the correct order to carry out Huffman's algorithm.
  • readFiles — This method reads in the files containing the compressed message and the codes.
    • It should output the time it takes to read the files.
  • buildCodes — This method builds the list of codes by parsing the String read in from the codes file.
    • You may call split on the string to separate the codes.
    • You should extract the character and the code from the string and create a CodeNode from them and insert it into the list.
    • It should output the time it takes to build the list of codes.
  • getBit — This is an optional method that extracts the bit in position pos from the byte array.
  • rebuildText — Uses bytes and codes to create the book.
    • Searches for the first prefix of the uncoded message that has a code in codes.
    • When found it adds the appropriate character to the book.
    • It should output the time it takes to decode the text.
  • writeFile() — Writes the contents of the book to the outputFileName.
    • It should output the time it takes to write the file.

CodeNode implements Comparable<CodeNode> (private inner class)

+character : Character
+code : String

+compareTo(other : CodeNode) : int
+toString() : String

Field summary

  • character — The character that this node stores the code for.
  • code — The code assigned to this character.

Method summary

  • compareTo — This method compares the nodes based on the code stored in them.

  • toString — This method returns the contents of the node in this format:

    character:code

Grading Rubric

In order to count as complete your submission must pass all JUnit tests. In order to do that:

  1. All class, field and method names must match these specifications exactly.
  2. All method signatures must match these specifications exactly.
  3. Your methods must function in the way specified and only in this way (do not perform extra functions).
  4. Your methods must be free of bugs.
  5. Get the numbers right: a. Output all original 3291642 (ASCII) or 3291623 (UTF-8) characters to the file.

If you are struggling to pass the tests, have bugs you can't find or error messages you don't understand then please reach out to me or your learning group.
