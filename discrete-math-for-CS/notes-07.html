The Sorting Problem

Before analyzing any sorting algorithm, it is worth being precise about what problem is being solved. This precision will matter when we write loop invariants: the invariants must ultimately guarantee that the algorithm satisfies the output specification exactly.

Input: A sequence of $n$ integers $\langle a_1, a_2, \ldots, a_n \rangle$.

Output: A permutation $\langle a'_1, a'_2, \ldots, a'_n \rangle$ of the input such that

$$a'_1 \leq a'_2 \leq \cdots \leq a'_n. $$

Two features of this specification deserve attention.

The word permutation carries significant mathematical weight. A permutation of a sequence is a reordering that contains all and only the original elements — no element is dropped, no element is duplicated, nothing new is inserted. Bundling both conditions into the single word "permutation" is a common move in formal mathematics: it lets us communicate two properties simultaneously without spelling them out every time.

The output condition $a'_1 \leq a'_2 \leq \cdots \leq a'_n$ specifies ascending (non-decreasing) order. Descending order would be a different problem specification, though not a fundamentally harder one: any algorithm for one direction can be adapted for the other.

Sorting is one of the most studied problems in computer science. It arises constantly in practice, algorithms for it were developed long before computers existed, and it serves as an excellent testbed for proof techniques — in particular, for loop invariant proofs (Week 3) and summation-based runtime analysis (Week 4). This week we apply both tools to two elementary sorting algorithms.

Bubble Sort — Algorithm

Bubble sort is designed around the most limited possible comparison model: the algorithm may examine only two adjacent elements at a time and decide whether to swap them. On any single pass through the array, the largest unsorted element "bubbles up" to its correct position at the end.

BubbleSort(A, n):
  for i = 1 to n - 1:
    for j = 1 to n - i:
      if A[j] > A[j + 1]:
        swap(A[j], A[j + 1])

Walking through the logic: the outer loop variable $i$ counts passes. On pass $i$, the inner loop scans index $j$ from $1$ to $n - i$, comparing each adjacent pair $(A[j], A[j+1])$ and swapping them if they are out of order. After the inner loop completes its first full pass (when $i = 1$), the largest element has been moved to position $n$. After the second pass, the second-largest is in position $n - 1$. In general, after pass $i$, the $i$ largest elements occupy positions $n - i + 1$ through $n$ in sorted order. The outer loop therefore needs only $n - 1$ passes: once $n - 1$ elements are correctly placed, the remaining element is automatically in its correct position.

Note that the inner loop bound shrinks with each pass. On pass $i$, there is no need to look beyond position $n - i$, because everything beyond that point is already sorted.

Bubble Sort — Loop Invariant and Correctness

Because bubble sort has two nested loops, it requires two loop invariants: one for the inner loop and one for the outer loop. The strategy is to prove the inner invariant first, then use it as a lemma inside the proof of the outer invariant, which in turn establishes correctness.

Inner Loop Invariant

Claim. After iteration $j$ of the inner loop (for a fixed value of $i$), $A[j+1]$ is the maximum element of $A[1], A[2], \ldots, A[j+1]$.

Informally: the inner loop is continually tracking the running maximum. Each time it compares $A[j]$ and $A[j+1]$ and potentially swaps, it ensures that the larger of the two ends up at position $j+1$. By the time $j$ reaches $n - i$, the maximum of the entire unsorted prefix has been moved to position $n - i + 1$.

Proof by induction on $j$.

Base case ($j = 0$, before the loop starts). Before any iteration, $j = 0$. The claim concerns $A[1]$, the sole element of the trivial sequence $\langle A[1] \rangle$. A sequence of one element has that element as its maximum. The invariant holds vacuously.

Inductive hypothesis. Assume that after iteration $j$, $A[j+1]$ is the maximum of $A[1], \ldots, A[j+1]$.

Inductive step. We show the invariant holds after iteration $j + 1$. On this iteration the algorithm compares $A[j+1]$ and $A[j+2]$.

  • If $A[j+1] \leq A[j+2]$: no swap occurs. Since $A[j+1]$ was already the maximum of $A[1], \ldots, A[j+1]$, and $A[j+2] \geq A[j+1]$, we have that $A[j+2]$ is the maximum of $A[1], \ldots, A[j+2]$.
  • If $A[j+1] > A[j+2]$: the algorithm swaps, placing the larger value at $A[j+2]$. The element now at $A[j+2]$ is the old $A[j+1]$, which was the maximum of $A[1], \ldots, A[j+1]$ and is larger than $A[j+2]$. So $A[j+2]$ is the maximum of $A[1], \ldots, A[j+2]$.

In both cases, after iteration $j + 1$, $A[j+2]$ is the maximum of $A[1], \ldots, A[j+2]$. By induction, the inner loop invariant holds for all $j$. $\square$

Termination of the inner loop. The inner loop runs from $j = 1$ to $j = n - i$. Applying the invariant at $j = n - i$: after the final iteration, $A[n-i+1]$ is the maximum of $A[1], \ldots, A[n-i+1]$.

Outer Loop Invariant

Claim. After iteration $i$ of the outer loop, the $i$ largest elements of $A$ are in non-decreasing order in positions $n - i + 1$ through $n$.

Proof by induction on $i$.

Base case ($i = 0$, before the loop starts). Zero elements are in their correct positions, which is vacuously true.

Inductive hypothesis. Assume that after iteration $i$, the $i$ largest elements of $A$ occupy positions $n - i + 1$ through $n$ in sorted order.

Inductive step. We show the claim holds after iteration $i + 1$. By the inductive hypothesis, positions $n - i + 1$ through $n$ are correctly sorted. On iteration $i + 1$, the inner loop runs over positions $1$ through $n - (i+1) = n - i - 1$, examining only the unsorted prefix $A[1], \ldots, A[n-i]$. By the inner loop invariant (applied at its termination), after the inner loop completes, $A[n-i]$ contains the maximum of $A[1], \ldots, A[n-i]$. Since $A[n-i]$ is the maximum of the unsorted prefix, and all larger elements already reside in positions $n - i + 1$ through $n$, we conclude that $A[n-i]$ is the $(i+1)$-th largest element of the full array, now correctly placed. The elements in positions $n - i + 1$ through $n$ are undisturbed. Therefore the $i + 1$ largest elements are in sorted order in positions $n - i$ through $n$. By induction, the outer loop invariant holds for all $i$. $\square$

Proof of Correctness

Let $A = \langle a_1, \ldots, a_n \rangle$ be an arbitrary input sequence of $n$ integers. The outer loop runs for $i = 1$ to $n - 1$. Applying the outer loop invariant at $i = n - 1$: after iteration $n - 1$, the $n - 1$ largest elements are in sorted order in positions $2$ through $n$. The single remaining element at position $1$ must therefore be the smallest element of the array, which is also in its correct position. The entire array is sorted in non-decreasing order, constituting a valid permutation of the input. Therefore BubbleSort is correct. $\square$

Bubble Sort — Runtime Analysis

We count the total number of primitive operations executed by BubbleSort on an input of size $n$, using a line-by-line analysis.

Line-by-Line Operation Count

Code element Operations per execution Notes
Method entry $1$ One-time overhead
Outer for header (each execution) $3$ Initialize/increment $i$; compute $n-1$; compare
Inner for header (each execution) $3$ Initialize/increment $j$; compute $n-i$; compare
Body: comparison $A[j] > A[j+1]$ $1$ One comparison; plus index arithmetic
Body: swap and index offsets treated as $3$ total with comparison Swap counted as one constant-cost call
Total per inner loop body execution $7$ Combined comparison + swap lines
Exit inner loop $3$ Final increment, subtract, compare-to-exit
Exit outer loop $3$ Final increment, subtract, compare-to-exit
Return $1$

Setting Up the Summation

Gathering constant terms from method entry and exits gives a leading constant of $5$. The outer loop runs for $i = 1$ to $n - 1$; inside each outer iteration, entering the inner loop costs $3$ operations (initialization), the inner loop body runs for $j = 1$ to $n - i$, and exiting the inner loop costs $3$ more operations. Combining loop-entry and loop-exit constants within the outer sum gives $6$ per outer iteration (plus the inner body). This yields:

$$f(n) = 5 + \sum_{i=1}^{n-1} \left[ 6 + \sum_{j=1}^{n-i} 7 \right] $$

Evaluating the Inner Sum

Since $7$ does not depend on $j$:

$$\sum_{j=1}^{n-i} 7 = 7(n - i) $$

Substituting:

$$f(n) = 5 + \sum_{i=1}^{n-1} \left[ 6 + 7(n-i) \right] = 5 + \sum_{i=1}^{n-1} \left[ 6 + 7n - 7i \right] $$

Distributing the Outer Sum

Split the outer summation over its three terms:

$$f(n) = 5 + \sum_{i=1}^{n-1} 6 + 7n\sum_{i=1}^{n-1} 1 - 7\sum_{i=1}^{n-1} i $$

Term 1: $\displaystyle\sum_{i=1}^{n-1} 6 = 6(n-1)$

Term 2: $\displaystyle 7n \sum_{i=1}^{n-1} 1 = 7n(n-1)$

Term 3 — arithmetic series: Recall from Week 4 that $\displaystyle\sum_{i=1}^{n} i = \frac{n(n+1)}{2}$. With upper limit $n - 1$ the formula becomes $\displaystyle\sum_{i=1}^{n-1} i = \frac{(n-1)n}{2}$. Therefore:

$$7\sum_{i=1}^{n-1} i = \frac{7n(n-1)}{2} $$

Combining Terms

$$f(n) = 5 + 6(n-1) + 7n(n-1) - \frac{7n(n-1)}{2} $$ $$= 5 + 6n - 6 + 7n^2 - 7n - \frac{7n^2 - 7n}{2} $$ $$= 7n^2 - \frac{7n^2}{2} + 6n - 7n + \frac{7n}{2} - 1 $$ $$= \frac{7}{2}n^2 + \frac{5}{2}n - 1 $$

Confirming the $\Theta$ Classification

Apply the limit definition from Week 6:

$$\lim_{n \to \infty} \frac{f(n)}{n^2} = \lim_{n \to \infty} \frac{\frac{7}{2}n^2 + \frac{5}{2}n - 1}{n^2} = \frac{7}{2} + \frac{5}{2n} - \frac{1}{n^2} \;\longrightarrow\; \frac{7}{2} $$

The limit is a finite nonzero constant, so by the limit theorem:

$$f(n) \in \Theta(n^2) $$

A note on constants. The precise constant $\frac{7}{2}$ depends on how we count the swap operation. If the swap takes $c$ operations instead of being absorbed into the constant $7$, the leading coefficient becomes $\frac{c}{2}$ instead of $\frac{7}{2}$. The asymptotic class $\Theta(n^2)$ is unaffected regardless of the value of $c$.

Selection Sort — Algorithm

Selection sort is often described as the most natural algorithm for a human sorting a hand of cards: scan the unsorted portion of the list, find the minimum element, and move it into its correct position. Repeat until the list is sorted.

SelectionSort(A, n):
  for i = 1 to n - 1:
    m = i
    for j = i + 1 to n:
      if A[j] < A[m]:
        m = j
    swap(A[i], A[m])

The variable $m$ tracks the index of the minimum element seen so far within the current subarray. On each iteration $i$ of the outer loop:

  1. Initialize $m \leftarrow i$ (tentative minimum is the first element of the unsorted portion).
  2. Scan $j = i + 1$ to $n$; whenever $A[j] < A[m]$, update $m \leftarrow j$.
  3. After the inner loop, $A[m]$ is the minimum of $A[i], \ldots, A[n]$. Swap it into position $i$.

After the first outer iteration, the global minimum is in position $1$. After the second, the second-smallest is in position $2$. After $n - 1$ iterations, the $n - 1$ smallest elements are correctly placed, and the largest element is necessarily in position $n$.

Notice the contrast with bubble sort. Bubble sort performs many swaps (potentially one per inner iteration); selection sort performs exactly one swap per outer iteration, for a total of at most $n - 1$ swaps. The number of comparisons, however, is the same order for both.

Selection Sort — Loop Invariant and Correctness

As with bubble sort, the nested loop structure requires two loop invariants.

Inner Loop Invariant

Claim. After iteration $j$ of the inner loop (for a fixed outer index $i$), $m$ is the index of the minimum element of $A[i], A[i+1], \ldots, A[j]$.

This is essentially the minimum-finding algorithm from an earlier week, modified to track the index rather than the value, and starting from position $i$ rather than position $1$.

Proof by induction on $j$.

Base case ($j = i$, before the inner loop starts). The inner loop initializes $m \leftarrow i$ just before it begins. The sequence $\langle A[i] \rangle$ has a single element; $m = i$ is trivially the index of its minimum. The invariant holds.

Inductive hypothesis. Assume that after iteration $j$, $m$ is the index of the minimum of $A[i], \ldots, A[j]$.

Inductive step. On iteration $j + 1$, the algorithm compares $A[j+1]$ with $A[m]$.

  • If $A[j+1] \geq A[m]$: no update to $m$. Since $A[m]$ was already $\leq$ all elements in $A[i], \ldots, A[j]$, and $A[m] \leq A[j+1]$, we have that $A[m]$ is still the minimum of $A[i], \ldots, A[j+1]$, and $m$ remains its index.
  • If $A[j+1] < A[m]$: the algorithm sets $m \leftarrow j+1$. Since $A[j+1] < A[m] \leq A[k]$ for all $k \in \{i, \ldots, j\}$ (by inductive hypothesis), $A[j+1]$ is less than every element in $A[i], \ldots, A[j]$, and it is trivially less than itself. So $m = j + 1$ is the index of the minimum of $A[i], \ldots, A[j+1]$.

In both cases the invariant holds after iteration $j + 1$. By induction, the inner loop invariant holds for all $j \geq i$. $\square$

Termination of the inner loop. The inner loop runs from $j = i + 1$ to $j = n$. Applying the invariant at termination ($j = n$): $m$ is the index of the minimum of $A[i], \ldots, A[n]$.

Outer Loop Invariant

Claim. After iteration $i$ of the outer loop, the $i$ minimum elements of $A$ are in non-decreasing order in positions $1$ through $i$.

Proof by induction on $i$.

Base case ($i = 0$, before the loop starts). Zero elements are in sorted positions, which is vacuously true.

Inductive hypothesis. Assume that after iteration $i$, the $i$ minimum elements of $A$ are in non-decreasing order in positions $1$ through $i$.

Inductive step. We show the claim after iteration $i + 1$. By the inductive hypothesis, $A[1], \ldots, A[i]$ contains the $i$ smallest elements in sorted order. These positions are not touched during iteration $i + 1$ (the inner loop scans from $i + 2$ onward, and the swap involves only positions $i + 1$ and $m$). By the inner loop invariant at termination, after the inner loop completes, $m$ is the index of the minimum of $A[i+1], \ldots, A[n]$. Because the $i$ smallest elements are already in positions $1$ through $i$, the minimum of $A[i+1], \ldots, A[n]$ is the $(i+1)$-th smallest element of the entire array. The algorithm swaps $A[i+1]$ and $A[m]$, placing this element at position $i+1$. Since $A[1] \leq A[2] \leq \cdots \leq A[i] \leq A[i+1]$ (the element placed is at least as large as all previous), the $i + 1$ minimum elements are now in non-decreasing order in positions $1$ through $i + 1$. By induction, the outer loop invariant holds for all $i$. $\square$

Proof of Correctness

Let $A = \langle a_1, \ldots, a_n \rangle$ be an arbitrary input. The outer loop runs from $i = 1$ to $n - 1$. Applying the outer loop invariant at $i = n - 1$: after $n - 1$ iterations, the $n - 1$ smallest elements are in sorted order in positions $1$ through $n - 1$. The element remaining at position $n$ is the largest element of $A$ and therefore belongs there. The full array $A[1], \ldots, A[n]$ is in non-decreasing order and is a permutation of the original input. Therefore SelectionSort is correct. $\square$

Selection Sort — Runtime Analysis

We apply the same line-by-line strategy used for bubble sort.

Line-by-Line Operation Count

Code element Operations per execution
Method entry $1$
Outer for header $3$ (initialize/increment; compute $n-1$; compare)
Assignment $m = i$ $1$
Inner for header $3$ (initialize/increment; compute $n$; compare)
Inner body: comparison + conditional assignment $4$ (worst case: comparison plus update $m$)
Exit inner loop $2$
Swap $A[i]$ and $A[m]$ $1$ (constant-cost call)
Exit outer loop $3$
Return $1$

Setting Up the Summation

Combining constants outside the loops gives a fixed overhead of $5$. Inside the outer loop (but outside the inner loop): entering the inner loop and the assignment $m = i$ account for $5$ operations per outer iteration. Inside the inner loop, $4$ operations per body execution. Exiting the inner loop costs $2$ additional operations. After the inner loop, the swap costs $1$ operation. Combining the loop-boundary terms ($5$ for entry, $3$ for exit, $1$ for swap) into a single constant $8$ per outer iteration gives:

$$f(n) = 5 + \sum_{i=1}^{n-1} \left[ 8 + \sum_{j=i+1}^{n} 4 \right] $$

Evaluating the Inner Sum

The inner sum runs from $j = i + 1$ to $j = n$. Using the formula $\displaystyle\sum_{j=a}^{b} 1 = b - a + 1$:

$$\sum_{j=i+1}^{n} 4 = 4(n - i - 1 + 1) = 4(n - i) $$

Substituting:

$$f(n) = 5 + \sum_{i=1}^{n-1} \left[ 8 + 4(n - i) \right] = 5 + \sum_{i=1}^{n-1} \left[ 8 + 4n - 4i \right] $$

Distributing the Outer Sum

$$f(n) = 5 + \sum_{i=1}^{n-1} 8 + 4n\sum_{i=1}^{n-1} 1 - 4\sum_{i=1}^{n-1} i $$

Term 1: $\displaystyle\sum_{i=1}^{n-1} 8 = 8(n-1)$

Term 2: $\displaystyle 4n(n-1)$

Term 3 — arithmetic series: $\displaystyle 4 \cdot \frac{(n-1)n}{2} = 2n(n-1)$

Combining Terms

$$f(n) = 5 + 8(n-1) + 4n(n-1) - 2n(n-1) $$ $$= 5 + 8n - 8 + 4n^2 - 4n - 2n^2 + 2n $$ $$= 2n^2 + 6n - 3 $$

Confirming the $\Theta$ Classification

$$\lim_{n \to \infty} \frac{f(n)}{n^2} = \lim_{n \to \infty} \frac{2n^2 + 6n - 3}{n^2} = 2 + \frac{6}{n} - \frac{3}{n^2} \;\longrightarrow\; 2 $$

The limit is $2$, a finite nonzero constant. Therefore:

$$f(n) \in \Theta(n^2) $$

The leading coefficient $2$ reflects that each outer iteration performs a constant-cost inner-loop body on $n - i$ elements. The coefficient would change if the swap or comparison were counted differently, but the asymptotic class would not.

Comparing the Two Algorithms

Both bubble sort and selection sort have the same asymptotic runtime: $\Theta(n^2)$. This means that for large inputs, neither algorithm is fundamentally faster than the other in the sense of big-theta growth. Several practical distinctions are worth noting.

Number of Comparisons

Both algorithms perform $\Theta(n^2)$ comparisons. In bubble sort, the inner loop runs from $j = 1$ to $n - i$, giving a total of $\displaystyle\sum_{i=1}^{n-1}(n-i) = \frac{n(n-1)}{2}$ comparisons. In selection sort, the inner loop runs from $j = i + 1$ to $n$, giving $\displaystyle\sum_{i=1}^{n-1}(n - i) = \frac{n(n-1)}{2}$ comparisons — the same count. The number of comparisons is identical.

Number of Swaps

This is where the algorithms differ most concretely. Bubble sort may perform a swap on every single inner-loop iteration, for up to $\frac{n(n-1)}{2}$ swaps in the worst case (a reverse-sorted input). Selection sort performs exactly one swap per outer iteration, for exactly $n - 1$ swaps regardless of input order. If swaps are expensive (for example, when elements are large records rather than integers), selection sort has a clear practical advantage.

Constants in the Runtime Functions

From our analyses:

  • Bubble sort: $f(n) = \frac{7}{2}n^2 + \frac{5}{2}n - 1$
  • Selection sort: $f(n) = 2n^2 + 6n - 3$

The leading coefficient for selection sort ($2$) is smaller than for bubble sort ($\frac{7}{2}$), largely because selection sort avoids the redundant swaps inside the inner loop. Both are $\Theta(n^2)$, so this difference disappears asymptotically, but it is real and measurable for fixed $n$.

Best-Case Behavior

Bubble sort has an interesting best-case property that selection sort lacks. On an already-sorted input, bubble sort can be modified with an early-exit flag to terminate after a single pass with zero swaps — giving $\Theta(n)$ best-case behavior. As written here, our version does not include this optimization and remains $\Theta(n^2)$ in all cases. Selection sort always performs the same number of comparisons regardless of input order: there is no early exit possible, so its best and worst cases are both $\Theta(n^2)$.

Stability

A sorting algorithm is stable if elements with equal keys maintain their original relative order after sorting. Bubble sort, as written, is stable: equal elements are never swapped (the comparison uses strict inequality $>$), so ties preserve their original order. Selection sort as written is not stable: the swap at the end of each outer iteration can move an element past an equal element, disrupting relative order.
