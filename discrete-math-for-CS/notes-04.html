Counting Operations

Having established that an algorithm is correct, the next natural question is: how expensive is it? Expense is measured by counting the operations an algorithm performs as a function of its input size $n$.

What counts as an operation?

The answer depends on the resolution of the analysis — roughly, how much detail you want to track.

  • Fine resolution: count every bit flip (relevant when analyzing, say, a multiplication algorithm at the hardware level).
  • Mid-level resolution: count each arithmetic operation, comparison, assignment, method call, and output statement as one step — but do not descend into the individual bits. This is the resolution most commonly used when analyzing algorithms written in a language like Java or JavaScript.
  • Coarse resolution: count only one distinguished operation (for example, only assignments, or only network requests). Useful when one operation dominates and all others are negligible by comparison.

Common operations counted at mid-level resolution:

Operation Examples
Assignment m = a[0]
Comparison i <= n, a[i] < m
Arithmetic / logical operator i + 1, x && y
Method call / return entering a procedure, return m

Runtime functions

Because cost depends on input size, we express it as a runtime function $f : \mathbb{N} \to \mathbb{N}$, where the input is the size $n$ of the problem instance and the output is the number of operations. Two practical requirements follow from this interpretation:

  1. Non-negativity: $f(n) \geq 0$ for all $n$. Negative operation counts are meaningless.
  2. Non-decreasing: $f(n) \leq f(n+1)$ for all $n$. Larger inputs should not require fewer operations.

These two properties rule out trigonometric functions (which oscillate) and other functions ill-suited to representing algorithmic cost. The functions that naturally arise are polynomials, logarithms, and exponentials.

Best case, worst case, average case

Consider the minimum algorithm, which scans a list $a[1..n]$ and maintains a running minimum:

MinAlg(a, n):
  m = a[1]
  for i = 2 to n:
    if a[i] < m:
      m = a[i]
  return m

Inside the loop, the comparison a[i] < m always executes, but the assignment m = a[i] executes only when a new minimum is found. This creates two distinguishable scenarios:

  • Best case: the list is already in non-decreasing order. The assignment inside the if body never executes; only the comparison runs each iteration.
  • Worst case: the list is in strictly decreasing order. Every element sets a new minimum; both the comparison and the assignment execute every iteration.

In formal analysis we almost always focus on the worst case: it provides a guaranteed upper bound on cost regardless of input, and planning for the worst is more informative than planning for the best.

Counting assignments in MinAlg (worst case)

Counting only assignments at coarse resolution:

  • Before the loop: 1 assignment (m = a[1]).
  • Inside the loop: in the worst case, one assignment per iteration. The loop runs from $i = 2$ to $i = n$, giving $n - 1$ iterations.
  • Total: $1 + (n - 1) = n$ assignments.

Wait — there is also the loop-setup assignment i = 2, making the total $n + 1$ assignments in the worst case. This is the runtime function $f(n) = n + 1$ under the "count only assignments" analysis.

Setting Up Summations

Counting only assignments glosses over many real operations. For a finer analysis, we use summation notation to express the total cost of a loop precisely.

Translating a loop into a sum

The key insight: a for loop with index $i$ running from $a$ to $b$ and performing some work per iteration corresponds directly to a summation

$$\sum_{i=a}^{b} (\text{work on iteration } i). $$

For MinAlg, each full iteration of the loop body — including the loop overhead (the increment i++ and the comparison i <= n) and the worst-case body (the comparison a[i] < m plus the assignment m = a[i]) — costs exactly 4 operations. The loop runs from $i = 2$ to $i = n$.

Three chunks of analysis:

  1. Before the loop: method call + initial assignment = 2 operations.
  2. The loop body (iterated): $\displaystyle\sum_{i=2}^{n} 4$
  3. Loop exit: one final increment + one final comparison + one return = 3 operations.

Combining:

$$f(n) = 2 + \sum_{i=2}^{n} 4 + 3 = 5 + \sum_{i=2}^{n} 4. $$

Since 4 does not depend on $i$, it factors out of the sum:

$$f(n) = 5 + 4\sum_{i=2}^{n} 1. $$

Applying the change-of-index rule (subtracting 1 from both bounds, valid because the summand has no $i$):

$$\sum_{i=2}^{n} 1 = \sum_{i=1}^{n-1} 1 = n - 1. $$

Therefore:

$$f(n) = 5 + 4(n-1) = 4n + 1. $$

This is the total operation count for MinAlg in the worst case under a mid-level analysis. The earlier coarse analysis gave $n + 1$ (assignments only); now we see there are roughly four times as many operations total, which means about one-quarter of all operations are assignments.

Index change rule

When the summand does not contain $i$, shifting both the lower and upper bounds by the same constant leaves the sum unchanged:

$$\sum_{i=a}^{b} c = \sum_{i=a-k}^{b-k} c \quad \text{for any constant } k. $$

When the summand does contain $i$, every occurrence of $i$ in the term must be compensated:

$$\sum_{i=a}^{b} i = \sum_{i=a-k}^{b-k} (i + k). $$

Counting from $i = 1$ to $n$

The sequential search algorithm (scan a list for a target) has its loop running from $i = 1$ to $n$, giving:

$$g(n) = 5 + \sum_{i=1}^{n} 4 = 5 + 4n. $$

Notice the difference from MinAlg: the loop here starts at 1 rather than 2, so it has $n$ iterations instead of $n-1$, and the runtime is $4n + 5$ rather than $4n + 1$.

A third algorithm (string equality checking) has two extra operations before the loop, yielding $4n + 7$.

All three functions — $4n + 1$, $4n + 5$, $4n + 7$ — are linear functions. As $n$ grows large the constant offsets become negligible; at $n = 1000$ they differ by less than 1%. This observation motivates the Big-Oh notation introduced in Week 6.

Distributive rule for sums

Any constant $d$ that does not depend on the summation index can be factored out:

$$\sum_{i=1}^{n} d \cdot a_i = d \cdot \sum_{i=1}^{n} a_i. $$

This is the distributive law applied to sigma notation, and it is the most frequently used simplification tool when working with summations.

Common Summations and Closed Forms

A closed form is a formula that evaluates a sum without actually performing each addition.

Sum of constants

$$\sum_{i=1}^{n} 1 = n. $$

Proof sketch: expanding the summation gives $1 + 1 + \cdots + 1$ ($n$ times), which equals $n$.

General range of constants

$$\sum_{i=a}^{b} 1 = b - a + 1. $$

The $+1$ accounts for including both endpoints. A common error is to write $b - a$, forgetting the lower endpoint itself.

Gauss's sum (arithmetic series)

$$\sum_{i=1}^{n} i = \frac{n(n+1)}{2}. $$

This sum arises whenever a loop's cost grows with each iteration — for example, if each pass through a loop processes one more element than the last. Three proofs appear in the lecture:

1. Proof by induction (covered in the next section).

2. Gauss's pairing argument. Write the sum twice — once forward, once backward — and add them term by term:

$$\begin{aligned} S &= 1 + 2 + 3 + \cdots + (n-1) + n \\ S &= n + (n-1) + (n-2) + \cdots + 2 + 1 \\ 2S &= (n+1) + (n+1) + \cdots + (n+1) \quad (n \text{ pairs}) \end{aligned}$$

Each pair sums to $n+1$, and there are $n$ pairs, so $2S = n(n+1)$, giving $S = \dfrac{n(n+1)}{2}$.

3. Geometric proof. Represent the sum as a staircase of unit squares with rows of height $1, 2, \ldots, n$. Rotate a copy of the staircase $180°$ and fit it against the original to form an $n \times (n+1)$ rectangle of area $n(n+1)$. Since the rectangle contains two copies of the original staircase, the staircase has area $\dfrac{n(n+1)}{2}$.

Geometric series

$$\sum_{i=0}^{n} 2^i = 2^{n+1} - 1. $$

More generally, for any base $r \neq 1$:

$$\sum_{i=0}^{n} r^i = \frac{r^{n+1} - 1}{r - 1}. $$

The powers-of-two case is central to computer science. An elegant way to remember the formula: in binary, the number $\underbrace{11\cdots1}_{n+1 \text{ ones}}$ equals $\sum_{i=0}^{n} 2^i$. Adding 1 to this binary number produces $1\underbrace{00\cdots0}_{n+1 \text{ zeros}} = 2^{n+1}$, so the original number must be $2^{n+1} - 1$.

Proof by Induction

Mathematical induction is a proof technique for statements of the form "property $P(n)$ holds for all $n \geq n_0$." It consists of two steps:

  1. Base case: prove $P(n_0)$ directly.
  2. Inductive step: assume $P(n)$ holds for some arbitrary $n \geq n_0$ (the inductive hypothesis) and prove $P(n+1)$.

Once both steps are established, $P(n)$ holds for all integers $n \geq n_0$ by the well-ordering principle.

Proving Gauss's sum by induction

Theorem. For all $n \in \mathbb{N}$,

$$\sum_{i=1}^{n} i = \frac{n(n+1)}{2}. $$

Proof.

Base case ($n = 1$): The left side is $1$. The right side is $\dfrac{1 \cdot 2}{2} = 1$. They are equal. $\checkmark$

Inductive step: Assume $\displaystyle\sum_{i=1}^{n} i = \dfrac{n(n+1)}{2}$ for some $n \geq 1$. We must show

$$\sum_{i=1}^{n+1} i = \frac{(n+1)(n+2)}{2}. $$

Starting from the left side, peel off the last term:

$$\sum_{i=1}^{n+1} i = \left(\sum_{i=1}^{n} i\right) + (n+1). $$

Apply the inductive hypothesis to the remaining sum:

$$= \frac{n(n+1)}{2} + (n+1). $$

Factor out $(n+1)$:

$$= (n+1)\left(\frac{n}{2} + 1\right) = (n+1) \cdot \frac{n+2}{2} = \frac{(n+1)(n+2)}{2}. $$

This is exactly the right side with $n$ replaced by $n+1$. The inductive step is complete.

By induction, the formula holds for all $n \geq 1$. $\blacksquare$

Proving the geometric series by induction

Theorem. For all $n \in \mathbb{N}_0$,

$$\sum_{i=0}^{n} 2^i = 2^{n+1} - 1. $$

Proof.

Base case ($n = 0$): The left side is $2^0 = 1$. The right side is $2^1 - 1 = 1$. Equal. $\checkmark$

Inductive step: Assume $\displaystyle\sum_{i=0}^{n} 2^i = 2^{n+1} - 1$. We must show

$$\sum_{i=0}^{n+1} 2^i = 2^{n+2} - 1. $$

Peel off the last term:

$$\sum_{i=0}^{n+1} 2^i = \left(\sum_{i=0}^{n} 2^i\right) + 2^{n+1}. $$

Apply the inductive hypothesis:

$$= (2^{n+1} - 1) + 2^{n+1} = 2 \cdot 2^{n+1} - 1 = 2^{n+2} - 1. $$

The inductive step is complete. By induction, the formula holds for all $n \geq 0$. $\blacksquare$

The structure of an inductive proof

The mechanical pattern is always the same:

  1. Write down what you need to prove for $n+1$ (substitute $n+1$ everywhere $n$ appears in $P(n)$).
  2. Start from the left side of the $n+1$ claim.
  3. Rewrite the expression so that the $n$-case sum appears as a sub-expression.
  4. Replace that sub-sum with its closed form using the inductive hypothesis.
  5. Use algebra to arrive at the right side of the $n+1$ claim.

Step 3 — "peeling off the last term" — is the key move in almost every summation proof by induction.

A note on elegance

Induction proofs are powerful but mechanical. Gauss's pairing argument and the geometric picture proof are often considered more elegant because they reveal why the formula is true, not merely that it is true. In mathematics, elegance typically means: correct, concise, clear, and illuminating. The inductive proof satisfies all of these except possibly the last.

Predicate Logic

Up to this point, propositions have been treated as indivisible atoms labeled $P$, $Q$, $R$, and so on. Predicate logic breaks a proposition into its grammatical components — subject and predicate — and introduces quantifiers to make statements about entire collections of objects.

Predicates

A predicate is a property that an object may or may not have. It is a proposition with a free variable — a sentence that becomes true or false once the variable is assigned a value.

Notation: $P(x)$ denotes the predicate $P$ applied to subject $x$.

Example. Let $W(x)$ denote "$x$ is white."

  • $W(\text{snow})$ is true.
  • $W(\text{grass})$ is false.
  • $W(5)$ is false (the number 5 has no color; the predicate does not apply, so by convention the result is false).

A predicate can take more than one argument. $T(x, y)$ might mean "$x$ is taller than $y$", which takes a truth value only once both $x$ and $y$ are specified.

Domain of discourse

The domain of discourse (sometimes called the universe) is the set of objects over which variables range. Restricting the domain changes the meaning of quantified statements. The domain should always be clear from context; in mathematics it is often $\mathbb{Z}$, $\mathbb{N}$, or $\mathbb{R}$.

The universal quantifier $\forall$

The symbol $\forall$ (an upside-down A, for "all") is the universal quantifier. The statement

$$\forall x\, P(x) $$

asserts that $P(x)$ is true for every element $x$ in the domain.

Example. With domain $\mathbb{Z}$ and $O(n)$ meaning "$n$ is odd":

$$\forall n \in \mathbb{Z},\; O(n) \leftrightarrow O(n^2) $$

asserts that an integer is odd if and only if its square is odd — a true statement (it follows from closure of odd integers under multiplication).

Most universal claims we make in mathematics are implicitly universally quantified. "Even numbers are divisible by 2" means "for all even numbers $n$, $n$ is divisible by 2." The quantifier is present even when not written.

The existential quantifier $\exists$

The symbol $\exists$ (a backwards E, for "exists") is the existential quantifier. The statement

$$\exists x\, P(x) $$

asserts that there is at least one element $x$ in the domain for which $P(x)$ is true.

Example. "$\exists n \in \mathbb{Z},\; n + 4 = 0$" is true: the witness is $n = -4$.

To prove an existential statement, it suffices to exhibit a single example. This is called an existence proof or constructive proof. When a property is rare — say, one example among infinitely many candidates — finding that example can be hard. Algebra is essentially the discipline of systematically finding the $x$ that satisfies an existential claim.

Negating quantified statements

Negation pushes through a quantifier, but flips its type:

$$\neg\, \forall x\, P(x) \;\equiv\; \exists x\, \neg P(x) $$ $$\neg\, \exists x\, P(x) \;\equiv\; \forall x\, \neg P(x) $$

Intuition for the first rule: if it is not the case that all things satisfy $P$, then there must be some thing that does not satisfy $P$.

Intuition for the second rule: if nothing satisfies $P$, then everything fails to satisfy $P$.

Example: "There is no largest integer."

Starting from the false positive claim and then negating it:

$$\exists n \in \mathbb{Z},\; \forall m \in \mathbb{Z},\; n \geq m \qquad (\text{false: ``there is a largest integer''}) $$

Negate and push the $\neg$ inward, flipping each quantifier in turn:

$$\neg\left(\exists n \in \mathbb{Z},\; \forall m \in \mathbb{Z},\; n \geq m\right) $$ $$\equiv\; \forall n \in \mathbb{Z},\; \neg\left(\forall m \in \mathbb{Z},\; n \geq m\right) $$ $$\equiv\; \forall n \in \mathbb{Z},\; \exists m \in \mathbb{Z},\; n < m. $$

The final form says: for every integer $n$, there exists an integer $m$ that is greater than $n$ — equivalently, there is always a bigger integer. This is the positive, quantifier-free-looking assertion that is logically equivalent to "there is no largest integer."

Nested quantifiers and order

When all quantifiers are of the same type, their order does not matter:

$$\forall x\, \forall y\, P(x, y) \;\equiv\; \forall y\, \forall x\, P(x, y). $$

When quantifiers are of different types, their order is critical:

  • $\exists n \in \mathbb{Z},\; \forall m \in \mathbb{Z},\; n \leq m$ — "there is a smallest integer" — is false.
  • $\forall n \in \mathbb{Z},\; \exists m \in \mathbb{Z},\; n \leq m$ — "every integer has one that is at least as large" — is true (take $m = n$, or $m = n + 1$, and so on).

Swapping the quantifiers turned a true statement into a false one. Do not permute mixed quantifiers without careful verification.
