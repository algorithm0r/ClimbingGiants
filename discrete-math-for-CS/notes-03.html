Problems and Algorithms

Sequences and Strings

Before defining computational problems formally, we need the mathematical objects that appear as inputs and outputs. A sequence is an ordered set — unlike an ordinary set, order matters and duplicate elements are permitted. A sequence of $n$ elements is written $(a_1, a_2, \ldots, a_n)$; a sequence of length zero is the empty sequence.

A string is a sequence of characters drawn from some fixed set called an alphabet, conventionally denoted $\Sigma$. The empty string is written $\varepsilon$. Strings appear wherever we process text, gene sequences, binary data, or any other symbol-by-symbol encoding, and they will be the inputs to several of the algorithms in this week's videos.

Computational Problems

A computational problem (or information processing problem) is a relationship between a set of valid inputs and a set of expected outputs. Crucially, a problem specifies what must be produced given a particular input — not how to produce it. Formally, a problem consists of:

  • an input condition describing the form and constraints of a valid input, and
  • an output specification describing the required result for each valid input.

Example — the Minimum Problem.

Input: A sequence of integers $A = (a_1, a_2, \ldots, a_n)$ with $n \geq 1$.

Output: An element $a_i \in A$ such that $a_i \leq a_j$ for all $j$ with $1 \leq j \leq n$.

The output condition uses $\leq$ rather than $<$ so that the specification is valid even when all elements are equal — any element of a constant sequence satisfies the condition and is an acceptable answer.

Algorithms

An algorithm is a finite sequence of information processing steps that transforms a valid input into the correct output for a given problem. An algorithm solves a problem if, for every valid input, it produces an output satisfying the problem's output specification.

Several important distinctions:

  • A problem can have multiple correct algorithms. Different strategies may all produce correct outputs; among equally correct and equally efficient algorithms, the one that is easiest to read, implement, and reason about is generally preferred.
  • An algorithm is not the same as a program. An algorithm is described at an abstract level, independent of any programming language. Pseudocode — a mix of natural language and code-like constructs — is the conventional medium for communicating algorithms to human readers without imposing implementation details.
  • Correctness is logically prior to efficiency. An incorrect algorithm is useless regardless of how fast it runs; analysis of efficiency only makes sense once correctness is established.

Two fundamental questions guide the study of algorithms:

  1. Is the algorithm correct? Does it produce the right output for every valid input?
  2. Is the algorithm efficient? How many operations does it perform as a function of the input size?

This week focuses entirely on question 1. Week 4 takes up question 2.

Loop Invariants

Most algorithms of practical interest contain loops. Proving a loop-based algorithm correct requires a tool that can reason about all possible executions of the loop, not just a handful of examples. That tool is the loop invariant.

Definition

A loop invariant is a predicate $P(i)$ about the program's variables that satisfies three conditions:

  • Initialization: $P(0)$ is true before the first iteration of the loop (i.e., after the initialization code but before the loop body executes).
  • Maintenance: For every $i \geq 0$, if $P(i)$ is true before iteration $i+1$, then $P(i+1)$ is true after iteration $i+1$ completes.
  • Termination: When the loop exits after iteration $n$, $P(n)$ together with the loop's termination condition implies that the algorithm has produced the correct output.

This structure is a proof by mathematical induction: Initialization provides the base case; Maintenance provides the inductive step; Termination extracts the desired correctness conclusion from the invariant at the end of the loop.

Choosing a Useful Invariant

Many predicates are technically invariant — "the sky is blue" remains true after every loop iteration — but most are useless. A useful loop invariant captures a running summary of what the algorithm has accomplished so far. The phrase "so far" is a reliable indicator: an invariant typically says something like "after $i$ iterations, variable $m$ correctly represents the minimum of the first $i$ elements examined." Identifying the right invariant is the creative step in a correctness proof; everything else is proof machinery.

Finding the Minimum

Pseudocode

Minimum(A = (a_1, ..., a_n)):
    m = a_1
    for i = 2 to n do
        if a_i < m then
            m = a_i
    return m

The variable $m$ tracks the minimum element seen so far. It is initialized to $a_1$ (which is the minimum of a length-one prefix), then updated whenever a smaller element is encountered.

Loop Invariant

Theorem. After iteration $i$ of the loop (for $i \in \{1, \ldots, n-1\}$), $m = \min(a_1, a_2, \ldots, a_{i+1})$.

Equivalently: $m \in \{a_1, \ldots, a_{i+1}\}$ and $m \leq a_j$ for all $j$ with $1 \leq j \leq i+1$.

(The loop variable runs from 2 to $n$, so after the $i$-th iteration the algorithm has examined elements $a_1$ through $a_{i+1}$.)

Proof

Initialization. Before the loop, $m = a_1$. This is the minimum of the prefix $(a_1)$, which has length one. The invariant holds vacuously for $i = 0$, interpreting "after 0 iterations" as the state after initialization and before the loop body runs.

Maintenance. Assume the invariant holds after iteration $i$: $m = \min(a_1, \ldots, a_{i+1})$. In iteration $i+1$, the algorithm compares $m$ to $a_{i+2}$.

  • If $a_{i+2} < m$: $m$ is updated to $a_{i+2}$. Since $m$ was the minimum of $(a_1, \ldots, a_{i+1})$ and $a_{i+2}$ is strictly less, the new $m = a_{i+2} = \min(a_1, \ldots, a_{i+2})$.
  • If $a_{i+2} \geq m$: $m$ is unchanged. Since $m \leq a_j$ for all $j \leq i+1$ and $m \leq a_{i+2}$, $m = \min(a_1, \ldots, a_{i+2})$.

In both cases the invariant holds after iteration $i+1$.

Termination. The loop runs for iterations $i = 1$ to $n-1$. After iteration $n-1$, the invariant gives $m = \min(a_1, \ldots, a_n)$. The algorithm returns $m$, which is the minimum of the entire sequence — precisely what the Minimum Problem requires.

Corollary (Correctness). For any input $(a_1, \ldots, a_n)$ with $n \geq 1$, $\text{Minimum}(A)$ returns $a_i$ such that $a_i \leq a_j$ for all $j$. $\square$

Sequential Search

The Search Problem

Input: A sequence $A = (a_1, a_2, \ldots, a_n)$ of integers and a target integer $t$.

Output: An index $i$ such that $a_i = t$ if such an index exists; otherwise $-1$.

When there are multiple occurrences of $t$ in $A$, any one index is an acceptable answer.

Pseudocode

Search(A = (a_1, ..., a_n), t):
    m = -1
    for i = 1 to n do
        if a_i = t then
            m = i
    return m

The variable $m$ is initialized to $-1$ (the "not found" sentinel). If any element equals $t$, $m$ is overwritten with that element's index. The algorithm always completes the full loop before returning, which simplifies the invariant statement.

Loop Invariant

Theorem. After iteration $i$ of the loop ($0 \leq i \leq n$), where $i = 0$ denotes the state prior to the loop:

$$P(i): \quad m = -1 \;\wedge\; t \notin \{a_1, \ldots, a_i\} \quad \text{OR} \quad m = j \;\text{ for some } j \text{ with } a_j = t $$

In other words: $m$ is $-1$ if and only if $t$ has not appeared among $a_1, \ldots, a_i$; and $m$ equals a valid index $j$ only if $a_j = t$.

Proof

Initialization ($i = 0$, prior to the loop). The algorithm sets $m = -1$. We must show that $t \notin \{a_1, \ldots, a_0\} = \emptyset$. This is vacuously true: no element exists in the empty prefix. The invariant holds.

Maintenance. Assume $P(i)$ holds before iteration $i+1$. By hypothesis, either (Case A) $m = -1$ and $t \notin \{a_1, \ldots, a_i\}$, or (Case B) $m = j$ with $a_j = t$.

  • Case B (already found): $m$ is set to some $j$ with $a_j = t$. In iteration $i+1$, either the condition $a_{i+1} = t$ is false (so $m$ is unchanged, and $P(i+1)$ holds with the same $j$), or $a_{i+1} = t$ (so $m$ is updated to $i+1$, and $P(i+1)$ holds with $j = i+1$). Either way, after the iteration $m$ is a valid index for $t$.

  • Case A (not yet found): $m = -1$ and $t \notin \{a_1, \ldots, a_i\}$.

    • Sub-case $a_{i+1} = t$: the algorithm sets $m = i+1$. Now $P(i+1)$ holds in the second disjunct with $j = i+1$.
    • Sub-case $a_{i+1} \neq t$: $m$ remains $-1$. Combining the Case A hypothesis with this sub-case, $t \notin \{a_1, \ldots, a_i\}$ and $t \neq a_{i+1}$, so $t \notin \{a_1, \ldots, a_{i+1}\}$. The first disjunct of $P(i+1)$ holds.

In all cases $P(i+1)$ holds after iteration $i+1$.

Termination. After iteration $n$, $P(n)$ holds. The algorithm returns $m$.

Corollary (Correctness). Let $(A, t)$ be any valid input.

  • Case 1: $t \notin A$. Then $t \notin \{a_1, \ldots, a_n\}$, so by $P(n)$ we cannot be in the second disjunct; we must have $m = -1$. The algorithm correctly returns $-1$.
  • Case 2: $a_i = t$ for some $i$. Suppose for contradiction that $m = -1$ after the loop. Then by $P(n)$, $t \notin \{a_1, \ldots, a_n\}$, contradicting our assumption. Therefore $m = j$ for some $j$ with $a_j = t$, which is the required output. $\square$

String Equality

The String Equals Problem

Input: Strings $a$ and $b$ of lengths $n$ and $m$ respectively, over a common alphabet.

Output: true if $a = b$; false otherwise.

This is a decision problem: the output is a single Boolean value.

Pseudocode

StringEquals(a of length n, b of length m):
    r = true
    if n ≠ m then
        r = false
    for i = 1 to n do
        if a_i ≠ b_i then
            r = false
    return r

The flag $r$ starts as true — an optimistic assumption of equality. Any evidence of inequality (mismatched lengths or a mismatched character) flips $r$ to false. Once set to false, $r$ can never be restored to true.

Loop Invariant

Theorem. After iteration $i$ of the loop ($0 \leq i \leq n$):

$$P(i): \quad r = \mathbf{true} \;\wedge\; a_j = b_j \;\forall j \leq i \quad \text{OR} \quad r = \mathbf{false} \;\wedge\; a \neq b $$

The two cases are mutually exclusive. In the first, $r$ is true and every character comparison so far confirms equality. In the second, $r$ is false because either $n \neq m$ or some character mismatch was detected.

Proof

Initialization ($i = 0$, prior to the loop). Two sub-cases depending on the length check:

  • If $n \neq m$: $r$ is set to false. Since strings of different lengths cannot be equal, $a \neq b$. The second disjunct holds.
  • If $n = m$: $r$ remains true. The universal $\forall j \leq 0$ is vacuously true (no characters have been compared). The first disjunct holds.

Maintenance. Assume $P(i)$ holds before iteration $i+1$.

  • $r = \mathbf{false}$ case: No code in the loop resets $r$ to true. Whatever happens in iteration $i+1$, $r$ remains false and $a \neq b$ remains established. $P(i+1)$ holds.

  • $r = \mathbf{true}$ case: We know $a_j = b_j$ for all $j \leq i$ (and $n = m$, since $r$ was never set to false by the length check). In iteration $i+1$:

    • If $a_{i+1} = b_{i+1}$: $r$ is unchanged. We now have $a_j = b_j$ for all $j \leq i+1$. First disjunct of $P(i+1)$ holds.
    • If $a_{i+1} \neq b_{i+1}$: $r$ is set to false. Because characters at position $i+1$ differ, $a \neq b$. Second disjunct of $P(i+1)$ holds.

Termination. After iteration $n$, $P(n)$ holds.

Corollary (Correctness). Let $a$ and $b$ be arbitrary strings.

  • Case 1: $a = b$. Then $n = m$ and $a_j = b_j$ for all $j$. The invariant's second disjunct would require $a \neq b$, a contradiction. So after the loop $r = \mathbf{true}$, which is the correct output.
  • Case 2: $a \neq b$. The invariant's first disjunct would require $a_j = b_j$ for all $j \leq n$ and $n = m$ — which would imply $a = b$, a contradiction. So $r = \mathbf{false}$, the correct output. $\square$

Detecting Negative Numbers

The Problem and Algorithm

Input: A sequence $A = (a_1, a_2, \ldots, a_n)$ of integers.

Output: true if any $a_i < 0$; false if all $a_i \geq 0$.

HasNegative(A = (a_1, ..., a_n)):
    flag = false
    for i = 1 to n do
        if a_i < 0 then
            flag = true
    return flag

Like StringEquals, this algorithm uses a Boolean flag initialized to the "no evidence" value (false). A single negative element flips it to true; once true, it stays true.

Loop Invariant

Theorem. After iteration $i$ of the loop ($0 \leq i \leq n$):

$$P(i): \quad \mathit{flag} = \mathbf{true} \iff \exists\, j \leq i \text{ such that } a_j < 0 $$

Equivalently: $\mathit{flag}$ is true if and only if a negative element has been encountered among $a_1, \ldots, a_i$.

Proof Sketch

Initialization ($i = 0$). $\mathit{flag} = \mathbf{false}$ and the set $\{a_1, \ldots, a_0\} = \emptyset$ contains no negatives. Both sides of the biconditional are false, so $P(0)$ holds.

Maintenance. Assume $P(i)$. In iteration $i+1$:

  • If $a_{i+1} < 0$: $\mathit{flag}$ becomes true (or remains true if already set). A negative exists among $a_1, \ldots, a_{i+1}$ (namely $a_{i+1}$), so the right-hand side is true. $P(i+1)$ holds.
  • If $a_{i+1} \geq 0$: $\mathit{flag}$ is unchanged. By $P(i)$, $\mathit{flag} = \mathbf{true}$ iff a negative existed among $a_1, \ldots, a_i$. Since $a_{i+1} \geq 0$, the truth value of the right-hand side does not change when the domain extends to include $a_{i+1}$. $P(i+1)$ holds.

Termination. After iteration $n$, $P(n)$ states: $\mathit{flag} = \mathbf{true}$ iff $\exists\, j \leq n$ with $a_j < 0$. The algorithm returns $\mathit{flag}$, which is therefore true exactly when $A$ contains a negative element, and false otherwise. This is the required output. $\square$

Note on Invariant Formulation

The biconditional $P \iff Q$ can equivalently be written as an exclusive disjunction: $(\mathit{flag} = \mathbf{true} \wedge \exists\, j\, [a_j < 0]) \;\oplus\; (\mathit{flag} = \mathbf{false} \wedge \forall\, j\, [a_j \geq 0])$. All formulations carry the same logical content; the choice between them is a matter of style and proof convenience.

Connections

The proof technique introduced this week — loop invariants established by induction — is a direct application of the proof structure from Week 2 Notes. Every loop invariant proof is an induction proof: Initialization is the base case; Maintenance is the inductive step. Recognizing this connection lets you import all the intuition from direct and inductive proof into the algorithm setting.

Looking forward, Week 4 Notes asks the second fundamental question about algorithms: not whether they are correct, but how many steps they take. The loops proven correct here are the same loops whose iterations will be counted in Week 4. Understanding the loop's invariant often clarifies which operations are executed on each pass, making the efficiency analysis more transparent.

Finally, Week 7 Notes applies loop invariant proof to sorting algorithms — programs whose correctness is considerably less obvious than the algorithms studied here. The template is identical; the invariants are more intricate. Mastery of the minimum, search, and string equality proofs now is the most direct preparation for that material.
