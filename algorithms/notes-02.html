Divide and Conquer

Divide and conquer is a recursive algorithm design strategy: split the input into smaller sub-instances of the same problem, solve each recursively, and combine the results. When only one recursive call is made per step (the problem decreases rather than divides), we call it decrease and conquer. Sequential search and binary search are decrease-and-conquer algorithms.

The five-step divide-and-conquer design process:

  1. State the problem formally — input conditions and output expectations
  2. Identify sub-instances — determine how to break the input into smaller pieces
  3. Write a self-reduction — express the solution to the full problem in terms of solutions to sub-instances
  4. Implement the algorithm — translate the self-reduction into pseudocode, adding base cases
  5. Analyze the runtime — write a recurrence relation from the pseudocode

Self-Reductions

A sub-instance is a smaller instance of the same problem (e.g., a shorter subarray). A self-reduction is a formula expressing the solution to the full problem in terms of solutions to sub-instances. Writing a correct self-reduction is the creative step.

The three search problems used throughout this week:

Sequential Search — $U(a, b)$: return $A[a] = x$ if $a = b$; else return $A[a] = x$ OR $U(a+1, b)$.

Recursive Search (both halves) — $R(a, b)$: if $a = b$, return $A[a] = x$; else let $m = \lfloor(a+b)/2\rfloor$, return $R(a,m)$ OR $R(m+1,b)$.

Binary Search — $S(a, b)$: if $a = b$, return $A[a] = x$; else let $m = \lfloor(a+b)/2\rfloor$, return $S(a,m)$ if $x \leq A[m]$, else $S(m+1,b)$.

A problem has optimal substructure if a correct self-reduction exists. This is a necessary condition for divide and conquer (and for dynamic programming, as we will see in Week 6).

Recurrence Relations

A recurrence relation $T(n)$ is a recursively defined function expressing the number of operations performed by a recursive algorithm on an input of size $n$. Standard form:

  • Base case: $T(n) = c$ for $n \leq 1$ (constant work on small inputs)
  • Recursive case: $T(n) = [\text{recursive terms}] + d$ for $n > 1$ ($d$ is the non-recursive work)

The recurrences for the three search algorithms:

Algorithm Recurrence Solution
Sequential Search $T(n) = c$ if $n \leq 1$; $T(n-1) + d$ if $n > 1$ $\Theta(n)$
Recursive Search $T(n) = c$ if $n \leq 1$; $2T(\lfloor n/2 \rfloor) + d$ if $n > 1$ $\Theta(n)$
Binary Search $T(n) = c$ if $n \leq 1$; $T(\lfloor n/2 \rfloor) + d$ if $n > 1$ $\Theta(\log n)$

Reading a recurrence from code: count the number of recursive calls ($a$), the size of each call, and the non-recursive work. This gives the template $T(n) = a \cdot T(\text{size}) + \text{extra work}$.

Design choices matter. Subtracting 1 instead of dividing by 2 changes the depth of the recursion tree from $\log n$ to $n$. With two recursive calls, this produces exponential runtime $\Theta(2^n)$ instead of $\Theta(n)$.

The Recursion Tree Technique

The recursion tree technique guesses a tight bound. Small approximations are acceptable because the guess will be proven separately by induction.

For each level of the recursion tree, track:

Column Meaning
Level Depth in the tree, starting at 0
Size Input size at this level
# Nodes Number of active recursive calls
Cost/Node Non-recursive work at one node (evaluate $f(n)$ at the node's size)
Total Cost (# Nodes) $\times$ (Cost/Node)

Procedure: Fill the first 2–3 rows concretely. Identify the pattern at a generic level $i$. Determine the tree depth $k$ by solving for when the size reaches the base case. Sum the Total Cost column from level 0 to $k-1$, then add the base-case cost.

Worked examples

Sequential Search — $T(n) = T(n-1) + d$:

This is a stick (one node per level). Size at level $i$: $n-i$. Depth: $k = n-1$. Total:

$$\sum_{i=0}^{k-1} d + c = d(n-1) + c \in \Theta(n) $$

Binary Search — $T(n) = T(\lfloor n/2 \rfloor) + d$:

Also a stick. Size at level $i$: $n/2^i$. Depth: $k = \log_2 n$. Total:

$$\sum_{i=0}^{k-1} d + c = d \log_2 n + c \in \Theta(\log n) $$

Recursive Search — $T(n) = 2T(\lfloor n/2 \rfloor) + d$:

Complete binary tree: $2^i$ nodes at level $i$. Size at level $i$: $n/2^i$. Total cost per level: $d \cdot 2^i$. Depth: $k = \log_2 n$. Total:

$$\sum_{i=0}^{k-1} d \cdot 2^i + cn = d(2^k - 1) + cn = d(n-1) + cn \in \Theta(n) $$

This uses the geometric series $\sum_{i=0}^{k-1} 2^i = 2^k - 1$.

When the total cost column is geometric with ratio $r < 1$, the entire sum is bounded by a constant (Zeno's paradox: $\sum_{i=0}^{\infty} r^i = \frac{1}{1-r}$ for $|r| < 1$). This appears in exercises like $T(n) = T(n/3) + 5n$, where the total cost per level is $5n \cdot (1/3)^i$ — bounded by $5n \cdot \frac{3}{2} \in \Theta(n)$.

When leaves dominate. In $T(n) = 4T(n/3) + 6n^2$: the total cost per level is $6n^2 \cdot (4/9)^i$, a geometric series with ratio $< 1$, so the root dominates and we might guess $\Theta(n^2)$. But the leaf count is $4^{\log_3 n} = n^{\log_3 4}$ (using the log identity from Week 1), which exceeds $n^2$ since $\log_3 4 \approx 1.26 > 2$... wait, actually $\log_3 4 \approx 1.26 < 2$, so $n^2$ dominates and the answer is $\Theta(n^2)$. The Master Theorem (Week 4) handles this class of recurrences systematically.

Proving Bounds by Induction

Induction converts a recursion tree guess into a rigorous proof. Proofs are split into two separate lemmas: one for the upper bound ($T(n) \leq b \cdot f(n)$) and one for the lower bound ($T(n) \geq a \cdot f(n)$). Combining them gives the $\Theta$ result.

Standard proof structure:

  1. Base case: verify the inequality at the starting value of $n$; identify conditions on the constant $b$ (or $a$)
  2. Inductive hypothesis (strong induction): assume $T(k) \leq b \cdot f(k)$ for all $k < n$
  3. Inductive step: expand $T(n)$, apply the hypothesis via double substitution, complete the algebra
  4. Leap of faith: identify the condition on $b$ that makes the final inequality hold
  5. Choose constants: set $b = \max(\text{conditions from base and inductive steps})$ for upper bounds; $a = \min(\ldots)$ for lower bounds

Strong vs. weak induction. For recurrences involving $\lfloor n/2 \rfloor$, strong induction is necessary — the recursive call does not always go to $n-1$. Strong induction assumes the property holds for all $k < n$, not just $k = n-1$.

Sequential Search — $T(n) = T(n-1) + d \in \Theta(n)$

Upper bound $T(n) \leq bn$: base case gives $b \geq C$; inductive step gives $T(n) \leq b(n-1) + d = bn - b + d \leq bn$ requires $b \geq d$. Choose $b = \max(C, d)$.

Lower bound $T(n) \geq an$: base case gives $a \leq C$; inductive step gives $T(n) \geq a(n-1) + d = an - a + d \geq an$ requires $d \geq a$. Choose $a = \min(C, d)$.

Binary Search — $T(n) = T(\lfloor n/2 \rfloor) + d \in \Theta(\log n)$

Base case issue. $n = 1$ fails: $b \cdot \log 1 = 0 < C$. Must use both $n = 2$ and $n = 3$ as base cases (the dependency graph shows $n = 3$ depends on $n = 1$, not $n = 2$).

Transitivity trick: since both $T(n)$ and $\log n$ are increasing, $T(2) \leq b \log 2 = b$ and $T(3) \leq b \log 3$ both follow from the single condition $b \geq T(3)$.

Upper bound inductive step ($n > 3$): $T(n) = T(\lfloor n/2 \rfloor) + d \leq b \log\lfloor n/2 \rfloor + d \leq b \log(n/2) + d = b \log n - b + d \leq b \log n$ requires $b \geq d$. Choose $b = \max(T(3), d)$.

Lower bound ($n \geq 1$): uses the approximation $\lfloor n/2 \rfloor \geq n/4$ for $n \geq 2$ to avoid a $-1$ inside the logarithm. Choose $a = d/2$.

Recursive Search — $T(n) = 2T(\lfloor n/2 \rfloor) + d \in \Theta(n)$

First attempt fails. Guessing $T(n) \leq bn$: after double substitution, $T(n) \leq bn + d$. There is no negative term to cancel $d$.

Fix: use a stronger hypothesis.

The Stronger Hypothesis Technique

When the natural inductive hypothesis $T(n) \leq b \cdot f(n)$ fails to close because there is no algebraic slack to absorb the constant $d$, modify the hypothesis to $T(n) \leq b \cdot f(n) - a$ for some additional constant $a > 0$. This is still in $O(f(n))$ but provides the needed room.

Proof for Recursive Search — claim $T(n) \leq bn - a$:

  • Base case ($n = 1$): $C \leq b - a$ — condition: $b \geq C + a$.
  • Inductive step: $T(n) = 2T(\lfloor n/2 \rfloor) + d \leq 2(b \lfloor n/2 \rfloor - a) + d \leq 2(bn/2 - a) + d = bn - 2a + d$.
    • Need $bn - 2a + d \leq bn - a$: requires $a \geq d$. Choose $a = d$.
    • From base case: $b \geq C + a = C + d$. Choose $b = C + d$.

Lower bound $T(n) \geq an$: uses $\lfloor n/2 \rfloor \geq n/2 - 1$; choose $a = \min(C, d/2)$.

The stronger hypothesis pattern appears again whenever a recurrence has two recursive calls of the same size — it is the standard fix when the naive guess fails.

Connections

The three recurrences analyzed this week — $\Theta(n)$, $\Theta(\log n)$, $\Theta(n)$ — are the first instances of the divide-and-conquer family. The Master Theorem in Week 4 provides a shortcut for this entire class of recurrences.

The geometric series formula from Week 1 (a sum with ratio $r < 1$ converges to a constant) is used directly here when the Total Cost column forms a convergent series.

The log identity $a^{\log_b n} = n^{\log_b a}$ from Week 1 is essential for evaluating the leaf-count term $a^{\log_b n}$ in multi-call recurrences.

The stronger hypothesis technique introduced here reappears in Week 3 when proving the mergesort bound, where an additive constant is needed to handle the base case where $\log 1 = 0$.

The induction technique and the two-step analysis (recursion tree guess → induction proof) carry forward to every recurrence in the course. Week 4 precomputes these results into the Master Theorem so you do not need to re-derive them each time.
