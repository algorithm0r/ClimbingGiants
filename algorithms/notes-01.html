What Is an Algorithm?

A problem is a specification with two parts: an input condition (the set of valid inputs) and an output expectation (what a correct answer must satisfy). A problem instance is a specific input satisfying the input condition.

An algorithm is a step-by-step procedure that produces a correct output for every valid instance. This distinguishes an algorithm from:

  • An approximation algorithm — produces an output within a known factor of the optimum. Used when exact solutions are intractable.
  • A heuristic — produces good outputs in practice but with no formal correctness guarantee.
  • A randomized algorithm — uses randomness; may produce different outputs on the same input in different runs.

The resources we measure when analyzing algorithms are time (operation count), space (memory), communication (in distributed systems), and randomness. In this course, time is the primary resource.

The word "algorithm" derives from the name of the 9th-century mathematician al-Khwarizmi, whose treatise on positional arithmetic introduced procedures that made computation practical — a useful reminder that the study of algorithms is old and motivated by real difficulty.

Runtime and Input Size

The runtime of an algorithm is expressed as a function $T(n)$ where $n$ is the size of the input. What counts as input size depends on the data:

Input type Input size $n$
Integer $N$ $\lfloor \log_2 N \rfloor + 1$ (number of bits)
String Number of characters
List or set Number of entries
Tree or graph Number of nodes

The choice of measure matters. If $n$ is the number of bits in an integer, then an $O(n)$ algorithm runs in time linear in the bit length — which is very different from linear in the numeric value.

Common runtime classes, ordered from slowest to fastest growing:

$$(\log_a n)^d \ll n^d \ll b^n \ll n! \ll n^n $$

Asymptotic Notation

Asymptotic notation describes how functions grow for large inputs, ignoring constant factors and lower-order terms. All five notations describe sets of functions — when we write $f(n) \in O(g(n))$, we mean $f$ belongs to the set of functions that grow no faster than $g$.

Big-O (upper bound)

$f(n) \in O(g(n))$ if there exist constants $b > 0$ and $n_f$ such that

$$f(n) \leq b \cdot g(n) \quad \text{for all } n > n_f $$

Interpretation: $f$ grows no faster than $g$.

Big-Omega (lower bound)

$f(n) \in \Omega(g(n))$ if there exist constants $a > 0$ and $n_f$ such that

$$a \cdot g(n) \leq f(n) \quad \text{for all } n > n_f $$

Interpretation: $f$ grows no slower than $g$.

Big-Theta (tight bound)

$f(n) \in \Theta(g(n))$ if $f \in O(g(n))$ and $f \in \Omega(g(n))$ simultaneously — that is, $f$ and $g$ grow at the same rate up to constant factors.

Little-o and little-omega (strict bounds)

$f(n) \in o(g(n))$ if for every constant $b > 0$, there exists $n_f$ such that $f(n) < b \cdot g(n)$ for all $n > n_f$. Interpretation: $f$ grows strictly slower than $g$.

$f(n) \in \omega(g(n))$ is the reverse: $f$ grows strictly faster than $g$.

Important conventions

Big-Theta is a set, not a number. You cannot write $\Theta(n^2) + 3$ inside a summation. When you need a concrete representative, pick a specific constant — write $cn^2$ for some $c > 0$.

Log base convention. In computer science, an unadorned $\log$ defaults to base 2. The notation $\lg$ explicitly means $\log_2$.

Log identity (swap rule). For any bases $a$ and $b$:

$$a^{\log_b n} = n^{\log_b a} $$

This identity appears repeatedly when simplifying recursion trees. For example, $8^{\log_2 n} = n^{\log_2 8} = n^3$.

Proving Bounds Directly

To prove $f(n) \in O(g(n))$ from the definition, you must exhibit specific constants $b$ and $n_f$. The following approximation moves are valid:

  • Drop negative terms. Removing a subtracted term makes the expression larger, which only strengthens an upper bound. Example: $4n^2 + 6n + 3 \leq 4n^2 + 6n^2 + 3n^2 = 13n^2$.
  • Promote positive terms. Replace a factor with a larger one over the valid range. If $i \leq n$, replace $i$ with $n$ in a sum.
  • Guess and check. Propose specific values of $b$ and $n_f$, then verify the inequality holds for all $n > n_f$.

Notation discipline: Use $\leq$ and $\geq$ for approximation steps. Use $=$ only for algebraic equalities. Mixing them obscures where the approximation occurs.

Worked examples

Claim: $4n^2 + 6n + 3 \in \Theta(n^2)$.

Upper bound: For $n \geq 1$, we have $6n \leq 6n^2$ and $3 \leq 3n^2$, so $4n^2 + 6n + 3 \leq 13n^2$. Take $b = 13$, $n_f = 1$.

Lower bound: $4n^2 + 6n + 3 \geq 4n^2$ for all $n \geq 0$. Take $a = 4$, $n_f = 0$.

Claim: $\log(3n^2 + n - 5) \in \Theta(\log n)$.

For large $n$, $3n^2 + n - 5 \leq 3n^2 + n^2 = 4n^2$, so $\log(3n^2 + n - 5) \leq \log(4n^2) = \log 4 + 2\log n \leq 4 \log n$ for $n \geq 2$. The lower bound follows similarly. So $b = 4$, $a = 1$, $n_f = 5$.

Counter-example: $n^{\sin n} \in O(n)$ but not $\Theta(n)$, because $\sin n$ oscillates between $-1$ and $1$, so the function oscillates between $1/n$ and $n$ — it has no stable growth rate.

The Limit Test

Computing constants directly can be tedious. The limit test offers an alternative.

Theorem (Limit Test). Let $L = \displaystyle\lim_{n \to \infty} \frac{f(n)}{g(n)}$.

Value of $L$ Conclusion
$L = \infty$ $f \in \omega(g)$ — $f$ grows strictly faster
$L = 0$ $f \in o(g)$ — $f$ grows strictly slower
$L = c$ for some $c \in (0, \infty)$ $f \in \Theta(g)$ — same growth rate

When the limit produces an indeterminate form ($\infty/\infty$ or $0/0$), apply L'Hôpital's rule: differentiate numerator and denominator separately, then retry.

Examples:

$\displaystyle\lim_{n \to \infty} \frac{6n + 6}{n} = 6$ — a nonzero constant, so $6n + 6 \in \Theta(n)$.

$\displaystyle\lim_{n \to \infty} \frac{\log n}{n}$. Applying L'Hôpital: $\frac{1/n}{1} \to 0$. So $\log n \in o(n)$.

Loop Analysis and Summations

The runtime of a loop is the sum of work done across all iterations. Setting up that sum correctly is the first skill.

Sum of constants: $\displaystyle\sum_{i=a}^{b} 1 = b - a + 1$

Gauss's sum: $\displaystyle\sum_{i=1}^{n} i = \frac{n(n+1)}{2}$

The story behind Gauss's sum: pair the first and last terms ($1 + n$), the second and second-to-last ($2 + (n-1)$), and so on. Each pair sums to $n+1$, and there are $n/2$ pairs.

Reversing the sum. When a loop counts down or has an inconvenient index direction, reverse it:

$$\sum_{i=1}^{n}(n - i + 1) = \sum_{i=1}^{n} i $$

Worked analysis: Grade School Binary Multiplication

Multiplying two $n$-bit integers by the grade school method: for each of the $n$ bits in the multiplier, shift and add a partial product of length up to $n$ bits. The total work is:

$$\sum_{i=0}^{n-1} \Theta(i) = \Theta\!\left(\sum_{i=0}^{n-1} i\right) = \Theta\!\left(\frac{n(n-1)}{2}\right) = \Theta(n^2) $$

This is the baseline we are trying to beat in Week 4 with Karatsuba's algorithm.

Bounding Hard Sums

Some sums do not have a simple closed form but can be bounded tightly using three techniques.

Bind the term (upper bound)

Replace each term with its maximum value over the summation range. For $\displaystyle\sum_{i=1}^{n} \log i$: every term satisfies $\log i \leq \log n$, so

$$\sum_{i=1}^{n} \log i \leq \sum_{i=1}^{n} \log n = n \log n $$

This gives $\displaystyle\sum_{i=1}^{n} \log i \in O(n \log n)$.

Split the sum (lower bound)

Drop the first half of the sum entirely (it is non-negative, so removing it only decreases the total). Bound each term in the remaining half from below by its minimum on that range. For $\displaystyle\sum_{i=1}^{n} \log i$:

$$\sum_{i=1}^{n} \log i \geq \sum_{i=\lceil n/2 \rceil}^{n} \log i \geq \frac{n}{2} \cdot \log\frac{n}{2} = \frac{n}{2}(\log n - 1) \in \Omega(n \log n) $$

Squeeze

If $\ell(n) \leq S(n) \leq u(n)$ and both $\ell$ and $u$ are in $\Theta(g(n))$, then $S(n) \in \Theta(g(n))$.

Result: $\displaystyle\sum_{i=1}^{n} \log i \in \Theta(n \log n)$ — this is the running time of Heap Sort.

Other important bounds

Sum Result
$\displaystyle\sum_{i=1}^{n} \sqrt{i}$ $\Theta(n^{3/2})$
$\displaystyle\sum_{i=1}^{n} i^2$ $\Theta(n^3)$
$\displaystyle\sum_{i=1}^{n} i \log i$ $\Theta(n^2 \log n)$
$\displaystyle\sum_{i=0}^{k-1} r^i$ (geometric, $r > 1$) $\Theta(r^k)$
$\displaystyle\sum_{i=0}^{\infty} r^i$ (geometric, $r < 1$) $\Theta(1)$ — converges to a constant

The geometric series result for $r < 1$ appears in Week 2 when summing across levels of a recursion tree.

The Integral Approximation

For a non-decreasing function $f$, the sum and the integral are within one term of each other:

$$\int_{k-1}^{n} f(x)\, dx \;\leq\; \sum_{i=k}^{n} f(i) \;\leq\; \int_{k}^{n+1} f(x)\, dx $$

This is derived geometrically: the sum of unit-width rectangles under-approximates or over-approximates the area under the curve depending on alignment.

Applied to $\displaystyle\sum_{i=1}^{n} i^2$:

Upper bound: $\displaystyle\int_{1}^{n+1} x^2\, dx = \frac{(n+1)^3}{3} - \frac{1}{3} \in O(n^3)$

Lower bound: $\displaystyle\int_{0}^{n} x^2\, dx = \frac{n^3}{3} \in \Omega(n^3)$

So $\displaystyle\sum_{i=1}^{n} i^2 \in \Theta(n^3)$. The exact closed form is $\dfrac{n^3}{3} + \dfrac{n^2}{2} + \dfrac{n}{6}$.

The integral method often yields tighter constants than the split/bind technique but requires integrating the function. Both are valid — use whichever is cleaner for the case at hand.

Connections

The runtime classes introduced this week — $\Theta(\log n)$, $\Theta(n)$, $\Theta(n \log n)$, $\Theta(n^2)$, $\Theta(n^3)$ — are the targets of the recurrence proofs in Week 2.

The geometric series result (a sum with ratio $r < 1$ converges to a constant) is used directly in the Week 2 recursion tree technique when levels of recursion shrink geometrically.

The log identity $a^{\log_b n} = n^{\log_b a}$ reappears in recursion tree exercises when identifying the growth class of a leaf-count term.

The summation bounding techniques (bind, split, squeeze, integral) connect to the Master Theorem in Week 4, which can be understood as a precomputed version of these same arguments applied to divide-and-conquer recurrences.
