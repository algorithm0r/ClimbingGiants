NP Membership via Verifiers

In Week 9, we defined NP as the class of decision problems that have a polynomial-time verification procedure. To show that a problem is in NP, we exhibit a correct verifier — an algorithm that takes the problem input $x$ and a certificate $w$ and decides yes/no in polynomial time, satisfying:

  1. Completeness (yes → yes): If the input is a yes-instance, some certificate causes the verifier to say yes.
  2. Soundness (no → no): If the input is a no-instance, no certificate causes the verifier to say yes.

This week, we build a library of NP membership proofs, then show that these problems are among the hardest problems in NP — they are NP-complete.

Verifiers for Classic Problems

Subset Sum

Problem: Given a set $S$ of positive integers and target $T$, does some subset of $S$ sum to $T$?

Certificate: The claimed subset $W \subseteq S$.

Verify(S, T, W):
  If W ⊄ S: say no.
  If Σ_{w ∈ W} w ≠ T: say no.
  Say yes.

Correctness:

  • Yes → yes: Assume a subset exists summing to $T$; let $W$ be that subset. $W \subseteq S$ (test 1 passes) and $\sum W = T$ (test 2 passes). ✓
  • No → no: Assume no subset sums to $T$. Assume $W$ passes test 1 ($W \subseteq S$). Then $\sum W \neq T$ and test 2 fails. ✓

Runtime: Subset check $O(n^2)$; sum $O(n)$ — all polynomial.

Knapsack (Decision Version)

Problem: Given $n$ items with weights $W[i]$ and values $V[i]$, capacity $C$, and threshold $t$: does some subset fit within capacity and achieve total value $\geq t$?

Certificate: Index set $A \subseteq \{1, \ldots, n\}$ of items to pack.

Verify(W, V, C, t, A):
  If A ⊄ {1,...,n}: say no.
  If Σ_{i ∈ A} W[i] > C: say no.      // exceeds capacity
  If Σ_{i ∈ A} V[i] < t: say no.      // below value threshold
  Say yes.

Correctness:

  • Yes → yes: A valid high-value subset exists; use it as $A$; it passes all three tests. ✓
  • No → no: Assume no valid subset achieves both constraints. Assume $A$ passes tests 1 and 2 ($A$ is a valid index set that fits in the knapsack). Then $A$ must fail the value test. ✓

Runtime: Each check is $O(n)$ — polynomial.

Clique

Problem: Given graph $G = (V, E)$ and integer $K$, does $G$ have a complete subgraph (clique) of size $K$?

Certificate: The vertex set $W$ of the claimed clique.

Verify(G, K, W):
  If W ⊄ V: say no.
  If ∃ u, v ∈ W with (u,v) ∉ E: say no.    // not complete
  If |W| < K: say no.                         // too small
  Say yes.

Common mistake: Forgetting the size test. Without it, the no → no branch fails: if $G$ has no clique of size $K$, a smaller complete subgraph might still pass the first two tests.

Correctness:

  • Yes → yes: $G$ has a clique of size $K$; let $W$ be its vertex set. $W \subseteq V$, all pairs connected, $|W| = K$ — all tests pass. ✓
  • No → no: $G$ has no clique of size $K$. Assume $W \subseteq V$ with all pairs connected (tests 1 and 2 pass). Then $|W| < K$ and test 3 fails. ✓

Independent Set

Problem: Given $G = (V, E)$ and $K$, does $G$ have an independent set of size $K$ (a subset of vertices with no edges between any two)?

Certificate: The claimed independent set $W$.

Modify the Clique verifier — change test 2: instead of rejecting when an edge is absent, reject when an edge is present.

Verify(G, K, W):
  If W ⊄ V: say no.
  If ∃ u, v ∈ W with (u,v) ∈ E: say no.    // edge exists (bad)
  If |W| < K: say no.
  Say yes.

The proof flows identically to Clique with "complete subgraph" replaced by "independent set." Clique and Independent Set are nearly complement problems — their verifiers differ in exactly one test.

Hamiltonian Cycle

Problem: Given connected undirected graph $G = (V, E)$, does $G$ have a Hamiltonian cycle — a cycle visiting every vertex exactly once, returning to the start?

Why a subset certificate doesn't work: Every Hamiltonian cycle visits all vertices, so a subset of vertices gives no information. The hard part is the ordering, not which vertices are included.

Certificate: A permutation $W$ of $V$ — an ordering of all vertices proposing the tour.

Verify(G, W):
  If W is not a permutation of V: say no.
  For i = 1 to |V| - 1:
    If (W[i], W[i+1]) ∉ E: say no.         // consecutive vertices must be connected
  If (W[|V|], W[1]) ∉ E: say no.           // last vertex must connect back to first
  Say yes.

Why the last test matters: The first loop checks for a Hamiltonian path (visiting all vertices in a line). The final test converts it to a Hamiltonian cycle (closing the tour). Omitting it would accept valid paths that are not cycles.

Correctness:

  • Yes → yes: $G$ has a Hamiltonian cycle; let $W$ be its vertex ordering. It is a permutation of $V$, all consecutive pairs have edges, and the closing edge exists. ✓
  • No → no: $G$ has no Hamiltonian cycle. Assume $W$ is a permutation of $V$ with all consecutive edges present (tests 1 and 2 pass). Then the closing edge $(W[n], W[1])$ cannot exist — otherwise $W$ would be a Hamiltonian cycle. Test 3 fails. ✓

Runtime: Permutation check $O(n^2)$; edge checks $O(|E|)$ — polynomial.

Polynomial-Time Reductions

Informal: A reduction from problem $A$ to problem $B$ is a mapping from inputs of $A$ to inputs of $B$ that preserves the yes/no answer.

Formal: $A \leq_P B$ ($A$ reduces to $B$ in polynomial time) means there exists a function $M$ (the mapping) such that:

  1. $M$ maps inputs of $A$ to inputs of $B$.
  2. If $x$ is a yes-instance of $A$, $M(x)$ is a yes-instance of $B$.
  3. If $x$ is a no-instance of $A$, $M(x)$ is a no-instance of $B$.
  4. $M$ is computable in polynomial time.

Interpretation: $A \leq_P B$ means "$A$ is no harder than $B$." Any solver for $B$ can be used to solve $A$: apply $M$ to transform the input, then run the $B$ solver, and return its answer.

How to solve $A$ using a solver for $B$:

$$\text{input } x \xrightarrow{M} M(x) \xrightarrow{B\text{-solver}} \text{answer for } M(x) = \text{answer for } x $$

Correctness follows from conditions 2 and 3. Runtime: polynomial (for $M$) + polynomial (for $B$ solver) = polynomial. So if $B \in P$, then $A \in P$.

Direction matters:

  • $A \leq_P B$ is used when you want to use a $B$-solver to solve $A$.
  • To prove $A$ is NP-hard, you take a known NP-hard problem $B$ and show $B \leq_P A$ — that solving $A$ is at least as hard as solving $B$.

NP-Hardness and NP-Completeness

NP-hard: A problem $X$ is NP-hard if every problem in NP reduces to $X$ in polynomial time.

$$\forall A \in \text{NP}: A \leq_P X $$

$X$ is "at least as hard as the hardest problems in NP." $X$ need not itself be in NP — NP-hard problems can be even harder than NP.

NP-complete: A problem is NP-complete if it is:

  1. In NP (has a polynomial-time verifier), and
  2. NP-hard (every NP problem reduces to it).

NP-complete problems are the hardest problems within NP.

Why this matters: If any NP-complete problem could be solved in polynomial time, then every NP problem could be solved in polynomial time (by reducing to it), which would mean P = NP. Conversely, if P ≠ NP, no NP-complete problem is in P.

SAT and the Cook-Levin Theorem

SAT (Satisfiability): Given a Boolean formula in conjunctive normal form (CNF) over variables $x_1, \ldots, x_n$, is there a truth assignment making the entire formula true?

CNF: An AND of clauses, where each clause is an OR of literals (a variable or its negation). Example:

$$(x_1 \lor \neg x_2 \lor x_3) \land (\neg x_1 \lor x_4) \land (x_2 \lor \neg x_3) $$

A formula is satisfiable if some assignment makes all clauses true; a contradiction if no such assignment exists.

Cook-Levin Theorem (1971): SAT is NP-complete.

Proved independently by Stephen Cook (published 1971) and Leonid Levin (proved ~1969, published 1973). Cook and Karp received the Turing Award in 1982 for founding complexity theory.

Why SAT was first: The NP verifier definition says a problem is in NP if there exists a polynomial-time algorithm that can check a proposed solution. The structure of any NP verifier can be encoded as a Boolean formula — specifically, the question "does there exist a certificate that makes the verifier accept?" becomes a SAT instance. This encoding works for any NP problem simultaneously, establishing that every NP problem reduces to SAT at once.

SAT is the entry point into NP-completeness: once SAT is NP-complete, all subsequent proofs only need to show a reduction from SAT (or from another NP-complete problem), not from all NP problems simultaneously.

Karp's Strategy

Transitivity of reductions: If $A \leq_P B$ and $B \leq_P C$, then $A \leq_P C$.

Proof: Compose the two mappings $M_A$ and $M_B$. $M_A$ maps $A$-inputs to $B$-inputs; $M_B$ maps $B$-inputs to $C$-inputs. The composition maps $A$-inputs to $C$-inputs and preserves yes/no through both steps. Both mappings are polynomial, so the composition is polynomial (polynomial of polynomial is polynomial). ✓

Karp's contribution (1972): Using Cook-Levin plus transitivity, Richard Karp proved 21 additional problems are NP-complete, each with a single reduction from a known NP-complete problem.

The strategy to prove $A$ is NP-complete:

  1. Show $A \in$ NP: Give a correct polynomial-time verifier.
  2. Choose a known NP-complete problem $B$: Pick one whose structure relates to $A$.
  3. Show $B \leq_P A$: Define a polynomial-time mapping $M$ from $B$-inputs to $A$-inputs that preserves yes/no.

By transitivity, every problem in NP reduces to $B$ (since $B$ is NP-complete), and $B$ reduces to $A$, so every problem in NP reduces to $A$. Therefore $A$ is NP-hard. Combined with step 1, $A$ is NP-complete.

Gary and Johnson (1979) catalogued over 300 NP-complete problems with proofs — a foundational reference.

Clique and Independent Set

Complement graph $G'$: Given $G = (V, E)$, the complement $G' = (V, E')$ where $E'$ contains exactly the edges not in $E$.

Key observation: A clique in $G$ becomes an independent set in $G'$ (all clique edges are absent from $G'$), and vice versa.

Clique $\leq_P$ Independent Set

Mapping $M$: Given $(G, K)$, return $(G', K)$ where $G'$ is the complement of $G$.

Runtime: Computing $G'$ requires one pass over the edge set — $O(|E|)$ — polynomial. ✓

Correctness:

  • Yes → yes: Assume $G$ has a clique of size $K$. Every edge in the clique is absent from $G'$. Those $K$ vertices have no edges between them in $G'$. $G'$ has an independent set of size $K$. ✓
  • Yes → yes backwards: Assume $G'$ has an independent set of size $K$. Every missing edge in that set exists in $G$. Those $K$ vertices form a complete subgraph in $G$. $G$ has a clique of size $K$. ✓

The reverse reduction (Independent Set $\leq_P$ Clique) follows by the same argument applied to the complement of $G'$, which is $G$ again.

Conclusion: Clique and Independent Set are equivalent in complexity. Both are NP-complete (given that Clique was proven NP-complete via a reduction from SAT).

Partition and Subset Sum

Partition $\leq_P$ Subset Sum (easy direction)

Mapping: Given input $S$ for Partition, return $(S, T)$ where $T = \frac{1}{2}\sum_{s \in S} s$. The set $S$ is unchanged; just compute $T$.

Correctness:

  • Yes → yes: If $S$ can be equally partitioned, each part sums to $T$. So $S$ has a subset summing to $T$. ✓
  • Yes → yes backwards: If $S$ has a subset $W$ summing to $T$, then the remaining elements sum to $\sum S - T = T$. So $S$ can be equally partitioned. ✓

This direction is easy: Partition is a special case of Subset Sum.

Subset Sum $\leq_P$ Partition (harder direction)

Challenge: Given $(S, T)$ for Subset Sum, create a Partition instance that is yes iff $S$ has a subset summing to $T$. The target $T$ is variable; Partition's target is fixed at half the total sum. The reduction must encode $T$ into the set.

Let $\Sigma = \sum_{s \in S} s$. Three cases:

Case 1: $T = \Sigma/2$. Set $S' = S$. The Partition instance directly asks if $S$ has a subset summing to $\Sigma/2 = T$. ✓

Case 2: $T > \Sigma/2$. Add a new element $L = 2T - \Sigma$ to $S$ to get $S'$. Total of $S'$ is $\Sigma + L = 2T$.

  • Yes → yes: Assume subset $W \subseteq S$ sums to $T$. Then $S' \setminus W$ has sum $2T - T = T$. $S'$ can be partitioned into two equal-sum ($T$) parts. ✓
  • Yes → yes backwards: Assume $S'$ can be partitioned into two parts each summing to $T$. Since $L = 2T - \Sigma > \Sigma - \Sigma = 0$ and $L$ can only be in one part, the other part (not containing $L$) must be entirely from $S$ and sum to $T$. ✓

Case 3: $T < \Sigma/2$. Add $L = \Sigma - 2T$ to $S$ to get $S'$. Total of $S'$ is $2(\Sigma - T)$. Similar algebra gives the same yes/no equivalence.

The added element $L$ in cases 2 and 3 is a gadget — a constructed piece of input with a specific structural property that makes the reduction work.

Conclusion: Subset Sum and Partition reduce to each other in both directions. They are equivalent in complexity — in some sense, the same problem viewed differently.

Vertex Cover

Problem: Given undirected graph $G = (V, E)$ and integer $K$, does $G$ have a vertex cover of size $K$ — a subset $V' \subseteq V$ with $|V'| \leq K$ such that every edge has at least one endpoint in $V'$?

Vertex Cover $\in$ NP

Certificate: The claimed vertex cover $W$.

Verify(G, K, W):
  If W ⊄ V: say no.
  If |W| > K: say no.
  If ∃ edge (u,v) ∈ E with u ∉ W and v ∉ W: say no.   // uncovered edge
  Say yes.

Correctness: Standard two-branch argument. ✓ Runtime: Subset check $O(n^2)$; size check $O(1)$; edge coverage $O(|E|)$ — polynomial. ✓

Key Lemma: Independent Set ↔ Vertex Cover

Lemma: $V'$ is a vertex cover of $G$ if and only if $V \setminus V'$ is an independent set.

Proof:

  • Assume $V'$ is a vertex cover. Consider any two vertices $u, v \in V \setminus V'$. If $(u, v) \in E$, then neither $u$ nor $v$ is in $V'$, so the edge is uncovered — contradicting $V'$ being a vertex cover. Therefore no two vertices in $V \setminus V'$ share an edge; $V \setminus V'$ is an independent set. ✓
  • Assume $I = V \setminus V'$ is an independent set. Consider any edge $(u, v) \in E$. Since $I$ has no edges, at least one of $u, v$ is not in $I$, i.e., it is in $V'$. So $V'$ covers the edge. ✓

Independent Set $\leq_P$ Vertex Cover

Mapping $M$: Given $(G, K)$ for Independent Set, return $(G, |V| - K)$ for Vertex Cover. The graph is unchanged; only the threshold changes.

Runtime: Computing $|V| - K$ is $O(1)$ — polynomial. ✓

Correctness:

  • Yes → yes: Assume $G$ has an independent set $I$ of size $K$. By the lemma, $V \setminus I$ is a vertex cover of size $|V| - K$. ✓
  • Yes → yes backwards: Assume $G$ has a vertex cover $V'$ of size $|V| - K$. By the lemma, $V \setminus V'$ is an independent set of size $K$. ✓

Conclusion: Vertex Cover is in NP (verifier shown) and NP-hard (Independent Set $\leq_P$ Vertex Cover, and Independent Set is NP-complete). Therefore Vertex Cover is NP-complete.

What NP-Completeness Means in Practice

The practical interpretation: If a problem is NP-complete, no polynomial-time algorithm for it is known, and finding one would prove P = NP (resolving the biggest open problem in computer science, and likely breaking much of modern cryptography). Most researchers believe P ≠ NP, so NP-complete problems are considered inherently intractable.

What to do when you encounter an NP-complete problem:

  1. Exact algorithms with pseudo-polynomial runtime: DP solutions for Subset Sum and Knapsack work well when the numeric values are small (e.g., $T$ or $C$ is not too large).
  2. Approximation algorithms: For many NP-complete optimization problems, polynomial-time algorithms exist that guarantee solutions within a constant factor of optimal. For Vertex Cover, a simple 2-approximation exists.
  3. Fixed-parameter tractable algorithms: Some NP-complete problems become polynomial when certain parameters are fixed (e.g., Vertex Cover is solvable in $O(2^K \cdot |V|)$ — polynomial when $K$ is small).
  4. Heuristics: Algorithms with no formal guarantee but good empirical performance.
  5. Recognizing the problem: Knowing a problem is NP-complete saves wasted effort searching for a polynomial-time exact algorithm.

NP-complete problems in games and puzzles: Generalized Minesweeper, generalized Battleship, and many other combinatorial puzzles are NP-complete when the grid size $n$ can grow. The specific fixed-size instances you play are trivially solvable — NP-completeness is about what happens as $n \to \infty$.

Connections

The verifier framework from Week 9 is the foundation of everything in this week. Every NP membership proof uses the same two-branch structure established there with COMPOSITES.

The Partition → Subset Sum reduction was introduced informally in Week 7 as motivation for the Partition problem. This week gives it formal treatment as a polynomial-time reduction and proves the harder direction (Subset Sum → Partition) using a gadget construction.

The DP solutions to Subset Sum and Knapsack from Week 7 are pseudo-polynomial — polynomial in the numeric value of $T$ or $C$, but exponential in the bit-length. NP-completeness explains why no polynomial-time exact algorithm exists (assuming P ≠ NP): these are the hardest problems in NP.

The course arc from Weeks 1–10 traces a spectrum of algorithm design strategies:

Strategy Weeks Representative problems
Divide and conquer 2–4 Mergesort, Binary search, Karatsuba
Dynamic programming 6–7 Fibonacci, LCS, Knapsack
Greedy 8–9 Interval scheduling, MST, Dijkstra
NP-complete (no efficient algorithm known) 9–10 Subset Sum, Knapsack, Vertex Cover

Complexity theory does not just classify problems — it tells you when to stop looking for an efficient exact algorithm and when to pivot to approximations, heuristics, or pseudo-polynomial methods.
